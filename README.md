# 보호소 커넥트

유기견 입양 서비스를 이런 방식으로 만들어보면 어떨까 해서 만든 시안이야. 처음부터 사진을 보여주기보다는 도트 강아지랑 먼저 대화하면서, 평소에 어떻게 지내고 어떤 걸 좋아하는지 알아가는 게 핵심고 그러고 나서 실제 사진과 프로필을 보는 흐름으로 잡았어.


## 일단 이렇게 열어보면 돼

저장소를 내려받고 `index.html`을 브라우저에서 열어봐. 화면만 확인할 때는 따로 설치하거나 빌드할 필요 없어. 글꼴이랑 아이콘, 참고 사진은 외부에서 가져오니까 인터넷은 연결돼 있어야 해.

로컬 서버로 열고 싶으면 Python 3가 설치된 상태에서, 이 저장소 폴더를 기준으로 아래 명령어를 실행하면 돼.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

그다음 브라우저에서 `http://localhost:8000`으로 들어가면 돼.

처음에는 봄이랑 대화하는 화면이 나와. 왼쪽 위 뒤로 가기를 누르면 운동장에 들어갈 수 있고, 오른쪽 위 집 버튼을 누르면 봄이가 있는 보호소를 볼 수 있어.

## 화면은 이런 흐름으로 생각했어

가까운 보호소를 고르고 → 운동장에서 도트 강아지를 만나고 → 대화하면서 알아가고 → 사진과 소개서를 보고 → 직접 만날 준비를 하는 순서야.

지금은 아래 동작들을 눌러볼 수 있게 해뒀어.

- 조이스틱으로 걷거나 달리기. 10초 동안 가만히 있으면 캐릭터가 앉아.
- 강아지 가까이에서 대화하기. 공놀이를 좋아하는 강아지와는 공을 받고 던질 수도 있어.
- 노란 게임기 모양의 대화 화면에서 동그란 질문 버튼을 누르거나 직접 질문 입력하기.
- 대화 수첩에서 이전 이야기와 관찰 기록 보기. 확인이 필요한 내용은 보호소에 물어볼 질문으로 담아둘 수 있어.
- 대화를 나눈 뒤 직접 버튼을 눌러 사진과 소개서 보기. 프로필에서 ‘조금 더 이야기하기’를 누르면 다시 대화로 돌아가.
- 입양 전에 확인할 항목을 체크하고, 가족 구성이나 돌봄 계획을 적어보기.

컴퓨터로 볼 때는 방향키나 WASD로 움직이면 돼. Shift를 누르면 달리고, E는 공놀이 키야.

## 아직 연결하지 않은 부분도 있어

보호소랑 강아지 정보는 전부 흐름을 보여주기 위한 가상 예시야. 대화도 실제 AI가 답하는 건 아니고, 질문을 미리 넣어둔 관찰 기록과 연결해서 답하도록 해뒀어. 기록에 없는 내용은 모른다고 답하고 보호소에 확인할 질문으로 남기는 방식이야.

등록은 서비스와 연결된 보호소만 할 수 있게 만들 계획이야. 시안은 계정에 따라 화면을 다르게 보여주는 정도이고, 별도로 만든 서버에는 로그인 검증과 보호소 권한 확인이 들어 있어. 서버의 동물 등록·수정과 관찰 기록 API도 준비됐고, 시안 화면 연결은 다음 작업이야.

현재 웹 시안의 대화 내용이나 입양 준비 메모는 새로고침하면 초기화돼. 서버에는 대화방·메시지 저장 API가 준비됐지만 시안과 아직 연결하지 않았어. 체크하거나 메모를 적어도 실제 입양 신청이나 서류 제출이 되는 건 아니야.

## 코드 수정할 때는 여기부터 보면 돼

화면을 수정하고 아래 명령어를 실행하면 `index.html`이 다시 만들어져. 빌드는 Python 3만 있으면 되고, 추가 패키지는 필요 없어.

```sh
python3 scripts/build.py
```

자주 볼 파일은 이 정도야.

- `work/mobile-concept/shelter-mobile.html`: 보호소, 프로필, 입양 준비 화면이랑 예시 데이터가 들어 있어.
- `work/mobile-concept/walk-*`: 운동장 화면과 조이스틱, 캐릭터 이동 관련 파일이야.
- `work/mobile-concept/natural-dogs.js`, `ball-play.js`: 강아지가 움직이는 방식이랑 공놀이를 다뤄.
- `work/mobile-concept/pet-chat-*`: 게임기 모양의 대화 화면을 수정할 때 보면 돼.
- `scripts/standalone-template.html`: 시안을 일반 브라우저에서 열 수 있게 감싸주는 틀이야.
- `index.html`: 위 파일들을 합쳐서 만든 실행 화면이야. 수정은 원본 파일에서 하고 다시 빌드해줘.

PNG 이미지들은 이미 넣어뒀어. 이미지를 다시 만들고 싶을 때만 `make-*.py`나 `prepare-player-sheet.py`를 실행하면 되고, 그때는 Pillow가 필요해.

## 백엔드 작업

`backend/`에 Spring Boot와 Supabase PostgreSQL을 쓰는 서버 구성을 넣었어. Java 21로 실행하고, 자세한 설정은 [백엔드 실행 안내](backend/README.md)를 보면 돼. 서버 상태 확인과 [데이터 구조·마이그레이션](docs/data-model.md), [가상 보호소 2곳·강아지 5마리 샘플](backend/sample-data/README.md), [보호소·강아지 조회 API](docs/read-api.md), [Supabase 인증·보호소 권한](docs/auth-and-permissions.md), [강아지·관찰 관리 API](docs/dog-management-api.md), [대화방·메시지 저장](docs/chat-storage-api.md), [기록 기반 AI 답변](docs/grounded-chat-api.md)이 들어 있어. AI는 서버 키 설정과 V2 적용 뒤 켜야 하고, 실제 응답 검증과 시안 연결은 아직이야.

[구현 순서와 브랜치 규칙](docs/backend-workflow.md)에 따라 작업별 PR을 만들고, 노션 카드에 진행 상태와 병합 결과를 같이 남겨.

## 움직임을 수정했다면 확인해봐

이동이나 공놀이 코드를 바꿨으면 아래 검사도 한 번 돌려봐. 이쪽은 Node.js가 설치돼 있어야 해.

```sh
node work/mobile-concept/check-player-motion.cjs
node work/mobile-concept/check-natural-dogs.cjs
node work/mobile-concept/check-ball-play.cjs
```

이동 속도랑 애니메이션, 10초 뒤 앉기, 공을 주고받는 순서, 장애물 돌아가기, 관찰 기록에 맞는 행동이 유지되는지 확인하는 검사야.

이미지 출처랑 수정 내역은 [CREDITS.md](CREDITS.md)에 따로 적어뒀으니까, 에셋 쪽을 만질 때 같이 보면 돼.

사진 조회 API와 프론트 연결 방법은 [사진 조회 문서](docs/photo-read-api.md)에 정리했어. 실제 사진 파일과 Supabase Storage 설정은 별도로 준비해야 해.
