# 같이 써볼 샘플 데이터

보호소 2곳, 강아지 5마리로 화면과 서버를 맞춰볼 수 있게 준비했어. 이름, 위치, 생일, 관찰 내용은 전부 가상이고 실제 입양 정보는 아니야.

[dataset.json](dataset.json)이 원본이야. 프론트에서도 먼저 열어보고 임시 화면에 쓸 수 있어. 다만 이 파일은 DB에 넣는 개발용 자료라 담당자와 검토 전 기록도 들어 있어. 그대로 사용자에게 내려주는 API 응답은 아니야. 실제 응답 필드는 C-03에서 같이 정하자.

## 어떤 친구들이 있나

| 보호소 | 강아지 | 소개에 쓸 특징 | 생일 표시 예시 | 성별 / 체중 | 입양 상태 / 공개 |
| --- | --- | --- | --- | --- | --- |
| 온기 보호소 (가상) · 서울 은평구 | 봄이 | 천천히 친해지고, 짧은 공놀이를 즐김 | 2023년생 추정 | 암컷 / 6.8kg | 입양 가능 / 공개 |
| 온기 보호소 (가상) | 두부 | 냄새를 살피며 느긋하게 산책 | 2022년생 추정 | 수컷 / 8.2kg | 입양 가능 / 공개 |
| 온기 보호소 (가상) | 콩이 | 공을 따라가고, 잠깐 놀고 나면 쉬는 편 | 2025년 4월생 추정 | 수컷 / 10.4kg | 입양 진행 중 / 공개 |
| 다온 보호소 (가상) · 경기 고양시 | 밤이 | 조용한 방석, 천천히 다가오는 인사를 선호 | 생일 미확인 | 암컷 / 15kg | 입양 가능 / 공개 |
| 다온 보호소 (가상) | 해리 | 익숙한 담요와 간식 장난감을 살펴봄 | 2020.09.10 | 수컷 / 12.1kg | 소개 준비 중 / 비공개 |

온기에는 3마리, 다온에는 2마리가 있어. 해리는 비공개 제외 처리를 확인하려고 넣었어. B-03에서 `isPublic`과 보호소 승인 여부를 반영하면 사용자 목록에는 총 4마리가 나오는 구성이야. `IN_PROGRESS`인 콩이의 표시 방식도 그때 응답에 맞추면 돼.

콩이와 밤이는 중성화 여부를 `null`로 두었어. 미확인을 ‘안 했음’으로 표시하면 안 돼. 생일도 연도만 알면 `01-01`, 월까지 알면 `01`을 저장에 사용하지만, 화면에서는 `birthDatePrecision`에 맞춰 위처럼 보여줘. 밤이는 날짜 자체가 없어.

소개 문구는 강아지가 말하는 말투로 썼고, 관찰 기록에는 실제로 본 행동처럼 상황과 반응을 구체적으로 적었어. 한 번의 관찰을 ‘항상 그렇다’는 성격으로 단정하지 않도록 해줘.

## 기록과 계정

| 데이터 | 개수 | 용도 |
| --- | --- | --- |
| 가상 운영자 | 1 | 보호소 승인 이력 |
| 가상 보호소 담당자 | 2 | 각 보호소의 ACTIVE MANAGER, 기록 작성·확인 |
| 가상 방문자 | 1 | 이후 대화·메모 테스트에 사용할 식별자 |
| 보호소 / 소속 관계 | 2 / 2 | 승인된 공개 보호소, 보호소별 담당자 |
| 강아지 | 5 | 프로필·목록 상태 비교 |
| 관찰 기록 | 25 | 강아지마다 확인 완료 4개와 검토 전 또는 철회 기록 1개 |

확인 완료는 20개, 검토 전은 4개, 철회는 1개야. 밤이의 철회 기록은 다른 강아지의 공놀이 기록을 잘못 옮겼다는 내용이야. 나중에 AI에 넘길 때는 해당 강아지의 `CONFIRMED` 기록만 사용하고, `DRAFT`와 `RETRACTED`는 제외해야 해. 그 필터와 AI 연결 자체는 B-07에서 구현해.

계정에는 이메일, 비밀번호, 인증 제공자 ID가 없어. 로그인 가능한 계정을 만드는 작업도 아니야. 보호소 전화번호·상세 주소·웹사이트와 실제 사진도 넣지 않았어. 지도 좌표는 지역 표시를 연습할 대략적인 테스트 지점이고, 실제 보호소 주소로 안내하면 안 돼.

## 도트와 맵 연결

`avatarKey`는 파일 URL이 아니라 프론트에서 찾을 이름이야. 기존 시안의 이미지는 저장소 루트 기준으로 아래처럼 연결할 수 있어.

| 키 | 사용할 수 있는 기존 파일 |
| --- | --- |
| `bomi` | `work/mobile-concept/bori-avatar.png` (파일명은 bori지만 봄이 이미지) |
| `dubu` | `work/mobile-concept/dubu-avatar.png` |
| `bami` | `work/mobile-concept/bami-avatar.png` |
| `kongi` / `haeri` | 아직 전용 이미지 없음. 준비 전에는 기본 도트 캐릭터 사용 |

`mapKey`는 온기 `sunny`, 다온 `forest`로 구분했어. 각각 햇살 운동장과 숲속 산책길에 연결할 논리 이름이고, 실제 프론트 파일 매핑은 아직 하지 않았어. 8개 행동의 속도·빈도·거리 설정은 B-10에서 정하므로 지금은 `dog_behavior_profiles`를 비워뒀어.

## 로컬 DB에 넣기

`backend/`에서 실행해. 먼저 [서버 실행 안내](../README.md)에 따라 로컬 PostgreSQL을 켜고 `.env`를 불러온 뒤, `DB_MIGRATE=true ./gradlew bootRun`으로 V1 테이블을 한 번 만들어줘. 준비 상태가 정상이면 서버를 끄고 아래 명령을 실행해도 돼.

```sh
./gradlew loadSampleData
```

서버 실행과 마이그레이션에서는 샘플이 자동으로 들어가지 않아. 위 명령을 직접 실행할 때만 현재 `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`로 접속해.

허용 주소는 `localhost`, `127.0.0.1`, `[::1]`의 `shelter_connect` 또는 `shelter_test` DB야. URL 옵션이 붙거나 Supabase 등 원격 주소면 접속 전에 중단해. 로컬 전용 개발 DB에 사용해줘.

처음에는 사용자 4명, 보호소 2곳, 소속 2개, 강아지 5마리, 기록 25개가 추가돼. 같은 고정 ID가 있으면 건너뛰어서 두 번째 실행 결과는 모두 0이야. 중간에 수정한 소개나 입양 상태는 덮어쓰지 않고, 빠진 행만 다시 넣어. 파일을 수정했다고 기존 DB 내용까지 갱신되지는 않아.

전체 작업을 한 트랜잭션으로 처리해서 중간에 잘못된 참조가 나오면 이번에 추가한 내용은 모두 취소해. 자동 초기화나 데이터 삭제 기능은 없어.

원본 JSON과 로더는 서버 JAR에 포함되지 않아. B-02에서는 로컬·CI 로딩을 준비했고, 이어진 B-02A에서 지정 Supabase 개발 프로젝트에 실제 적용했어. 로그인, API, 사진, AI 대화는 아직 연결하지 않았어.

## 새 Supabase 프로젝트에 처음 넣을 때

DB 비밀번호를 로컬에 설정하기 전이라면, 로그인된 Supabase SQL 편집기에서도 처음 한 번 적용할 수 있어. **아직 `shelter` 스키마가 없는 개발 프로젝트용**이야.

```sh
./gradlew exportSupabaseBootstrap
```

`backend/build/supabase-bootstrap.sql`이 만들어져. 이 명령은 파일만 만들고 DB에는 접속하지 않아. 적용할 프로젝트 이름과 기존 테이블을 먼저 확인한 뒤, SQL 편집기에 파일 전체를 넣어 실행하면 돼.

기존 V1 파일을 그대로 포함하고 샘플 JSON을 INSERT로 바꿔서, 테이블·기록·샘플을 한 트랜잭션으로 넣어. 이미 `shelter`가 있으면 중단하므로 반복 실행하거나 기존 DB를 초기화하는 용도로 쓰면 안 돼. 마지막 결과가 보호소 2·강아지 5·관찰 25인지 확인해줘.

SQL 편집기에서 직접 실행한 V1의 파일명·체크섬도 같은 트랜잭션의 Flyway 이력에 남겨. 사용 중인 Flyway 12.4의 PostgreSQL 이력 형식을 사용하고, 체크섬은 Flyway 계산기로 구해. CI에서는 별도 임시 PostgreSQL DB에 생성 SQL을 적용한 뒤 실제 Flyway `validate`와 `migrate`를 실행해서, 검증이 통과하고 V1을 다시 실행하지 않고 V2로 이행하는지 확인해. 내보내기 파일은 V1만 포함하므로 AI 답변을 켜기 전에는 Flyway로 V2까지 적용해야 해.

이 방법도 `shelter`의 RLS와 비공개 권한을 유지해. Supabase 기본 스키마나 Data API 공개 설정은 바꾸지 않아. 이후 서버 연결에는 기존 안내대로 DB 환경변수가 필요해.

앱 테이블 11개와 Flyway 이력 테이블 모두 RLS를 켜. Supabase 편집기가 RLS 확인 창을 보여주면 **Run and enable RLS**로 실행하면 돼. 이력은 DB 소유 계정으로 관리하고, 모바일·웹 사용자는 DB에 직접 접근하지 않는 구성이야.
