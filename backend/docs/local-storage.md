# Windows private file storage

`STORAGE_BACKEND=local` selects native filesystem adapters for dog photos, generated assets and community images. Auth remains an independent GoTrue service; the existing `SUPABASE_URL` setting points to its HTTPS origin. The default `supabase` mode is retained.

Required settings:

- `LOCAL_STORAGE_ROOT`: absolute protected directory with an `objects` subdirectory.
- `LOCAL_STORAGE_SIGNING_KEY`: persistent base64url encoding of at least 32 randomly generated bytes. Keep it outside Git and grant access only to the service account and administrators.
- `LOCAL_STORAGE_PUBLIC_URL`: HTTPS API origin. HTTP `127.0.0.1` is allowed for isolated local verification.
- Existing photo/asset/community enablement flags still apply. Local storage does not require a Supabase server key. Asset workers and automatic imports must stay disabled during migration; enabling either still requires a PixelLab API key.

Object filenames are `SHA256(bucket + "/" + key) + ".blob"`, compatible with the verified export manifest. Preserve every object key in the database, verify file sizes and hashes before copying, and use a separate writable copy rather than the original backup. Buckets remain private; only domain services issue signed URLs after their existing permission checks.

Signed URLs expire after 60 seconds, bind the object ID and expiry with HMAC-SHA256, and are validated before any object read. Downloads use no-store, nosniff and no-referrer headers. There is no public directory listing or direct filesystem path route. Uploads use atomic replacement on the same filesystem; file, bucket and size validation applies.

Grant the Windows backend service account read/write permissions only to the live object directory. Retain owner-only permissions on backup copies and signing-key configuration. Back up the app database, Auth database, live object files and persistent configuration together to storage outside the miniPC. A database dump alone does not include image files.

Cutover requires a write pause, final data and file synchronization, an explicit Auth-provider identity mapping, and API verification. Preserve the old services and the pre-cutover copies until the rollback and restore checks pass. This implementation alone does not perform a production cutover or configure outgoing email.
