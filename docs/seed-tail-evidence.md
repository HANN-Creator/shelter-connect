# B-69 기본 도트 꼬리 검수 근거

[노션 B-69](https://app.notion.com/p/3f45b2d1a55f80ec94c8da223b8e68c6) · `backend/b-69-tail-evidence`

B-68 배포 뒤 비공개 실제 생성에서, 측면 꼬리가 작은 등 윤곽처럼 보이는 도트가 일반 검수에서 PASS 처리되고 SYSTEM 기본 도트 승인을 받았다. 사진에서는 꼬리가 가려져 있었으며, 이것이 원래 짧은 꼬리라는 근거는 없었다. 해당 테스트 작업은 공개하지 않고 취소했고 임시 STAFF 소속·로그인과 원본 사용 허가를 해제했다. 기존 이미지·판정·3회 PixelLab 요청 이력은 보존했다.

## 처리

- 일반 외형 검수와 별도로 실제 사진 및 WEST/EAST 도트를 Luna가 관찰한다. 이전 판정이나 기대 정답은 주지 않는다. BASE 검수마다 Luna 요청 1회가 추가된다.
- 사진의 꼬리 가시성, 도트의 꼬리 연결·윤곽·끝과 위치 좌표를 별도로 기록한다. 사진에 가려진 꼬리를 생물학적으로 짧은 꼬리라고 확정하지 않는다. 정면의 정상 가림이나 뒷모습 눈 비노출 기준은 바꾸지 않는다.
- 실제 원본 32px와 좌표 격자를 정수 배율로 보여준다. 모델이 지목한 꼬리 경로를 원본 알파 픽셀로 확인한다. 인접한 경유점 사이의 모든 픽셀도 확인해 투명한 틈을 건너뛴 경로를 거절한다. 일반 완전 꼬리는 4개 이상 픽셀·3px 이상 범위가 필요하다. 실제 사진에서 완전한 짧은 꼬리가 명확히 확인된 경우에는 짧지만 보이는 경로를 허용한다.
- 일반 검수 PASS가 별도 꼬리 실패를 덮어쓰지 못한다. 기존 일반 판정은 `generalPropertyReview`, 추가 근거는 `tailEvidence`로 보존한다. 구체적으로 실패한 측면만 기존 B-68 선택 보완에 연결한다. 위치가 불확실한데 완전한 꼬리라고만 답한 경우에는 추가 이미지 비용을 쓰지 않고 보류한다.
- 새 작업은 `qualityPolicy.seedTailEvidenceVersion=photo-tail-evidence-v1`을 저장한다. 해당 작업의 기본/최종 승인에는 사진·전체 4방향 도트·규칙·모델이 일치하는 통과 근거가 필요하다. 누락·다른 사진·모순 판정은 승인하지 않는다. 이전 저장 작업의 정책을 일괄 변경하지 않는다.
- 첫 생성과 보완 모두 공유 규칙의 꼬리 예방 문구를 사용한다. 승인 그림체 `cozy32-photo-style-v1`, 스타일 원본, 도트 크기32·모션 여백40, 최대 기본 보완3회/동작당3회, 접수 불명·중복 보호는 그대로 사용한다.

규칙: `sprite-regressions-2026-10-09-v17` / SHA256 `84a6c987de69c9e911997aac3b91df0262566396ab4e42279101af2e82768082`.

## 실제 이미지 검증

실제 `gpt-5.6-luna` 검수에 기대 정답 없이 동일 사진과 실패/정상 도트를 각각 보냈다. 텍스트 관찰만 분리한 첫 시도는 실패 도트를 또 PASS 처리했다. 따라서 좌표와 실제 픽셀 근거를 추가했다. 최종 입력에서 실패 원본의 WEST/EAST는 차단됐고 기존 완전한 꼬리 정상 도트는 통과했다. 정상 응답의 2px 간격 경유점을 최초 엄격 인접 검사에서 거절한 기록도 보존하고, 실제 중간 픽셀을 모두 확인하도록 보완한 뒤 동일 응답을 재검증했다. 응답을 통과하도록 수정하거나 다시 생성한 것은 아니다.

[고정 회귀 자료](../backend/scripts/fixtures/tail-evidence-v17/README.md)에 실제 실패 PNG와 원판정, 실제 Luna 응답을 보존한다. 자동 테스트는 네이티브 픽셀과 저장 응답을 재생한다. 이는 모의 AI 성공을 실제 품질 통과로 보고하는 방식과 구분한다. 원본 사진과 비밀 키·서명 주소는 커밋하지 않는다.

검증은 다음을 포함한다. 최종 실행 수치와 CI는 PR·노션에 기록한다.

- Java 단위/HTTP 검사 및 bootJar
- PostgreSQL 통합: 새 근거 누락·다른 사진·모순이면 모션 시작 전 보류, 정상 자동 승인과 이전 정책 호환
- Python 생성 규칙·최대 프롬프트 길이 및 모션 검사
- 실제 실패/정상 쌍의 Luna 검수와 저장된 응답에 대한 원본 픽셀 재검증

실제 재검수 도구는 `StyledSeedTailEvidenceLiveTest`이며 `TAIL_EVIDENCE_LIVE_APPROVED`, `TAIL_EVIDENCE_LIVE_PHOTO`, `TAIL_EVIDENCE_LIVE_OUTPUT`, `OPENAI_API_KEY`를 사용한다. 이미 완료한 응답은 정확한 사진·도트·규칙 해시를 확인하고 재사용한다. 응답 없이 요청 의도만 남았으면 중복 유료 호출하지 않는다. 일반 테스트·CI에서는 실제 API를 호출하지 않는다.

## API·DB·배포와 남은 범위

신규 엔드포인트·마이그레이션·운영 환경변수는 없다. 기존 작업 JSON에 정책과 검수 근거가 추가된다. DB V23을 유지한다. 이번 변경은 코드/검사이며 배포 성공은 별도로 확인해야 한다.

B-68 실서버에서는 readiness, 조회, 정책v16, 중복 요청 재사용, 실제 BASE 저장·해시와 SYSTEM 승인, 첫 IDLE 실패의 자동 보완 시작까지 확인했다. 이후 BASE 오판 때문에 비공개 테스트를 취소했으므로 전체 12개 모션·최종 승인·프론트 재생·10마리 확장은 완료되지 않았다. B-69 배포 후 새로운 비공개 테스트로 이 전체 경로를 이어서 확인한다.

이 검사는 모델이 지목한 위치의 픽셀 존재를 확인한다. 꼬리의 의미적 위치를 완벽히 분할하는 알고리즘은 아니며 모든 강아지에서 100% 판정을 보장하지 않는다. 현재 실제 검증 쌍은 1개 개체의 실패/정상 두 세트다. 비용/오판을 포함한 추가 개체 검증은 전체 자동화 확대 전에 필요하다.
