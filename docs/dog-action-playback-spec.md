# 강아지 행동별 재생 명세서

문서 v2 · 2026-09-23 · [B-18 작업 카드](https://app.notion.com/p/3e45b2d1a55f80c0aa17c4040863a431)

**개발 API:** `https://shelter-connect-dev.onrender.com`

프론트는 행동 코드마다 공통 재생 규칙을 하나씩 만들고, 강아지별 에셋과 행동 설정을 그 규칙에 연결한다. 두부의 WALK와 봄이의 WALK는 같은 이동 로직을 쓰지만 이미지와 행동 비중은 각 강아지의 값을 사용한다.

이 문서의 API 필드와 기본값은 현재 서버 코드 기준이다. 행동 진입·중단 순서, 상황 우선순위, 타이머 기준은 **RN 구현을 위한 v1 초안**이다. RN에 이미 구현됐거나 프론트와 최종 합의한 것으로 보지 않는다. 문서 작성으로 API·DB·생성 스위치를 바꾸지 않는다. 실제 에셋이 등록되지 않은 개발 강아지는 에셋 API에서 404가 나올 수 있다.

## 1. 프론트 고정 규칙과 강아지별 값

| 프론트에서 공통으로 정할 것 | 서버에서 강아지별로 읽을 것 |
| --- | --- |
| WALK는 전진, BACK_OFF는 바라보는 방향을 유지한 후진 | 이동 속도 `speedTilesPerSecond` |
| 어떤 상황에서 어떤 행동을 후보로 삼을지 | 비중 `weight`, 거리·반응 대기, 공놀이 허용 여부 |
| 행동 시작·유지·종료·일어나기 순서 | `minDurationMs`, `maxDurationMs`, `cooldownMs` |
| 행동 코드에 맞는 스프라이트를 찾아 재생하는 방법 | `availableActions`, `animations[code]` |
| 로딩 실패·지원하지 않는 행동의 처리 | 프레임 좌표·시간·반복·마지막 자세·복귀 방식 |

속도까지 공통값으로 시작하려면 서버 기본값인 WALK **0.8**, RUN **1.8**, BACK_OFF **0.6 타일/초**를 기준으로 맞추면 된다. 현재 API는 보호소가 속도를 다르게 저장할 수 있으므로 앱이 상수로 덮어쓰지는 않는다. 모든 강아지의 속도를 고정할지 여부를 바꾸려면 서버 설정 정책도 함께 맞춘다. 이미지 재생 시간을 이동 속도로 대신 계산하지 않는다.

## 2. 맵에 들어올 때 읽는 API

둘 다 로그인 없이 조회하며 응답의 `data`를 사용한다. 상세 오류·관리 API는 [행동 설정 API](dog-behavior-api.md)와 [에셋 API](dog-asset-generation.md)를 참고한다.

| GET 경로 | 사용 항목 |
| --- | --- |
| `/v1/dogs/{dogId}/behavior` | `dogId`, `schemaVersion`, `basis`, `revision`, `settings` |
| `/v1/dogs/{dogId}/assets` | `id`, `schemaVersion`, `status`, `availableActions`, `fallbackAction`, `behaviorRevision`, `frameSize`, `anchorPixels`, `facing`, `baseUrl`, `expiresAt`, `animations` |

행동 설정의 `settings.actions`에는 **8개 코드가 모두** 들어온다. 에셋의 `availableActions`는 **실제 생성·승인된 행동만** 담는다. 현재 신규 생성은 공통 IDLE/WALK/SIT와 대표 행동 최대 2개, 총 3~5개다. 이전 묶음이나 로컬 검토본에는 8개가 있을 수 있으므로 배열 길이를 고정하지 않는다. `BASE`는 기준 이미지이며 선택할 행동이 아니다.

### 선택 가능한 행동 구하기

다음 조건을 모두 만족한 행동만 새로 선택한다.

1. 프론트가 아는 행동 코드다.
2. `availableActions`에 있고 `animations[code]`가 유효하며 시트 로딩이 끝났다.
3. `settings.actions[code].weight > 0`이다.
4. 지금 상황에 맞고 해당 행동의 cooldown이 끝났다.

**에셋이 있다는 것과 그 행동을 하도록 설정됐다는 것은 다르다.** RUN 에셋이 남아 있어도 비중이 0이면 공놀이를 포함해 새로 선택하지 않는다. 반대로 비중이 있어도 에셋이 없으면 그 행동을 재생하지 않는다.

가능한 후보 안에서 `weight / 후보 weight 합계`로 선택한다. 합계가 100일 필요는 없다. 후보가 없으면 로딩된 IDLE로 정지한다. 이 안전 대기는 IDLE의 cooldown에 막히지 않는다. IDLE까지 사용할 수 없으면 현재 유효한 manifest의 `baseUrl`을 정지 표시하고, 기준 이미지도 없으면 로딩/기본 도트 표시를 사용한다. 없는 IDLE 파일을 계속 호출하지 않는다.

`behavior.revision`과 `assets.behaviorRevision`은 달라도 된다. 최신 설정으로 후보를 걸러 현재 승인된 에셋과 교집합을 사용한다. 버전이 다르다고 프론트에서 생성 API를 호출하지 않는다. `basis=DEFAULT`는 서버가 반환한 기본 설정이며, 에셋이 많아도 기본적으로 IDLE/WALK/SIT만 후보가 된다.

## 3. 행동 코드별 규칙

아래 이동·진입·종료 규칙은 RN 구현 초안이다. 반복과 복귀 열은 현재 서버 생성 결과의 값이며 **실제 재생에는 manifest 값을 우선**한다. 각 행의 진입 조건에 2절의 공통 후보 조건도 적용한다.

| 코드 / 화면 이름 | 진입할 상황 | 맵 위치·방향 | 재생과 정상 종료 |
| --- | --- | --- | --- |
| `IDLE` / 가만히 살펴보기 | 기본 대기, 선택 가능한 행동 없음 | 위치 고정. 마지막 방향 유지 | 반복. 설정된 유지 시간 후 다시 선택. 사건 반응은 우선순위에 따라 전환 |
| `WALK` / 천천히 걷기 | 배회, 방문자에게 접근, 공 추적·복귀 | 경로 방향으로 전진. 서버 WALK 속도 | 반복. 목적지 도착 또는 유지 시간 종료 시 IDLE/다음 상태. 장애물로 이동 불가하면 정지 |
| `RUN` / 신나게 달리기 | 달리기 배회, 허용된 공 추적·복귀 | 경로 방향으로 전진. 서버 RUN 속도 | 반복. 목적지·시간 종료 시 정지. 일반 대체는 IDLE, 공 추적은 사용 가능한 WALK를 먼저 검토 |
| `SNIFF` / 냄새 맡기 | 자유 행동 후보 중 선택 | 위치 고정. 발 기준점 유지 | 반복. 유지 시간이 끝나면 IDLE. WALK와 동시에 적용하지 않음 |
| `TAIL_WAG` / 꼬리 흔들기 | 허용된 방문자 인사·놀이 반응 | 위치 고정. 인사할 방향 유지 | 반복. 유지 시간이 끝나면 IDLE. 걸으면서 꼬리만 합성하는 기능은 이번 규격에 없음 |
| `BACK_OFF` / 한 발 물러나기 | 방문자가 개인 거리 안에 있고 반응 대기가 끝남 | 방문자를 바라본 채 반대 방향으로 후진. 서버 BACK_OFF 속도 | 반복. 안전 거리 회복·유지 시간 종료·장애물 중 먼저 발생한 조건에 정지. 도망가는 방향으로 몸을 돌리지 않음 |
| `SIT` / 잠깐 앉기 | 자유 행동 후보 중 선택 | 진입·유지·일어나기 동안 위치 고정 | 앞으로 1회 → 마지막 자세 유지 → 역순으로 일어나기 → IDLE/예약한 다음 행동 |
| `LIE_DOWN` / 편안히 쉬기 | 자유 행동 후보 중 선택 | 진입·유지·일어나기 동안 위치 고정 | 앞으로 1회 → 마지막 자세 유지 → 역순으로 일어나기 → IDLE/예약한 다음 행동. SIT를 먼저 재생할 필요 없음 |

TAIL_WAG가 재생됐다는 이유로 화면에 ‘항상 사람을 좋아함’처럼 성격을 단정하지 않는다. 성격 설명은 보호소 관찰 기록을 사용한다. 방문자 캐릭터의 **10초 정지 후 SIT**는 별도 규칙이며 강아지에 그대로 적용하지 않는다.

### 현재 생성 결과의 참고값

| 코드 | 현재 신규 생성 프레임 수 | 프레임당 시간 | `loop` | `holdLastFrame` | `returnToIdle` |
| --- | --- | --- | --- | --- | --- |
| IDLE | 16 | 140ms | true | false | DIRECT |
| WALK | 48 | 30ms | true | false | DIRECT |
| RUN | 48 | 15ms | true | false | DIRECT |
| SNIFF | 16 | 100ms | true | false | DIRECT |
| TAIL_WAG | 16 | 90ms | true | false | DIRECT |
| BACK_OFF | 24 | 70ms | true | false | DIRECT |
| SIT | 16 | 90ms | false | true | REVERSE_FRAMES |
| LIE_DOWN | 16 | 100ms | false | true | REVERSE_FRAMES |

표는 검사·협의용이다. 로컬 검토본은 선별된 프레임 수가 다를 수 있다. `frameCount`, `frames[i].durationMs`와 실제 배열을 읽고, 16장/24장/48장이나 60fps를 하드코딩하지 않는다.

## 4. 시간·좌표의 뜻

| 항목 | 프론트 적용 |
| --- | --- |
| `speedTilesPerSecond` | 맵 한 타일/초. 이동량 = 정규화한 방향 × 속도 × 경과 초. 대각선에서도 동일 속도 |
| `frames[i].durationMs` | **현재 이미지 한 장**의 유지 시간. 맵 이동 속도와 다른 값 |
| `minDurationMs` / `maxDurationMs` | 행동 진입 시 범위 안에서 유지 시간을 한 번 고름. 매 화면 프레임마다 다시 뽑지 않음 |
| `cooldownMs` | 행동에서 완전히 나온 시점부터 같은 행동을 다시 시작하기까지 기다림 |
| `reactionDelayMs` | 방문자 사건이 생긴 뒤 기다리는 시간. 사건 조건이 사라지면 예약 취소 |
| `ballPlay.reactionDelayMs` | 공이 던져진 사건의 대기 시간. 렌더링 프레임마다 타이머를 초기화하지 않음 |

반복 동작은 시작 시점부터 유지 시간을 잰다. SIT/LIE_DOWN은 진입 애니메이션을 끝낸 뒤 **마지막 자세를 유지하는 시간**에 min/max를 적용한다. 일어나기까지 끝나야 해당 동작 종료와 cooldown 시작으로 본다. 목적지·안전 거리 도착, 충돌, 화면 전환은 최소 시간보다 우선한다.

타이머는 경과 시간을 쓰고 앱이 백그라운드에 있을 때는 멈춘다. 복귀 직후 쌓인 시간을 한 번에 이동량에 더하지 않는다. 위치 변경과 이미지 프레임 변경은 따로 계산하되 같은 실행 상태를 본다.

현재 시트는 64×64 셀, 기준점은 `(32,60)`이다. `anchorPixels`를 기준으로 맵 좌표에 붙이고 확대 배율을 적용한다. 프레임마다 보이는 털의 아래 끝을 맞추면 RUN의 몸 들림이 사라지고 발이 미끄러진다. 충돌 판정은 애니메이션의 몸통 경계가 아니라 고정된 발 주변 영역을 사용한다. 충돌 영역 크기는 맵 타일 규격과 함께 프론트에서 확정한다.

제공 에셋은 `right-three-quarter` 한 방향이다. 좌우·위아래 전용 이미지가 있는 것으로 가정하지 않는다. 좌우 반전 허용 여부와 세로 이동 표현은 프론트·아트 검토 후 확정할 항목이다. BACK_OFF는 몸을 180도 돌리는 방식으로 구현하지 않는다.

## 5. 상황별 후보와 우선순위

아래 우선순위는 프론트 구현 초안이며 서버가 실시간 행동 명령을 보내는 구조가 아니다.

| 우선 | 상황 | 처리 |
| --- | --- | --- |
| 1 | 강아지 비공개·맵 이탈·백그라운드·자원 정리 | 이동·선택 타이머 정지. 비공개 강아지는 제거 |
| 2 | 대화 화면 전환 | 해당 강아지의 맵 배회·공놀이를 멈춤. 대화 UI의 연출은 별도 |
| 3 | 방문자가 개인 거리 안에 들어옴 | 반응 대기 후 BACK_OFF 검토. 없거나 금지·cooldown이면 정지하고 접근하지 않음 |
| 4 | 진행 중인 공 추적·복귀 | 일반 배회 선택 중지. 6절 흐름 실행 |
| 5 | 방문자 접근·인사 | 접근 가능하면 WALK, 도착 후 허용된 TAIL_WAG 또는 IDLE |
| 6 | 특별한 사건 없음 | IDLE/WALK/RUN/SNIFF/SIT/LIE_DOWN 중 가능한 후보로 가중 선택 |

방문자가 `approachDistanceTiles` 이내에 들어온 시점에 반응을 예약한다. 대기 후에도 반경 안에 있고 접근 값이 0보다 클 때 접근한다. `personalSpaceTiles`에서 멈춘다. 두 점이 완전히 겹치면 방향 벡터를 계산하지 말고 정지한다. 경로가 없으면 다른 강아지나 울타리를 통과시키지 않는다.

방문자가 반경 안에 계속 머무른다는 이유로 매 순간 인사를 새로 예약하지 않는다. 새 진입 사건에서 다시 예약한다. BACK_OFF는 현재 개인 거리 조건도 확인하되, 같은 후진이 끝난 직후 계속 반복되지 않게 cooldown을 적용한다. 더 높은 우선순위로 공놀이가 취소되면 공 소유 상태도 정리하고 자동 복귀를 중단한다.

### SIT/LIE_DOWN 중 다른 행동이 필요할 때

1. 진입 중이면 현재 프레임부터 0번까지 역순으로 되돌린다.
2. 마지막 자세 유지 중이면 마지막 프레임부터 0번까지 역순 재생한다.
3. 일어나기가 끝난 시점에 예약된 행동의 에셋·비중·상황을 다시 검사한다.
4. 조건이 여전히 맞으면 시작하고, 아니면 IDLE로 돌아간다.

중간에 다른 요청이 오면 역순 재생을 다시 시작하지 말고 다음 행동 예약만 바꾼다. 제거·화면 전환은 이 과정도 즉시 중단할 수 있다. 일어나기 중에는 맵 이동을 시작하지 않는다.

## 6. 공놀이 연결

`FETCH`, `CATCH`, `THROW`는 현재 강아지 에셋 코드가 아니다. 공 던지기는 방문자와 공의 상호작용이고, 강아지는 기존 WALK/RUN으로 이동한다. 공 이미지 부착·획득 판정·복귀 목적지는 프론트가 관리한다.

공개 행동 API의 `interactions.BALL_CHASE`가 아래 값을 반환한다. `schemaVersion=1`을 지원하는 클라이언트는 이 레시피로 상태를 전환한다.

| 단계 | 사용할 행동 우선순위 | 다음 단계 조건 |
| --- | --- | --- |
| CHASE | RUN → WALK | 공에서 `slowDistanceTiles=1.5` 이내 |
| APPROACH | WALK | 공에서 `arrivalDistanceTiles=0.5` 이내 |
| INSPECT | SNIFF → IDLE | 이동을 멈추고 `sniffDurationMs=1200` 경과 |
| RETURN | WALK | 가져오기 허용 시 던진 위치로 복귀 |
| FINISH | IDLE | 놀이 종료 |

1. `enabled=false`이면 시작하지 않는다. true이면 `reactionDelayMs`를 기다린 뒤 공·경로·강아지 상태를 다시 확인한다.
2. `preferredActions` 순서로 현재 에셋과 양수 비중을 확인한다. 첫 행동을 시작할 때 cooldown을 적용한다. 한 공놀이 안에서 계속 쓰는 WALK를 단계마다 새 선택으로 취급하거나 cooldown으로 중단하지 않는다.
3. CHASE 시작부터 RETURN 종료까지 전체 `maxChaseDurationMs=15000`을 적용한다. 자유 배회의 개별 `minDurationMs/maxDurationMs` 대신 이 제한과 단계 조건으로 이동을 끝낸다. 별도의 공 사건 없이 자동 재시작하지 않는다.
4. INSPECT가 끝나고 `returnEnabled=true`일 때만 공을 입 근처에 붙여 RETURN을 실행한다. 복귀 도착은 같은 0.5타일 반경을 사용한다. false이면 공을 그 자리에 두고 FINISH로 넘어간다.
5. 이동 후보가 없거나 공이 사라짐·소유권 상실·경로 실패·시간 초과가 발생하면 공을 현재 위치에 놓고 `fallbackAction=IDLE`로 정지한다. 더 높은 우선순위의 상태는 즉시 놀이를 취소한다.

SNIFF를 사용할 수 없으면 INSPECT 동안 IDLE로 대기한다. 입 부착 위치는 체형별 보정이 필요한 프론트 값이며 현재 manifest에는 없다. 공놀이 허용 시 서버는 RUN/SNIFF 비중이 양수인 경우 두 대표 행동으로 우선 생성한다. RN에서 이동·공 표시·상태 전환을 구현해야 실제 놀이가 보인다.

## 7. 로딩·버전·오류 처리

| 상황 | 처리 |
| --- | --- |
| 처음 맵 진입 | 두 API를 강아지 ID에 묶어서 읽고, 기본 이미지/IDLE을 준비한 뒤 행동 선택 시작 |
| 선택 동작 시트가 아직 로딩 중 | 후보에서 제외. 먼저 로딩된 IDLE 또는 유효한 기준 이미지로 대기 |
| 알 수 없는 행동 코드 | 선택하지 않음. 다른 유효한 후보 사용 |
| 지원하지 않는 `schemaVersion` | 동적 재생 중단·갱신 안내. 알 수 없는 필드를 추측해서 재생하지 않음 |
| `frameCount`·좌표·프레임 배열 불일치 | 해당 클립을 사용할 수 없음으로 처리. 없는 프레임 좌표로 잘라내지 않음 |
| 시트 URL 만료 / 다운로드 401·403 | manifest를 한 번 다시 읽어 새 URL로 재시도. 반복 실패하면 해당 클립 제외 |
| 에셋 API 404 `ASSET_NOT_FOUND` | 승인본 부재 또는 공개 조건 미충족일 수 있음. 이전 승인 에셋을 계속 표시하지 않고 기본 표시로 전환. 강아지 공개 상태는 행동/목록 조회로 확인 |
| 행동 API 404 `DOG_NOT_FOUND` | 맵에서 해당 강아지 제거 |
| 409 `ASSET_CHANGED` | 새 manifest 재조회. 이전·새 작업의 시트를 섞지 않음 |
| 네트워크/5xx | 실패 안내·재시도 제공. 성공이나 `basis=DEFAULT` 응답으로 위장하지 않음. 유효한 IDLE이 있으면 잠시 정지, 없으면 기본 표시 |

시트 캐시는 `dogId + manifest.id + 행동 코드`로 구분한다. 서명 URL 문자열을 강아지 식별자로 쓰지 않는다. URL은 약 60초 뒤 만료되며, 다운로드가 끝난 로컬 이미지의 재생 시간이 60초로 제한되는 것은 아니다. 다른 강아지로 전환한 뒤 늦게 도착한 이전 요청의 결과는 무시한다.

맵 진입·복귀·새로고침 때 재조회한다. 공개 중단/권리 철회는 별도 실시간 푸시가 없으므로 재조회 시 확인한다. 새 에셋 작업을 받으면 사용 중 클립과 IDLE을 같은 manifest에서 준비한 뒤 한 번에 교체한다. 최신 행동 설정으로 현재 행동이 금지됐다면 다음 선택을 기다리지 말고 중단·일어나기 규칙을 적용한다.

## 8. 프론트와 확인할 예시

아래는 선택 결과 설명용 예시이며 실제 강아지의 성격·서버 응답 JSON이 아니다.

| 사례 | 입력 조건 | 기대 결과 |
| --- | --- | --- |
| 두부는 코를 킁킁 | 에셋 IDLE/WALK/SNIFF, SNIFF 비중 20 | 자유 행동에서 SNIFF를 선택할 수 있음 |
| 봄이는 뛰는 모습이 있음 | 에셋 IDLE/WALK/RUN, RUN 비중 0 | RUN을 선택하지 않음. 공놀이도 WALK만 검토 |
| 설정은 바뀌었지만 에셋은 이전 것 | RUN 비중 20, RUN 에셋 없음 | 자유 행동 후보에서 RUN 제외. 공놀이면 WALK 대체 검토 |
| 공개 근거가 없어 기본 설정으로 돌아옴 | `basis=DEFAULT`, 에셋은 4종 | IDLE/WALK/SIT만 선택. 자발적 접근·공놀이 없음 |

| 개인 거리 안인데 후진 에셋이 없음 | BACK_OFF 미제공 | IDLE로 멈춤. 달리기 에셋을 거꾸로 재생해 후진을 만들지 않음 |
| 모든 이동 클립이 로딩 실패 | 유효한 IDLE만 있음 | 제자리 대기. 맵 위치만 미끄러지듯 움직이지 않음 |
| 10초 동안 강아지가 서 있음 | 강아지 SIT 비중 0 또는 미제공 | 자동으로 앉히지 않음. 방문자 10초 규칙과 분리 |

## 9. 연결 완료 검사

- [ ] 각 강아지가 다른 `availableActions`를 받아도 같은 재생 코드를 사용한다.
- [ ] 비중 0·없는 시트·미로딩·cooldown 상태의 행동은 후보에서 빠진다.
- [ ] 이동은 타일/초, 이미지는 프레임 ms로 계산하고 대각선 속도가 빨라지지 않는다.
- [ ] SIT/LIE_DOWN은 한 번 진입하고 유지한 뒤 역순으로 일어난다. 중간 요청도 현재 프레임에서 처리한다.
- [ ] BACK_OFF는 바라보는 방향과 이동 방향이 반대이며 장애물을 통과하지 않는다.
- [ ] 공놀이가 꺼진 아이는 공을 쫓지 않고, RUN이 없는 아이는 유효한 WALK로 대응한다.
- [ ] 대화·맵 전환·백그라운드에서 타이머가 중복되지 않고 복귀 시 순간이동하지 않는다.
- [ ] 다른 manifest나 강아지의 늦은 응답이 현재 캐릭터를 덮어쓰지 않는다.
- [ ] 404·URL 만료·다운로드 실패·미지원 코드에서 무한 요청이나 빈 프레임 재생이 없다.

프론트에서 최종 확정할 항목은 방향 표현, 충돌 영역, 공 관련 위치·반경, 상황 우선순위와 자세 전환 연출이다. 이 문서는 구현 기준 초안을 제공하며 C-03의 전체 합의나 Q-01의 RN 연결 완료를 대신하지 않는다.
