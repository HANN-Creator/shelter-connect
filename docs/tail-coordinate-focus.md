# 꼬리 좌표를 방향별 확대 이미지로 재검수 (B-72)

[노션 카드](https://app.notion.com/p/3f45b2d1a55f802bb1e5e892c3f653b6) · 브랜치 `backend/b-72-tail-coordinate-focus`.

v18 실서버의 신규 개체 `448536202600925`는 자동 선택 보완 1회 후 일반 외형 4방향 검수를 통과했다. 별도 꼬리 관찰이 EAST 경로의 `(2,11)`, `(2,10)`, `(2,9)`를 투명한 칸에 찍었고, 두 방향을 함께 다시 관찰해도 같은 오류가 남아 `SEED_REVIEW`로 보류됐다. 그림 자체의 확정 결함과 좌표 관찰 실패는 다르므로 이 경우 추가 PixelLab 편집으로 외형을 바꾸지 않는다.

## 바뀐 검수 입력

첫 관찰은 기존처럼 원본 사진과 WEST/EAST 전체 도트를 함께 본다. 불확실한 방향만 각각 한 번씩 다음 입력으로 다시 관찰한다.

- 원본 사진과 해당 방향의 전체 32px 도트 정수 확대본.
- 이전 좌표 범위에 3px 여유를 둔 확대본. 각 칸에 원본의 절대 x,y를 적는다. 경로가 비어 있으면 32×32 전체 격자를 쓴다.
- 이전 응답·정확한 알파 배열·투명한 좌표·전체 이미지와 확대본의 해시. 자른 영역은 위치 힌트이며 꼬리의 끝이나 완전성을 증명하지 않는다.

전체 도트로 꼬리의 연결·형태·끝을 먼저 판단하고 좌표 격자로 위치를 읽는다. 칸의 글자/흰 배경은 원본 픽셀이 아님을 알린다. 투명한 칸 직전에서 경로를 잘라 통과하거나 몸통 픽셀로 경로를 옮기는 방법은 허용하지 않는다. 사진의 기존 관찰과 다른 방향 응답은 서버가 그대로 보존한다. 응답의 방향이 다르거나 스키마가 맞지 않으면 해당 방향은 보류된다.

방향별 호출은 최초 불확실 방향 목록을 고정하여 최대 2회다. 기존 1회 재관찰과 비교하면 양쪽 모두 불확실할 때만 1회가 늘어난다. 한쪽만 불확실하면 호출 수가 같다. 실패한 호출을 무한 반복하거나 사진/스프라이트를 재생성하지 않는다. 한쪽 호출 실패는 해당 방향의 원판정을 보존하며, 다른 쪽 결과는 별도로 남긴다.

원본 PNG·팔레트·그림체·보완 횟수·이력은 유지한다. 기존의 신뢰도(0.75), 실제 알파/연결/길이 검사, 외형/눈/입/꼬리 일관성 검사를 낮추지 않는다. 픽셀 경로의 유효성만으로 꼬리의 해부학적 정확성 또는 최종 팩 품질이 증명되는 것은 아니다. 모호한 결과는 계속 보류한다.

## 적용과 이력

`StyledRecoveryReview`의 공통 기본 도트 검수를 통해 최초 생성, 선택 보완 뒤 검수, 새 규칙 재검수에 동일하게 적용된다. `refinements`에는 방향·확대 범위·원본/입력 이미지 해시·요청 텍스트 해시·원응답 또는 오류를 기록한다. `observationHistory`에는 최초 결과와 성공적으로 해석한 방향별 결과를 남긴다.

공통 규칙은 `sprite-regressions-2026-10-09-v20`, SHA-256 `c4ca9267dfa9b734debb459a9a0ce76950994702bd0922a0fadf41e696911721`이다. 생성 그림체/PixelLab 요청/보완 예산/승인 기준은 변경하지 않는다. 실패 4방향 PNG·실서버 검수 응답·실제 확대 재검수 결과를 `backend/scripts/fixtures/tail-coordinate-focus-v20`에 보존하고 Java/Python 회귀 검사에서 해시와 잘못된 좌표를 재현한다.
