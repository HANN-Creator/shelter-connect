# B-66 기본 도트 그림체·꼬리 보존

눈과 여백이 통과해도 귀여운 그림체가 사라지거나 양옆 꼬리가 빠질 수 있다. 사용자가 새로 제시한 단순한 도트 강아지 예시의 머리·몸 비율, 점눈, 진한 외곽선과 단색 면을 따로 검사하고, 네 방향 꼬리의 존재·연결·모양을 비교한다. 실제 사진의 귀·털·무늬·연령 특징은 유지한다.

## 선택된 새 그림체

작업 중 사용자가 견종별 도트 예시 이미지를 새 기준으로 제시했다. `flat32-photo-style-v2`는 그 이미지에서 글자·로고가 없는 네 강아지 부분을 추린 168px 참조 보드를 사용한다. 원래 32px `style.png`는 보존한다. 사진은 귀·털색·무늬·꼬리의 개체 정보, 참조 보드는 그림체와 비율에 사용한다. 실제 사진의 길고 사실적인 다리를 그대로 따라가지 않고 큰 머리·작은 몸·짧은 다리로 단순화한다. 생성 결과는 계속 원본 32×32이며, 참고 이미지 크기 허용과 결과 픽셀 규칙을 분리했다.

작은 검은 점눈·적은 색상·단색 면·진한 윤곽을 사용한다. 이전의 필수 눈 반짝임·복잡한 명암 규칙을 그대로 강요하지 않는다. 사진의 귀, 털색, 무늬, 실제 꼬리는 유지하고 참조의 흰 스티커 테두리·그림자·글자는 생성하지 않는다. [PixelLab 공식 입력 명세](https://api.pixellab.ai/v2/openapi.json)의 스타일 참조 최대 168px와 두 텍스트 필드 각각 최대 2000자를 확인했다.

## 생성과 검수

- 공통 품질 규칙 v15의 `seedAppearance`를 서버와 CLI의 최초 생성·보완에 모두 전달한다. 스타일 지침과 보완 문장은 PixelLab `style_description`, 사진 외형과 주요 예방 문구는 `description`에 들어간다. 글자 수를 맞추기 위해 규칙을 삭제하지 않는다.
- `SEED_STYLE`: 눈 표현과 별개인 전신 그림체 변화. 각 방향의 `rendering`이 PASS여야 한다.
- `SEED_TAIL`: 양옆 꼬리 누락, 불확실한 꼬리, 방향별 형태·자세 불일치. `tailConsistency`도 PASS여야 한다. 테두리가 비어 있다는 이유로 꼬리가 온전하다고 판단하지 않는다.
- 사진에 꼬리가 안 보이면 `UNOBSERVED`다. 꼬리가 없다는 확인으로 쓰지 않는다. 양옆에는 일관된 꼬리를 표현하고 미확인 부분은 추정으로 남긴다. 실제 짧은 꼬리는 억지로 늘리지 않는다. 사진에서 실제 부재가 확인된 경우만 `CONFIRMED_ABSENT` 예외를 허용한다.
- 정면이나 후면의 기하학적으로 타당한 가림은 허용한다. 양옆 누락을 가림으로 통과시키지 않는다.
- 새 작업과 명시적 새 규칙 재검수는 `seedAppearanceVersion=seed-appearance-v1`을 고정한다. 새 보고서에서 판정 필드가 빠지거나 불확실하면 승인하지 않는다. 기존 승인 작업은 소급 변경하지 않는다. 이전 규칙 해시에 묶인 학습 문장은 새 그림체에 그대로 섞지 않으며 기존 재검증 절차를 거친다.
- 눈 이외 결함은 눈 제한 편집 대상이 아니다. 기존 최대 2회 기본 도트 보완 범위에서 전체 캐릭터 재생성을 사용하며 실패 원본·보고서·비용 이력을 보존한다. 이 작업은 자동 꼬리 영역 편집기를 새로 만드는 범위가 아니다.

## 회귀 자료와 학습

`backend/scripts/fixtures/seed-appearance-v15/`에 실제 꼬리 누락 원본, 수동 검토된 꼬리 수정본, 엄격한 마스크 검사에서 거절된 제공자 응답과 감사 기록을 보존한다. 두 버전 모두 여백 검사를 통과한다. 픽셀 검사는 이 사실과 원본 해시를 확인하며, 꼬리의 시각적 유무를 수학적으로 증명했다고 보고하지 않는다.

새 결함 두 종류를 BASE 학습 범위에 연결했다. V24는 해당 DB 제약에 두 코드만 추가하며 기존 데이터·권한·동작 학습 범위는 유지한다. 실패 사례 기록 → 정상 사례와 독립 재검증 → 활성화된 규칙만 다음 생성에 적용하는 기존 흐름을 따른다. 이 변경 자체가 외부 모델의 가중치 학습을 뜻하지 않는다.

## 적용 범위

공개 API 요청 형식과 환경변수는 그대로다. 품질 보고서에 `appearanceVersion`, `sourceTail`, `tailConsistency`, 각 view의 `rendering`·`tail` 필드와 두 실패 코드가 추가된다. V24는 일회용 로컬 PostgreSQL에서 검증하며 원격 DB에는 적용하지 않는다. 서버 배포가 필요하다. 기존 B-64의 걷기·앉기 잔여 결함은 별도다.

## 실행한 검증

- Java 단위 검사: 404건, 실패 0, 의도된 live/DB 건너뜀 5. PostgreSQL 통합 검사: 418건, 실패 0, 실제 외부 호출 건너뜀 2. `test integrationTest bootJar` 성공.
- Python 스크립트 검사 90건, 모션 검사 26건 통과. 신규 BASE 결함 2종의 저장, 모션 범위 오용 차단, 2회 보완 후 정지, 눈 편집 오용·승인·공개 차단을 일회용 PostgreSQL에서 확인했다.
- 실제 공공 API의 새 성견 `413589202600407` 사진을 PixelLab에 보내 4방향 원본을 생성했다. 이전 실제 호출·실패 원본은 로컬 실행 기록에 보존했다. 사용자 새 스타일 기준을 강화한 결과는 Luna에서 눈·정체성·그림체·꼬리 PASS, 별도 2px 여백 검사에서는 북/서/동 FAIL이었다. 이 결과는 `flat-candidate-margin/` 회귀 자료로 보존한다.
- 해당 후보의 최종 판정은 FAIL이다. 성공 기준을 낮추거나 픽셀을 축소하지 않고 기존 보완 경로로 여백을 재생성한다. 최종 결과는 후속 기록에 추가한다.
- 승인된 실제 이미지 검사에서는 Gradle의 up-to-date / build cache 재사용을 끈다. 입력 경로가 다른 호출을 이전 테스트 성공으로 건너뛰는 문제를 발견해 수정했고, 새 입력에 대한 실제 응답 파일 생성으로 확인했다.
- 모의 응답을 사용하는 코드 검사와 실제 Luna 시각 판정을 구분한다. 로컬 미리보기 생성은 운영 큐·DB 저장·공개 성공이 아니다.
