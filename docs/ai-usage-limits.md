# AI 대화 사용량 제한 · B-29

일반 계정이 질문을 반복해서 보내도 유료 대화 호출이 무한히 늘어나지 않도록 제한한다.

| 환경변수 | 기본값 | 의미 |
| --- | --- | --- |
| `AI_USER_MINUTE_LIMIT` | 6 | 한 사용자의 최근 60초 생성 시도 |
| `AI_USER_DAILY_LIMIT` | 60 | 한 사용자의 UTC 날짜별 생성 시도 |
| `AI_GLOBAL_DAILY_LIMIT` | 500 | 서비스 전체의 UTC 날짜별 생성 시도 |
| `AI_CONCURRENT_LIMIT` | 2 | 서비스 전체에서 동시에 준비하는 외부 AI 답변 |

인사와 기록 없음 안내처럼 서버가 바로 만드는 답변, 완료된 답변 재조회, 이미 처리 중인 메시지 재요청은 집계하지 않는다. 실패 후 명시적인 재시도는 외부 호출 비용이 발생할 수 있어 새 시도로 집계한다. 실패했다고 일일 사용량을 돌려주지 않는다.

생성 전에 DB 트랜잭션에서 한도를 확인하고 예약한다. V7의 `ai_reply_usage` 기록과 PostgreSQL 잠금을 사용하므로 여러 서버, 새 대화방, 서버 재시작에도 같은 한도가 적용된다. 외부 통신 중에는 DB 잠금을 유지하지 않는다. 완료·실패 시 동시 호출 자리만 반환하며, 중간에 서버가 종료되면 예약 만료 뒤 회복한다.

초과 응답은 HTTP `429`이며 기존 `code/message/requestId` 형식을 유지한다. `Retry-After` 헤더는 재요청까지 기다릴 초 수다.

| code | 처리 |
| --- | --- |
| `AI_USER_MINUTE_LIMIT` | 최소 60초 뒤 같은 메시지의 답변 생성 재요청 |
| `AI_USER_DAILY_LIMIT` | 다음 UTC 날짜에 재요청. 기존 대화 조회는 가능 |
| `AI_DAILY_LIMIT` | 전체 일일 한도 소진. 기존 대화 조회는 가능 |
| `AI_BUSY` | 5초 뒤 재요청 |

한도 거절 시 메시지의 생성 시도 횟수를 늘리거나 실패 상태로 바꾸지 않는다. 프론트에서 질문 메시지를 새로 만들지 말고 같은 메시지 ID로 다시 요청하면 된다. 단, 앞선 실제 생성이 `FAILED`라면 기존 규칙에 따라 `retry: true`가 필요하다.

이미지 생성 및 보호소 행동 추천 한도는 각각의 기존 설정을 따른다. 이 제한은 대화 호출 횟수 상한이며 공급자의 요금표에 따른 정확한 금액 상한은 아니다. 출력 토큰 상한과 함께 비용을 제한하고, 공급자 계정의 예산 설정도 유지한다.

적용 순서: 개발 DB에 V7 적용 → 새 서버 배포 → 인증 차단·429 계약 확인. 실제 적용 SHA와 결과는 PR·노션 카드에 기록한다.
