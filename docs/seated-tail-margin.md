# B-49 앉기 왼쪽 꼬리 잘림

공공데이터 개체 `442418202600971`의 실제 PixelLab SIT-west 결과에서 앉은 뒤 꼬리가 오른쪽 경계로 뻗었다. 원본 9프레임 중 **3–8번**이 경계에 닿았으며 마지막 앉은 자세도 잘렸다. 기존 경계 검사는 이 결과를 이미 실패로 판정했고 서버 작업도 미승인 상태다. 보완 2회로 해결되지 않은 결과를 미리보기에서 확인한 사례다.

## 현재 미리보기 복원

- 같은 원본의 정상 2번 프레임에서 온전한 꼬리 픽셀을 가져와, 앉은 엉덩이 위치에 맞게 이동했다. 새 이미지 API 호출은 없다.
- 0–2번 프레임은 그대로 유지했다. 3번은 아래로 3px, 4–8번은 아래로 5px 이동한 꼬리를 사용했다.
- 변경 영역은 이 강아지에서 검토한 `x=27..31, y=16..30`뿐이다. 영역 밖의 몸·얼굴·발 RGBA 픽셀과 원래의 9프레임·130ms·마지막 자세 유지·역순 복귀를 보존했다.
- 수정본은 9프레임 모두 하나의 연결된 실루엣이고, 경계 접촉이 없다. 실제 확대 이미지와 현재 미리보기에서 꼬리 끝을 확인했다.
- 앞서 반영한 B-48 쉬기 꼬리 고정도 유지한다. 서버 원본 PNG·DB·품질 이력·승인·보완 횟수는 변경하지 않았다.

이 좌표와 꼬리 재사용은 **이번 개체 전용의 수동 검토 결과**다. 다른 강아지에 같은 좌표를 적용하는 자동 복원 기능으로 취급하지 않는다. 미리보기의 `sit-left-adjustment/rebuild.py`가 해시·변경 영역을 검증하고 B-48 위에 B-49를 순서대로 재구성한다.

## 다음 생성과 검수

공유 `quality-rules.json`의 SIT 규칙을 구체화했다. 내려앉는 동안과 마지막 유지 자세 모두 꼬리를 엉덩이 옆으로 모으고 **완전한 꼬리 끝**을 화면 안에 두도록 한다. 첫 생성과 기존의 결함별 보완 생성 모두 이 규칙을 사용한다. 다른 행동의 생성 문구는 유지했다.

Luna 시각 검수에는 꼬리를 단순히 잘라 경계 검사만 통과시킨 결과를 `IDENTITY_DRIFT`로 거절하도록 추가했다. 기존 원본 9프레임 경계 검사도 계속 강제한다. 규칙 강화가 다음 유료 생성의 성공을 보장한다는 뜻은 아니며, 이번 작업에서는 새 유료 생성을 실행하지 않았다.

## 재현·예방·차단 검증

실제 원본과 수정본의 알파 픽셀을 `backend/scripts/fixtures/sit-tail-alpha.json`에 저장했다. 사진·자격 증명은 포함하지 않는다.

| 검사 | 확인할 결과 |
| --- | --- |
| Python·Java 실제 원본 재현 | 원본 프레임 3–8 전부 `CANVAS_CLIPPING` |
| 수정본의 경계 검사 | 9프레임 모두 경계 접촉 없음 |
| 마지막 프레임만 원본으로 되돌리기 | 프레임 8 실패, 마지막 자세 숨김으로 통과 불가 |
| 검사 중 원본 보존 | 프레임 바이트 변경 없음 |
| 초기·보완 생성 입력 | 4방향·5개 꼬리 계약에서 완전한 꼬리 끝 지시 유지 |
| 제공자 제한 | 모든 행동·방향·보완 조합의 프롬프트 1,000자 이내 |

Java 시각 응답은 의도적으로 통과하는 모의 응답을 사용해 결정적 경계 검사가 우선하는지 검증한다. 모의 응답 통과를 실제 Luna 시각 정확도 검증으로 보고하지 않는다. 실제 코드 테스트·CI·병합 SHA·개발 배포 결과는 PR 기록에 남긴다.
