# B-50 · 실패 사례에서 자동 품질 규칙 만들기

생성 → 검사 → 문제 시트 보완은 기존 서버 기능이다. 이번 변경은 **검사 결과를 장기 보관하고, AI가 예방 문구와 검사 기준을 제안한 뒤 과거 정상·불량 사례로 재검증하여 다음 생성에 적용**하는 부분을 자동화한다. 사람이나 Codex가 매번 규칙 파일을 수정할 필요가 없다.

모델 가중치를 재학습하거나 AI가 Java/Python 코드를 수정하는 방식은 아니다. 실행 코드는 고정하고, 검증된 짧은 규칙을 DB에서 읽는 방식이다. 새로운 픽셀 검사 알고리즘 자체를 만드는 작업은 여전히 개발 범위다.

## 처리 흐름

1. 실제 검사 시 원본 시트·4방향 기준 이미지의 비공개 Storage 키와 SHA-256, 행동·방향·꼬리 계약, 기본 규칙 해시, 검사 결과를 저장한다. 편집 원본이 불량이면 해당 원본을 근거로 저장한다.
2. 불량의 각 결함 코드마다 후보를 하나 만든다. 같은 작업·시트·결함·기본 규칙 버전에는 중복 생성하지 않는다.
3. 동일한 범위에 이미지 해시가 다른 정상 사례가 있어야 진행한다. 없으면 `WAITING_EVIDENCE`로 대기한다.
4. 기존 Luna 설정으로 불량 시트에서 영어 예방 문구(15~120자)와 검사 기준(20~240자)을 생성한다. 전송 직전 사진·파생물 사용 허가와 파일 해시를 재확인한다.
5. 별도 AI 호출에서 최대 4개 사례(불량 최대 2개, 정상 최대 2개)를 재판정한다. 이전 정답·판정 문장은 이 호출에 전달하지 않는다. 기준 이미지와 원본 9프레임, 변경할 수 없는 공통 규칙을 전달한다.
6. 코드가 기존 정답과 비교한다. 정상 오탐, 불량 누락, 규칙 완화, 알려진 잘림 프레임 누락(마지막 8번 포함)이 있으면 `REJECTED`다. 통과하면 `ACTIVE`다.
7. 새 생성 또는 보완 제출 직전에 동일 행동·방향·꼬리 계약·기본 규칙 해시에 맞는 ACTIVE 규칙을 전부 읽는다. 같은 결함의 여러 규칙도 보존한다. [전체 규칙 간결화](all-lesson-compaction.md)에서 Luna가 중복 표현을 합치고, 별도 호출로 모든 규칙의 의미 보존을 검사한 뒤 PixelLab 글자 제한 안의 문구를 사용한다. 길이·누락·충돌 검사 실패는 생성 전에 차단하며 규칙을 버리지 않는다. 원본 검사 기준은 후속 품질 검사에 모두 전달하고 ID·내용·해시·압축/검증 결과를 보존한다.

기존 최대 2회 자동 보완, 접수 불명 중복 호출 방지, 4방향 기준 이미지 승인, 최종 에셋 승인 절차는 유지한다. 승인된 기존 에셋은 수정하지 않는다. 실패 이력을 지우거나 프레임을 숨겨서 통과시키지 않는다.

## 상태와 비용 경계

| 상태 | 의미 |
| --- | --- |
| WAITING_EVIDENCE | 비교할 정상 사례를 기다림 |
| PROPOSING → CANDIDATE | AI가 후보 문구를 생성함 |
| VALIDATING → ACTIVE | 과거 사례 재검증을 통과해 적용 가능 |
| REJECTED | 정상·불량 구분 또는 안전 기준 실패 |
| FAILED | 모델/Storage 오류 또는 작업 중단; 자동 재호출하지 않음 |
| DISABLED | 운영자 중단 또는 근거 이미지 사용 허가 철회 |
| STALE | 공통 규칙 버전 변경으로 재사용 중단 |

후보당 모델 호출은 제안 1회 + 재검증 1회다. lease와 DB 선점으로 중복 워커가 같은 후보를 호출하지 않는다. 응답 불명·재시작으로 lease가 만료되면 실패로 남기며 무한 재시도하지 않는다. 학습 자체는 PixelLab 이미지를 새로 생성하지 않는다. 이후 실제 이미지 보완은 기존 생성 비용이 적용된다.

과거 사례 검증만으로 신규 이미지 품질이 좋아졌다고 단정하지 않는다. `validation.freshGenerationVerified=false`로 이 경계를 명시한다. 새 생성물은 다시 전체 품질 검사를 받아야 한다. 정상 사례 하나만 있는 경우에도 범위를 제한해 적용하며, 다양한 개체의 일반화 보장은 아니다.

새 배포 이후 검사되는 결과부터 축적한다. 기존 DB 이력과 로컬 수동 수정 이미지를 묵시적으로 가져오지 않는다. 기본 규칙 파일의 고정 하네스와 DB의 자동 사례 하네스는 함께 사용한다. CLI와 서버는 같은 `motion_payload`/`learned_guidance`를 쓰지만 독립 CLI가 운영 DB를 자동 조회하지는 않는다.

## API와 DB

운영자만 다음 API를 호출할 수 있다. 인증 없음은 401, 일반 사용자·보호소 담당자는 403이다.

- `GET /v1/operations/styled-quality-lessons`: 최근 100개 후보·상태.
- `GET /v1/operations/styled-quality-lessons/{id}`: 후보, 근거 해시, 재검증 결과, 상태 변경 이력.
- `POST /v1/operations/styled-quality-lessons/{id}/disable`: `{"note":"중단 이유를 10자 이상 입력"}`. 다음 제출부터 적용 중단. 진행 중이거나 이미 끝난 생성물은 소급 변경하지 않는다.

강제 활성화·검사 우회 API는 없다. 잘못된 규칙을 끄면 이후에는 나머지 유효 규칙과 공통 규칙을 사용한다. 자동으로 일반 소스 코드를 되돌리는 기능은 없다.

V15는 `styled_quality_examples`, `styled_quality_lessons`, `styled_quality_lesson_events`와 `styled_asset_steps.learned_lessons`를 추가한다. 세 테이블에 RLS를 적용하고 공개·로그인 클라이언트 직접 접근을 차단한다. 서버 런타임은 사례·이력을 추가/조회만 하며 규칙 상태만 갱신할 수 있다. 기존 권한과 외래 키 정리를 따른다.

기존 `AI_ENABLED`, `ASSET_GENERATION_ENABLED`, `ASSET_WORKER_ENABLED`, `OPENAI_MODEL` 설정을 사용한다. 학습 워커는 서버 내부 예약 실행이며 앱 조회 요청이 학습이나 생성을 시작하지 않는다. 배포 전에 해당 개발 DB에 V15를 적용한다.

## 검증 방법

- 오프라인: 실제 앉기 꼬리 잘림을 재현한 9프레임 알파 fixture, 정상 복원 fixture, 공유 Python 요청 생성기, 로컬 PostgreSQL 워커 통합 검사. 모델 응답과 PixelLab은 모의 응답이며 실제 시각 판별 능력 검증과 구분한다.
- 긍정/부정: 정상 오탐 거부, 정상 사례 없음 대기, 권한 철회 차단, 동시 선점, 중단된 호출 재구매 방지, 다음 개체 적용, 다른 행동/방향 격리, 운영자 중단 이후 미적용, RLS/추가 전용 기록, API 문서와 인증 오류.
- 실제 Luna 검증은 `RUN_STYLED_LESSON_LIVE=true`를 명시한 단일 통합 테스트로 분리한다. 승인된 로컬 이미지 경로·보고서 경로·기존 OpenAI 설정이 필요하며 기본 테스트/CI는 실행하지 않는다. 로컬 임시 DB에서만 실행하고 결과에 실호출과 모의 생성 범위를 기록한다.

### 2026-10-06 실제 Luna 검증

사용자가 기존 4방향 기준 도트와 왼쪽 앉기 원본·보완 9프레임의 OpenAI 전송을 승인한 뒤, 배포된 것과 같은 학습 워커와 `gpt-5.6-luna`로 제안 1회·재검증 1회를 실행했다. 정답을 숨긴 재검사에서 원본의 잘림 프레임 `3, 4, 5, 6, 7, 8`을 모두 검출하고 보완본의 9프레임은 정상으로 판정했다.

모델이 제안한 기준은 “Every frame keeps all visible artwork inside the canvas with no edge clipping.”이었다. 후보가 자동으로 `ACTIVE`가 되고, 로컬 PostgreSQL에 내용·해시·이력이 저장되며, 다음 작업의 PixelLab 요청에 예방 문구와 후속 검수에 검사 기준이 전달되는 것까지 통과했다. 사람이 후보 문구나 활성화 결과를 수정하지 않았다.

이 검사는 실제 이미지에 대한 실제 Luna 호출이며, 최초 실패·정상 라벨은 알려진 원본·보완 사례에서 제공했다. PixelLab 생성·Storage 업로드·최초 품질 검사 응답은 모의 처리했다. 새 강아지 생성이나 새 이미지 품질 개선은 검증하지 않았고 `freshGenerationVerified=false`를 유지한다. 테스트 계정·규칙·작업은 격리된 로컬 DB에서 정리했으며, 이 테스트 규칙을 개발 서버 DB에 옮기지 않았다.

실검증 준비 중 모의 애니메이션이 모든 방향에 왼쪽 첫 프레임을 사용하던 테스트 오류를 수정했다. 방향별 원본 보존 검사 자체는 변경하지 않았다. 별도 방향 fixture 회귀 검사와 실제 다음 생성 요청·검수 기준 전달 단언을 추가했다. 후속 브랜치: `backend/b-50a-live-lesson-verification`.

노션: 이전 자동 승인 검토에서 외부 쓰기가 거절되어 별도 승인 대기 중이다. 이 문서와 PR에 결과를 기록하며 노션 반영 완료로 보고하지 않는다.

## B-52 기본 도트 학습

동작과 별도로 기본 도트(BASE)의 실패·정상 기록과 검증된 규칙 적용도 [기본 도트 학습](seed-quality-learning.md)에 연결했다. V16이 필요하며, 정상 학습 예시는 AI 통과와 같은 원본 해시에 대한 담당자 승인을 모두 만족해야 한다. 동작 9프레임 대신 실제 사진과 네 방향 도트로 재검증하고 다음 기본 도트 생성·눈 검수에 적용한다. 기존 로컬 승인본이나 과거 실패를 자동으로 소급 수집하지 않는다.
