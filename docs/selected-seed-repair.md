# 통과 방향 보존과 선택 보완 (B-68)

노션: https://app.notion.com/p/3f45b2d1a55f80cb8d1bdd4a375b1ab6

B-67 실제 배포 검증에서 뒤쪽 꼬리만 실패했는데 네 방향을 모두 다시 편집하면서, 통과했던 얼굴·무늬·여백이 바뀌었다. 최종 시도는 정면 입 표현으로 보류됐다. 새 작업은 `qualityPolicy.seedRepairVersion=selected-seed-repair-v1`을 고정해 실패한 방향만 보완한다. 승인된 그림체, 기존 팩, 보완 횟수는 유지한다.

## 처리

- 검수의 방향별 필수 판단, 결함 목록, 신뢰도, 실제 가장자리/여백 검사로 대상을 정한다. 다른 방향은 편집 API 입력에서 제외하고 원본 PNG 바이트를 재사용한다. 방향을 특정할 수 없는 실패는 `SEED_REVIEW`로 남긴다.
- 얼굴 외형·그림체·방향·꼬리가 모두 맞고 눈/입만 실패하면 Luna가 작은 네이티브 좌표 영역을 찾는다. 위치가 불확실하거나 마스크가 크거나 투명 영역·후면·몸 아래쪽을 선택하면 전체 재생성으로 우회하지 않는다.
- PixelLab `inpaint-v3`에는 편집 영역과 원본을 전달한다. 결과의 해당 영역만 원본에 적용한다. 영역 밖과 통과 방향의 모든 픽셀은 보존한다. 원본 응답·마스크·수정 픽셀 수·영역 밖 응답 차이를 기록하며 합성한 네 방향 전체를 다시 사진 기반 검수한다. 마스크 처리는 잘림 프레임을 지우기 위한 용도가 아니다.
- 다른 외형 결함은 `edit-images-v2`에 실패 방향만 전달한다. 반환 이미지 개수와 방향 순서를 확인한다. 기존 네 방향 편집 정책을 가진 작업은 기존 프로토콜을 유지한다.
- 매회 전체 Luna 재검수와 실제 알파 여백 검사 후에만 기본 도트를 승인한다. 통과 방향도 다음 검수에서 실제 문제가 드러나면 이후 보완 대상이 될 수 있다. 무변경 응답은 보완 횟수를 소비하며 예산을 초기화하지 않는다.
- 기본 생성과 보완에 자연스러운 작은 입·실제 흰 주둥이 무늬 보존 지침을 적용한다. 검수는 흰 털 자체를 치아/웃음으로 단정하지 않는다. 그림체는 기존 `cozy32-photo-style-v1` 그대로다.

## 기록 및 호환

`qualityReport.seedRepairPlan`에 정책·방향·원본 결합 해시·규칙 해시·위치 판단을 보존한다. `result.selectedRepair`에는 이전 방향별 해시, 편집 원본 저장 키, 실제 수정 픽셀 수를 저장한다. 종전 시도는 `attempt_history`에 남는다. 검수 통과가 없으면 동작 생성·최종 공개가 차단된다. 새 DB 마이그레이션/환경변수/API 경로는 없다. 선행 스키마는 V23이다.

규칙 v16 회귀 자료 `backend/scripts/fixtures/selected-seed-repair-v16`는 실제 실패 원본·마지막 보완본과 당시 판단을 보존한다. 좌표 테스트에 쓰인 마스크는 검사 자료일 뿐, 운영에 강아지별 좌표를 하드코딩하지 않는다. 실제 유료 검증은 opt-in `StyledSelectedRepairLiveTest`로 실행한다. 요청 직전 파일·접수 ID·원본 응답·재검수 결과를 보관하며, 접수 불명 시 재실행으로 중복 구매하지 않는다.

## 검증 결과

2026-10-09 실제 PixelLab 편집 3회와 매회 gpt-5.6-luna 재검수 후 네 방향 모두 통과했다. 처음 WEST 1방향, 다음 NORTH/WEST/EAST, 마지막 WEST/EAST만 편집했다. SOUTH는 전체 3회 동안 최초 PNG와 동일하고 NORTH는 통과 후 마지막 편집에서 보존됐다. 원본 요청/응답과 전체 검수·해시는 로컬 실행 기록에 남겼으며, 공개 가능한 PNG·해시·판정은 `live-evidence.json`과 `selected/`에 보존했다. 검수는 흰 주둥이 털을 실제 치아로 단정하지 않았고, 보완 후에는 측면 흰 무늬와 완전한 꼬리까지 통과했다.

PostgreSQL 422개 통과(2개 선택 검사 제외), Python 90개·모션 26개 통과. 이 DB 검사는 실제 PostgreSQL에 모의 공급자를 연결한 흐름 검사이며, 앞의 실제 공급자 검증과 구분한다. 국소 눈/입 마스크의 픽셀 보존·저장·승인·불확실 차단은 회귀/DB 검사로 확인했고, 이번 실제 공급자 성공 사례는 VIEW 편집이었다. 새 모델 눈/입 국소 편집의 실제 시각 결과를 검증한 것으로 확대 해석하지 않는다.

Render 관리 화면은 Codex 저장 사이트 권한에서 차단돼 새 배포를 수행하지 못했다. 새 코드의 운영 실행·이번 강아지 동작 12시트·최종 서버 SYSTEM 승인·프론트 조회, 10마리 운영 검증은 아직 완료하지 않았다. 실제 기본 도트 통과와 자동화 전체 운영 완료는 구분한다.
