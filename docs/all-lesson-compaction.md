# B-62 전체 학습 규칙의 AI 간결화

첫 기본 도트, 첫 행동 생성, 일반 보완과 학습 후 추가 보완에 **해당 범위의 ACTIVE 규칙 전부**를 사용한다. 고정 2개, 후보 20개, 결함별 1개 제한을 없앴다. 행동·방향·꼬리 계약·공통 규칙 해시는 계속 일치해야 하며, 다른 동작의 규칙을 섞지는 않는다.

## 생성 흐름

1. 유효한 모든 규칙을 ID 순으로 고정하고 원문·검수 기준·ID·해시를 기존 `learned_lessons`에 저장한다. 같은 결함의 서로 다른 규칙도 남긴다. 근거 사용 허가가 철회된 규칙은 사용할 수 없다.
2. 기존 공통 생성 문구를 먼저 만든다. 공급자의 설명 한도(기본 도트/편집 2,000자, 일반 행동 1,000자)에서 공통 문구와 연결 문자열을 뺀 공간을 계산한다. 이는 자체 임의 제한이 아니라 2026-10-07 확인한 [PixelLab OpenAPI](https://api.pixellab.ai/v2/openapi.json)의 `description.maxLength`이다 (`create-character-pro`, `animate-pixminimax`, `edit-animation-v2`).
3. 연결된 Luna에 모든 규칙 원문과 공통 문구, 남은 길이를 보내 중복을 합치고 간결하게 작성하게 한다. 규칙을 선택하거나 버리는 작업이 아니다. 길이·형식이 맞지 않으면 실제 글자 수와 전체 원문을 다시 전달해 작성 호출을 최대 세 번까지 수행한다. 이는 규칙 수 제한이 아니다. 끝내 맞추지 못하면 문장을 자르지 않고 차단한다.
4. 별도 Luna 호출에서 압축 문구를 원본 규칙 **하나씩 전부** 대조한다. 각 규칙의 조건·부정·예외·의미 보존과 공통 문구와의 양립, 새 요구사항 추가 여부를 검증한다. 작성자의 자체 승인이나 일부 규칙만 검사한 결과는 인정하지 않는다. 누락이 검출되면 전체 원문과 실패한 규칙별 판정을 작성자에게 돌려보내 최대 세 차례 작성·검증한다. 각 검증에 사용한 문구와 판정 이력도 보존한다.
5. 길이·문자 형식·전체 판정 개수·모든 규칙의 보존 여부를 서버가 검사한다. 하나라도 실패하면 PixelLab 접수 전에 중단한다. 긴 문장을 자르거나 누락 규칙을 제거하여 통과시키지 않는다.
6. 공통 생성 문구는 그대로 두고 검증된 문구를 덧붙인다. 전체 규칙 해시와 실제 전송 설명 해시가 저장된 검증 결과와 일치해야 유료 요청을 예약한다. 추가 보완의 필수 규칙 ID·해시 검사도 유지한다.
7. 이미지가 생성되면 **압축 전 원본 규칙의 검수 기준 전부**를 품질 검수에 전달한다. 압축한 문장만으로 검수하지 않는다.

AI의 의미 보존 판정도 오류 가능성이 있으므로 기존 픽셀·가장자리·외형·방향 검사와 사람의 승인 단계는 유지한다. 문자열 연결 테스트나 모의 AI 통과를 실제 이미지 품질 통과로 보고하지 않는다.

## 재사용과 실패 보존

V21 `styled_lesson_prompts`는 작업·동작·입력 해시별로 원본 규칙, 공통 문구, 글자 수, 작성 결과, 별도 검증 결과, 최종 설명 해시와 상태를 보존한다. 동일 입력의 READY 결과는 재사용한다. 규칙이나 문구 한도가 바뀌면 별도 입력으로 기록한다. 모델 호출 전 단계를 저장하므로 중단된 호출을 서버 재시작 때문에 자동 중복 실행하지 않는다. 실패한 동일 입력도 임의 재시도하지 않고 검토가 필요함을 표시한다.

- `LESSON_PROMPT_NO_SPACE`: 공통 문구 뒤에 압축 문구를 담을 공간이 없음.
- `LESSON_PROMPT_INVALID`: 길이·형식이 잘못된 압축 결과.
- `LESSON_PROMPT_MEANING_LOST`: 누락·변경·충돌·새 요구사항 또는 불완전한 검증 결과.
- `LESSON_SOURCE_CHANGED`: 규칙 상태·원본 권한·고정한 입력이 바뀜.
- `LESSON_PROMPT_INTERRUPTED` / `LESSON_PROMPT_REVIEW_REQUIRED`: 중단 또는 실패한 동일 입력. 유료 이미지 자동 재접수 없음.
- `LEARNED_RULE_NOT_APPLIED`: 실제 생성 문구가 검증된 결과와 다르거나 추가 보완 필수 규칙이 빠짐.

기존 요청 횟수와 보완 예산, 접수 불명 보호, 승인 에셋과 그림체, 공통 품질 기준 v12는 바꾸지 않는다. 모델의 가중치를 재학습하는 기능이 아니라 검증된 규칙을 생성 요청에 활용하는 기능이다.

## DB·검증·배포

DB V21은 새 기록 테이블 하나를 추가하며 런타임 서버 역할에만 접근을 허용한다. 기존 테이블 데이터를 수정하지 않는다. API 요청 형태와 새 환경변수는 없다. 배포 전에 V21을 적용해야 한다.

회귀 검사는 후보 20개를 넘는 동일 결함의 규칙 전체, 기본 도트와 행동 첫 생성 및 추가 보완, 압축 누락·길이 초과·허가 철회 차단, 캐시 재사용·중단 시 모델 중복 방지, 생성 설명 해시와 원본 규칙의 검수 전달을 확인한다. 로컬 및 CI 결과와 실제 개발 DB 적용·배포 여부는 PR과 노션 기록에 남긴다. 이미지 재생성과 실제 시각 품질 확인은 B-60에서 이어간다.

## 실제 텍스트 연결 확인 (2026-10-07)

사진을 전송하지 않는 서로 다른 예방 규칙 여덟 개의 합성 자료로 실제 `gpt-5.6-luna` 작성·별도 의미 검증을 호출했다. 원문 합계 477자를 410자로 정리해 420자 한도와 여덟 규칙 모두의 의미 보존 판정을 통과했다. 이는 검증 자료의 개수이며 실제 적용 개수 제한은 없다.

앞선 380자 스트레스 확인에서는 길이 초과, 문장 끊김, 조건 누락을 검출해 차단했다. 길이 피드백과 전체 원문을 다시 주는 작성 보완 및 누락 판정을 돌려주는 자동 재작성으로 연결했다. 매우 작은 여유 공간에 모든 고유 조건을 담을 수 있다고 보장하지 않는다. 실패하면 조건 삭제나 문자열 자르기로 통과시키지 않는다. 이 검증은 텍스트와 서버 흐름에 대한 것이며 새 PixelLab 이미지 생성은 수행하지 않았다.
