# B-74 기준 도트 보완 재개와 얼굴 무늬 검수

[노션 카드](https://app.notion.com/p/3f45b2d1a55f801fbf4dddc74ab689ad) · `backend/b-74-recheck-repair-resume`

기존 `quality-recheck`는 저장된 이미지만 재검수한다. 규칙 변경 후 남은 예산이 있어도 이미지를 다시 생성하지 않는 기존 계약을 유지한다. 별도 명시적 재개가 필요한 미승인 BASE에는 다음 API를 사용한다.

`POST /v1/shelter-admin/dogs/{dogId}/styled-assets/{jobId}/seed-repair-resume`

본문: `requestId`(UUID), `note`(20–2000자), `expectedSeedHashes`(4방향 SHA-256), `expectedRulesSha256`(현재 작업에 고정된 규칙 해시).

같은 보호소 STAFF/MANAGER 권한과 현재 사진 사용 허가를 확인한다. 일반 자동 승인 정책의 `SEED_REVIEW` BASE이고 모든 모션이 아직 시작하지 않았으며 보완 예산이 남아 있어야 한다. 작업별 한 번만 허용하고 같은 ID/본문은 결과가 바뀐 뒤에도 같은 작업을 반환한다. 다른 ID/본문·낡은 해시·이미 시작한 모션·소진 예산·학습 전용 작업을 차단한다. DB V23 유지, 새 환경변수 없음.

이전 결과·검수·제출 영수증·repairCount를 이력에 보존하고 현재 원본부터 검수한다. 원래 maxSeedRepairs/maxRepairsPerClip을 그대로 사용한다. 통과하면 원본 그대로 동작 생성으로 이어지고, 확정 결함이 있으면 남은 횟수로 선택 보완한다. 불확실하거나 위치를 특정할 수 없는 결과는 공개하지 않는다. 수동 승인이나 예산 초기화 경로가 아니다.

## 털무늬 판단과 보완

공통 규칙 v25는 승인된 귀여운 비율·부드러운 팔레트를 유지하면서 큰 흰색/유색 패치의 위치를 보존한다. 사진보다 갈색이 연하거나 명암이 단순하다는 이유만으로 무늬가 사라졌다고 판단하지 않는다. 새 생성과 보완에 같은 예방 문구를 전달한다.

COAT_MISMATCH가 검출되면 기존 판정을 보여주지 않은 독립 관찰을 한 번 수행한다. 무늬 보존, 얼굴 무늬 결함, 몸 무늬 결함, 불확실로 구분한다. 첫 관찰의 무늬 결함과 두 번째 관찰의 정상 판정이 충돌하면 불확실로 남기며 정상 판정을 골라 공개하지 않는다. 다른 눈·방향·그림체·정체성 결함은 해제하지 않는다. 불확실한 털무늬는 유료 보완·부정 학습·자동 승인을 차단한다.

얼굴만 문제인 경우 원래 선택 보완의 REGION 마스크를 사용한다. 원본 32px의 상단 얼굴 영역과 옆모습의 전방 절반에 한정하고 투명 픽셀·몸·꼬리 영역 선택을 거부한다. 마스크 밖은 PixelLab 반환값과 무관하게 원래 픽셀을 유지한다. 위치 판정 실패를 전체 재생성으로 바꾸지 않는다. 독립 재검수로 결과를 확인한다.

## 실제 검증

공공동물 448536202600925의 배포 작업은 v24에서 얼굴 무늬 3방향 실패, 꼬리 통과, BASE repairCount=1/제출 2회 상태였다. 원본 4방향·검수 결과를 `backend/scripts/fixtures/material-coat-v25/`에 보존했다. 이 기록은 판정의 정답을 가정하는 라벨이 아니다.

운영 DB를 변경하지 않고 동일 체크포인트와 이미 소진한 횟수·영수증을 격리 DB에 복제해 실제 배포용 JAR를 실행했다. 승인된 PixelLab/Luna와 비공개 저장소를 사용하고 인증된 임시 STAFF로 새 API를 호출했다. v25 실제 기본 도트 검수는 4방향 통과했고 원본 해시와 repairCount를 그대로 유지해 SYSTEM 승인 후 동작 생성으로 이어졌다. 첫 관찰에서 COAT_MISMATCH가 없어 추가 털무늬 관찰/얼굴 편집 호출은 없었다. 이 결과를 실제 얼굴 편집 품질 검증으로 보고하지 않는다.
