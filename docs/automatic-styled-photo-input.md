# 사진 자동 분석과 native32 생성 연결 (B-94)

`POST /v1/shelter-admin/dogs/{dogId}/styled-assets`는 `traits`를 생략하면 저장된 사진의 외형과 얼굴 영역을 분석해 기존 native32 파이프라인으로 넘긴다. 기존 사진 분석기는 이전 에셋 경로에만 연결되어 있었고 native32 요청은 사람이 작성한 설명을 필수로 요구했다.

## 처리와 저장

1. 권한·사진 사용 허가·행동 선택 버전을 확인하고 사진 ID와 `styled-photo-analysis-v1`으로 동일 요청을 찾는다. 응답은 기존과 같은 202와 작업 ID다.
2. 워커는 현재 규칙·소속 권한·lease를 확인한 후 `qualityPolicy.photoPreparation`에 분석 시작, 모델, 사진 SHA-256, 버전을 저장한다. 네트워크 호출은 DB 트랜잭션 밖에서 실행한다.
3. Luna는 실제 강아지 수, 머리 노출 여부, 정규화된 머리 영역과 8개 외형 관찰을 반환한다. 사진 속 글은 지시로 따르지 않으며 보이지 않는 특징은 불확실한 상태로 남긴다. 각 관찰은 최대 80자로 제한해 기존 설명 필드에 모두 담는다.
4. 원래 응답을 저장한 후 강아지 한 마리·머리 영역·해상도·문자열 한도를 검증한다. 머리 영역에 12% 여백을 추가하고 8개 관찰을 기존 `styled_input`으로 변환한다. 사진 바이트에서 안정적인 seed를 얻는다.
5. `photoPreparation.status=READY`, 분석 원문, 사진/입력 해시를 보존한 뒤 다음 워커 실행에서 기존 스타일·학습 규칙·품질 보완·SYSTEM 승인 흐름을 사용한다. API에는 같은 작업 ID가 유지된다.

분석 준비는 이미지 보완 횟수를 소모하지 않는다. 사진 등록·수집·생성 요청을 시작하는 조건은 바꾸지 않는다. 이 변경은 전체 공공 동물 자동 수집이나 대량 실행 스케줄러를 추가하지 않는다. 성격·건강·입양 정보·추가 행동은 사진에서 추정하지 않으며 기존 확인된 행동 설정을 따른다.

## 실패와 비용 경계

- 같은 사진·분석 버전·행동 버전 요청은 분석 전후 모두 같은 작업을 반환한다. 새 모델 호출이나 새 PixelLab 작업을 만들지 않는다.
- 유효한 분석 응답 저장 후 프로세스가 중단되면 같은 사진 해시를 확인해 저장 응답부터 재개한다. 응답이 남지 않은 시작 기록은 `STYLED_PHOTO_ANALYSIS_INTERRUPTED`로 멈추며 유료 분석을 무조건 반복하지 않는다.
- 여러 강아지, 숨은 머리, 너무 작은/잘못된 영역, 잘못된 분석 필드는 `PHOTO_APPEARANCE_REQUIRES_REVIEW`로 멈춘다. 원문은 담당자가 원인을 확인하도록 남는다. 관찰에 불확실성이 있어도 유효한 한 마리·머리 영역이면 생성할 수 있고 이후 원본 기반 품질 검수를 거친다. 이 구조적 입력 검사만으로 실제 이미지 품질을 보장하지 않는다.
- 저장 사진의 해시가 바뀌면 `PHOTO_APPEARANCE_SOURCE_CHANGED` 또는 기존 `SOURCE_PHOTO_CHANGED`로 차단한다. 권한 철회·lease 만료 후에는 결과를 확정하거나 이미지를 제출하지 않는다.
- 명시한 `traits`가 잘못되었거나 null이면 기존 입력 오류로 거절한다. 자동 분석으로 조용히 전환해 추가 비용을 발생시키지 않는다.
- 자동 입력과 수동 입력은 별개의 요청이다. 같은 사진을 두 방식으로 각각 요청하면 별도 생성 비용이 생길 수 있다. 자동 요청 실패를 해결하려고 중복 요청이나 DB 상태 변경으로 예산을 초기화하지 않는다.

## 적용과 확인

- DB: 기존 `styled_input`과 `quality_policy` JSON을 사용한다. V24 유지, 새 마이그레이션 없음.
- 설정: 기존 `OPENAI_API_KEY`, `OPENAI_MODEL`, AI 및 에셋 워커 설정을 사용한다. 모델이나 PixelLab 설정을 변경하지 않는다.
- 품질 규칙: v41 및 기존 기준 도트/동작 보완 예산 유지. 기존 승인 팩을 변경하지 않는다.
- 단위·PostgreSQL 검증: 입력 범위, 실제 DB 저장, 분석 전후 중복 방지, 네트워크의 트랜잭션 분리, 응답 저장 후 재개, 응답 미확인 시 중복 과금 차단, 사진 변경·권한 철회 차단, 수동 호환을 검사한다.
- 실사진 검증: 공공 API의 새 사진 3장(441553202603073, 441553202603072, 445468202602743)에 구성된 Luna 모델을 실제 호출해 생산 Java 변환기로 입력을 준비했다. 사진 분석 실행 위치는 로컬이며 배포 서버의 신규 사진 전용 진입점 검증과 구분한다.
- 실제 3마리 생성은 준비된 자동 분석 결과를 기존 배포 API의 수동 입력 계약에 넣어 비공개 개발 자료로 검증한다. 이 결과를 신규 `photoId` 전용 경로의 배포 성공으로 보고하지 않는다. 배포 후 해당 경로는 별도 검증이 필요하다.

유료 실분석 검사는 `STYLED_PHOTO_LIVE_APPROVED=true`, `STYLED_PHOTO_LIVE_OUTPUT` 경로와 기존 OpenAI 환경변수를 명시했을 때만 실행한다. 일반 CI에서는 실행하지 않으며 이전 실응답을 재사용할 때 사진·모델·분석 버전을 확인한다. 원본 사진과 API 키는 저장소에 커밋하지 않는다.
