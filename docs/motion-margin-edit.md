# B-55 반복된 동작 프레임 잘림의 마지막 편집 보완

선행 작업은 B-54다. 새 강아지의 실제 왼쪽 WALK에서 최초 생성과 두 번의 재생성이 모두 CANVAS_CLIPPING으로 실패했다. IDLE 전용 편집만으로는 이 경로를 보완할 수 없어 일반 동작의 잘림에도 마지막 편집을 연결한다.

완료 기준은 새 작업의 분기·원본 전송·원본과 복원본 검수·기존 예산 및 정책 보존을 검사하는 것이다. 실제 PixelLab 편집 품질은 별도로 배포 후 검증한다. 노션 새 카드는 앞선 외부 쓰기 승인 대기로 만들지 않았다.

## 서버 동작

- 새 작업만 `qualityPolicy.marginRepair=frame-margin-edit-v1`을 저장한다. 두 번째이자 마지막 보완에 CANVAS_CLIPPING이 남으면 전체 9프레임 편집을 사용한다. 첫 보완은 PixMiniMax 재생성을 유지한다.
- B-54의 IDLE_MOTION 편집 및 기존 LOW TAIL_WAG 편집이 우선한다. 그 외 반복된 잘림은 해당 행동과 방향에 맞는 공통 편집 입력을 사용한다.
- 승인된 도트의 얼굴·귀·털·몸 크기·꼬리 모습을 유지하면서 잘린 끝을 안쪽으로 복원하도록 요청한다. WALK는 보행, SIT은 앉은 마지막 자세 등 공통 행동 규칙을 계속 전달한다. 전신 축소·꼬리 삭제·서 있는 프레임 반복·프레임 제거로 결함을 감추지 않는다.
- 직전 실패 시트의 SHA-256과 크기를 확인하고 전 프레임을 보낸다. 편집 원본을 따로 저장하고 복원본과 원본을 각각 검수한다. 어느 한쪽이 실패해도 최종 승인이 차단된다.
- 기존 작업에 정책을 소급 적용하거나 보완 횟수를 초기화하지 않는다. 기존 2회 한도·중복 전송 보호·접수 불명 처리도 유지한다. 소진된 이번 작업은 자동으로 추가 편집하지 않는다.

## 회귀 자료

기존 `quality-rules.json`의 왼쪽 꼬리 잘림 및 실제 편집 원본 검사 사례가 사용하는 `tail-repair-alpha.json`에 새 WALK 실패 세 시트의 알파 27프레임과 원본 해시를 추가했다. 기존 공통 가장자리 검사로 3개 모두 재현하고, 동일 원본을 손실 없이 편집 입력으로 전달하는지 검사한다. 알파 회귀만으로 꼬리 자세의 시각 판단까지 검증했다고 보지 않는다.

기준 자체를 완화하거나 변경하지 않았으므로 품질 규칙 v9와 해시는 유지한다. 기존 활성 BASE 학습 규칙도 이 변경 때문에 무효화하지 않는다. 편집 방식은 별도의 작업 정책 버전으로 고정한다.

## 연결 범위

REST 요청·DB 마이그레이션·환경변수 추가는 없다. 작업 응답의 `qualityPolicy`에 선택적 필드가 추가된다. 코드·회귀 검사 통과는 실제 외부 모델의 편집 성공을 보장하지 않는다. 테스트·CI·병합·배포 및 실제 원본 검증 결과는 PR과 로컬 검증 기록에서 구분한다.

## 로컬 검사

- Python 42개 통과: 실제 WALK 실패 27프레임 재현, 여덟 행동·네 방향의 전체 프레임 편집 입력과 길이 제한, 기존 품질·생성 회귀.
- Java 단위 17개 통과: 패키징된 Python 빌더의 행동·방향·원본 가장자리 보존과 품질 판정.
- PostgreSQL 통합 61개 통과, 명시적 실제 API 검사 1개 비실행: 마지막 편집 분기, 편집 원본 실패의 승인 차단, 예산 보존, 기존 정책 유지, UNKNOWN 꼬리의 일반 편집과 LOW 전용 편집 분리.
- `bootJar` 성공. 검사의 외부 모델 응답은 모의 응답이며 실제 편집 후 화질 검증이 아니다.
