# B-54 반복 실패한 쉬기의 마지막 보완을 전체 프레임 편집으로 전환

실제 새 기준 도트의 정면 IDLE에서 머리 위로 움직이는 꼬리 같은 돌출부가 생겼다. 최초 생성과 두 번의 PixMiniMax 재생성이 모두 `IDLE_MOTION` 검사를 통과하지 못했다. 문제를 발견·저장하는 기능은 동작했지만 재생성만으로 고치지는 못했다.

## 변경

- 새 작업은 `qualityPolicy.idleRepair=calm-idle-edit-v1`을 저장한다. IDLE의 첫 보완은 기존 재생성이고, 다시 `IDLE_MOTION`으로 실패한 경우 두 번째이자 마지막 보완만 PixelLab `edit-animation-v2`를 사용한다.
- 직전 실패 시트의 저장 키와 SHA-256을 확인하고 9프레임 전체를 전송한다. 승인된 첫 프레임의 머리·눈·귀·발·꼬리 노출과 몸 높이를 기준으로 고치며, 작은 호흡·깜박임만 허용한다. 사진에 꼬리가 보이지 않는 `UNKNOWN`도 승인 도트의 보이는 구조를 따른다.
- 프레임을 자르거나 숨기지 않는다. 편집 원본을 별도로 보존하고 원본과 승인 첫 프레임·팔레트 복원 결과를 각각 검사한다. 어느 쪽이든 실패하면 승인할 수 없다.
- 동작별 보완 한도는 2회로 유지한다. 기존 작업의 정책·이미지·보완 횟수·이력은 바꾸지 않는다. 이 정책이 없는 진행 중·완료 작업은 기존 재생성을 유지하며, 소진된 이번 실패 작업에 세 번째 보완을 자동으로 추가하지 않는다.
- 기존 LOW 꼬리 흔들기 편집은 유지한다. 다른 행동이나 `IDLE_MOTION`이 없는 실패를 이 경로로 보내지 않는다.

## 규칙과 실제 실패 보존

`quality-rules.json`에 이미 등록된 `idle-becomes-tail-wag` 회귀 사례의 `idle-motion-alpha.json` 자료를 확장했다. 이번 최초 생성과 두 번의 실패 결과 27프레임을 알파 값과 원본 SHA-256으로 보존하고, 검사에서 계속 실패하며 편집 요청으로 9프레임 전체가 손실 없이 전달되는지 확인한다.

검수 기준을 완화하지 않아 공통 품질 규칙 v9와 해시는 그대로다. 기존 활성 학습 규칙도 무효화하지 않는다. 편집 방식의 새 버전은 별도 작업 정책에 고정한다. 이 변경은 모델의 실제 편집 성공을 보장하지 않는다.

## 검증

- Python 41개 통과: 실제 실패 3시트 재현, 네 방향 편집 입력·프레임 보존·길이 제한, 기존 생성 및 꼬리 보완 회귀.
- Java 단위 16개 통과: 패키지에 포함된 실제 Python 빌더, 방향별 입력과 전체 프레임, 원본 검사.
- PostgreSQL 통합 57개 통과, 명시적 실제 API 검사 1개 비실행: 마지막 보완 전환·UNKNOWN·편집 원본 실패 차단·두 번의 한도 보존·기존 정책 고정·기존 꼬리 및 학습 경계.
- `bootJar` 성공. 위 검사는 실제 PixelLab 편집 성공을 대신하지 않는다. 새 편집 경로는 배포 후 새 작업으로 별도 실검증해야 한다.

REST 요청·DB 마이그레이션·환경변수 추가는 없다. 생성 작업 응답의 `qualityPolicy`에 선택적 필드 하나가 추가된다. CI·병합·배포 여부와 이번 생성의 최종 품질은 PR 기록에 별도로 남긴다. 노션 외부 쓰기는 앞선 별도 승인 대기로 미동기화다.
