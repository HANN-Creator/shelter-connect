# 사진·특징 → 동작 에셋 실서버 검증

B-22 · [작업 카드](https://app.notion.com/p/3e45b2d1a55f8027b034dd9ffe89c6b4)

검증 도구는 개발 서버에 사진과 관찰 기록을 보내고 결과를 검사한다. OpenAI·PixelLab 호출, 행동 선택, 걷기·달리기 렌더링과 Storage 저장은 배포된 Spring Boot 서버가 한다. 검증 도구에는 OpenAI·PixelLab 키를 주지 않는다.

## 확인하는 흐름

1. 실제 Supabase 임시 계정으로 로그인한다. 가상 보호소에 해당 계정의 테스트 소속과 가상 그림 사용 허가만 준비한다.
2. 서버 API로 비공개 강아지와 확인된 달리기 관찰을 등록한다.
3. 특징 분석 API를 호출한다. `DRAFT`와 확인 필요 표시, 공통 3종에 `RUN`이 추가되는지 확인한다. 같은 요청을 다시 보내도 같은 초안을 받아야 한다.
4. 행동을 확인하고 PNG를 multipart로 업로드한다. 같은 파일과 업로드 ID는 같은 사진·생성 작업으로 반환되어야 한다.
5. 서버 워커가 기준 도트를 만들 때까지 기다린다. `RIG_REVIEW`에서는 유료 요청이 BASE 한 건이고 모든 동작이 대기 중이어야 한다. 이때 최종 승인과 잘못된 체형 버전을 보내면 409여야 한다.
6. 검증용 그림에 한해서 체형 확인 API를 실행한다. 워커가 `REVIEW`에 도달하면 IDLE·WALK·RUN·SIT의 실제 PNG를 내려받아 프레임 수, 투명도, 영역, 시간, 서로 다른 프레임 여부를 검사한다.
7. 가상 강아지를 잠시 공개하고 입양 상태를 `AVAILABLE`로 바꿔 승인 전 에셋 조회 404를 확인한다. 새 강아지의 기본 입양 상태는 `PAUSED`이므로 공개 여부만 바꾸면 승인 후에도 조회할 수 없다. 검증용 최종 승인 후에는 로그인 없이 프론트용 manifest와 행동 설정을 받아 버전을 비교한다. 내려받은 PNG가 검토본과 같은지도 확인한다.
8. 임시 로그인 계정을 삭제하고 소속·허가를 철회한다. 가상 강아지는 비공개·보관 상태로, 사진은 권리 철회 상태로, 작업은 취소 상태로 바꾼다. 검사 전부터 있던 19개 테이블의 행이 그대로인지 확인한다.

체형 확인과 최종 승인은 테스트가 담당자 역할로 API를 호출하는 것이다. 실서비스의 검토 절차를 없애지 않으며, 자동 체형 제안이나 보행이 보기에도 자연스럽다는 판정은 포함하지 않는다. 사진 입력 자리는 직접 그린 가상 그림으로 검사한다. 실제 보호소 사진 사용 허가와 RN 재생 검수는 별도다.

이 검사의 갈색 가상 강아지는 서버 흐름 검증용이다. 사용자가 승인한 두부 캐릭터를 대체하거나 그림체 변경을 승인한 결과로 제시하지 않는다. 디자인 비교에는 승인된 원본을 사용하고, 새로 생성한 결과인지 기존 원본을 렌더링한 결과인지 표시한다.

## 실행

Python과 `backend/motion-requirements.txt`의 라이브러리, `psql`이 필요하다. 로컬 설정 파일은 기존 Supabase 개발 DB와 Storage 설정을 사용한다. 개발 프로젝트 ref를 코드의 허용 대상과 다시 비교한다. 다른 서버·프로젝트나 HTTP, 리다이렉트로 자격 증명을 보내지 않는다.

`backend`에서 실행한다. 출력 폴더는 Git checkout 밖의 새 경로로 지정한다.

```sh
.motion-venv/bin/python scripts/check_asset_pipeline_live.py \
  --project-ref gwimdiwrqfcqulefshoz \
  --env-file .env.supabase \
  --storage-env-file .env.storage \
  --output-dir /tmp/shelter-assets-check-01 \
  --allow-paid-calls \
  --exercise-synthetic-review-apis
```

`psql`이 PATH에 없다면 `--psql /설치경로/psql`, 신뢰할 CA 묶음이 필요하면 `--ca-file /인증서경로`를 지정한다. TLS 검증은 끄지 않는다.

한 번에 특징 분석 1회, PixelLab BASE·IDLE·SIT 3회를 사용한다. WALK·RUN은 서버 하네스가 만든다. 기본 하루 한도도 그대로 적용되므로 잔여량이 부족하면 실패할 수 있다. 처리 결과가 불명확하거나 실패하면 자동 재호출하지 않는다. 단계별 대기 시간은 기본 20분이다.

## 결과와 보존 범위

`report.json`에 통과한 검사, 생성 작업 ID, 프레임 수·파일 해시, 유료 제출 건수와 정리 결과를 남긴다. `input.png`, `base.png`, `rig.json`, 동작별 PNG도 함께 저장한다. 토큰·서버 키·서명 URL은 보고서나 로그에 남기지 않는다.

실패하면 종료 코드 1이다. `cleanupNeedsAttention`이 있으면 보고서의 이번 실행 ID를 기준으로 임시 데이터 정리를 확인한다. 강제 종료나 컴퓨터 종료 때는 `finally`도 실행되지 않을 수 있다.

비용 집계가 초기화되지 않도록 유료 요청 이력과 비공개 검증 자료는 보관한다. DB·Storage 자료를 전부 삭제했다는 의미가 아니다. 검사가 끝난 뒤 기존 서명 URL은 최대 60초의 만료 시각까지 유효할 수 있다.

CI에서는 이 도구의 오프라인 검사만 실행한다. 이미지 누락·정지 화면·잘못된 프레임·외부 주소를 걸러내는지 확인하며, 실제 계정 생성이나 유료 요청은 하지 않는다.

## 2026-09-23 실서버 확인

같은 가상 그림·관찰·생성 작업을 사용해 단계별로 검증했다. 최초 실행에서 실제 로그인, Luna 행동 분류와 중복 방지, 사진 업로드, PixelLab BASE 생성까지 확인했다. 체형 검토 중 발견한 RUN 잘림은 [B-23 / PR #30](https://github.com/HANN-Creator/shelter-connect/pull/30)에서 수정했고, 개발 서버 `c024efe8378c7ecc0604bc83a149bb9343b1a94d`에 배포했다.

목·다리·털색 좌표를 실제 BASE에 맞춰 검토한 뒤 같은 작업을 이어서 실행했다. IDLE 16프레임, WALK 24프레임, RUN 24프레임, SIT 16프레임이 생성됐고 투명 PNG·재생 시간·마지막 자세 유지 규칙을 통과했다. 서버에서 내려받은 WALK·RUN 픽셀은 로컬에서 검토한 보정 결과와 모두 일치했다.

공개 조회 검사에서는 테스트 강아지의 기본 상태 `PAUSED`를 발견해 요청에 `adoptionStatus=AVAILABLE`을 추가했다. 기존 생성 파일을 재사용해 승인 전 404, 승인 후 익명 manifest 조회, 행동 버전과 PNG 해시 일치를 확인했다. 이 재검사에는 유료 생성 요청이 없었다.

총 사용량은 Luna 특징 분석 1회, PixelLab BASE·IDLE·SIT 각각 1회다. WALK·RUN은 서버 하네스로 생성했다. 테스트 계정·소속·사진 허가·공개 상태는 다시 정리했고, 원래 테스트 작업 외의 기존 19개 테이블 기록은 보존했다. 실서비스 사진 사용 허가와 RN 앱에서의 재생 검수는 별도로 진행한다.
