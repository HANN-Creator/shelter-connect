# 브라우저에서 실제 사용자 흐름 확인 · B-34

RN이 준비되기 전에도 작은 웹 화면에서 개발 서버의 연결을 확인할 수 있다. `backend/scripts/browser-flow`가 화면이고, `BrowserFlowCheck`가 로컬 연결과 임시 자료를 관리한다. 가짜 API 응답을 넣지 않는다. 도구는 API JAR에 포함하지 않으며 Render에 배포하지 않는다.

## 실제 실행 결과 · 2026-09-29

- `shelter-connect-dev.onrender.com`의 배포 버전 `9a81436`에서 브라우저 13개 흐름 모두 통과했다.
- 실제 모델 생성 ID가 저장된 완료 답변 1건을 DB에서 확인했다. 낯선 사람에 대한 가상 봄이의 관찰 기록을 설명했고, 다른 상황에서도 항상 같은 반응을 보인다고 단정하지 않았다.
- 화면에서 돌봄 계획을 직접 수정해 저장한 뒤, 저장하지 않은 입력을 덮어쓰고 재조회해 서버의 수정본이 돌아오는 것도 확인했다.
- 서명 URL의 8×8 체크무늬 이미지가 브라우저에 표시됐다. 실제 보호소 사진이나 사진 등록 API를 검증한 결과는 아니다.
- 이번 사진 행·Storage 객체·임시 Auth 계정·개인 기록을 정리했고, 기존 앱 테이블 12개의 건수가 실행 전과 같았다.
- Java 테스트 323개, Python 설정·검증 도구 테스트 35개, 화면 JavaScript 구문 검사와 JAR 빌드가 통과했다.

이후 변경한 POST 쿼리 접미사 차단은 오프라인 보안 테스트로 확인했다. 비용이 드는 동일 AI 흐름은 다시 실행하지 않았다.

## 실행

Java 21과 기존 개발 프로젝트의 `.env.admin-tls`, `.env.storage`가 필요하다. `backend` 폴더에서 아래처럼 실행한다. 포트가 사용 중이면 `--port` 값을 바꾼다. 기존 프로세스를 종료하지 않는다.

```sh
python3 scripts/browser_flow.py \
  --project-ref <개발-프로젝트-ref> \
  --api-origin https://shelter-connect-dev.onrender.com \
  --env-file .env.admin-tls \
  --storage-env-file .env.storage \
  --port 8891 --allow-paid-ai
```

콘솔의 `http://127.0.0.1:8891/`을 열고 준비 완료 후 **전체 흐름 검증하기**를 누른다. 실제 AI 답변을 한 번 요청하므로 호출 비용이 발생할 수 있다. `--allow-paid-ai`를 빼면 AI 호출과 전체 검증은 비활성화되고 조회·저장 버튼만 사용할 수 있다. 도구 전체에서 답변 요청은 최대 3회로 제한한다. 기존 서버의 사용량 한도는 그대로 적용한다.

임시 계정 A/B의 비밀번호는 로컬 프로세스에만 있다. 로그인 버튼은 실제 Supabase 비밀번호 로그인을 수행한 뒤 일반 사용자 토큰을 브라우저 메모리에 넘긴다. 브라우저는 그 토큰을 Authorization에 넣고, 로컬 연결 도구가 선택한 Render 서버로 전달한다. 서비스 사용자 등록은 실제 `POST /v1/me`다. 새로고침하면 브라우저의 로그인 정보는 사라지며 같은 임시 계정으로 다시 로그인할 수 있다.

## 확인하는 13가지 흐름

1. 비로그인 보호 요청 401
2. Supabase 실제 로그인과 일반 사용자 등록
3. 보호소·강아지·행동 설정 조회
4. 대화 전 사진 잠금 403 PHOTO_LOCKED
5. 같은 강아지의 열린 대화방 재사용
6. 메시지 저장·동일 요청 중복 방지·다른 내용 409
7. 기록 기반 답변 생성·저장·화면 표시
8. 대화 후 사진 조회·서명 URL의 이미지 로딩
9. 입양 질문·돌봄 계획·체크 항목 저장과 재조회
10. 오래된 메모 버전의 덮어쓰기 차단
11. 계정 B에서 A의 대화·메모 접근 차단과 별도의 사진 잠금
12. 새 로그인 토큰으로 같은 대화·답변·메모 유지
13. 토큰 없는 보호 요청 401

각 버튼으로 개별 흐름도 확인할 수 있다. 로그아웃 버튼은 브라우저의 토큰·개인 화면을 비우고 실제 401을 확인한다. 응답이 실패하면 중단하며 자동으로 AI를 다시 생성하지 않는다. 요청 기록에는 메서드·경로·HTTP 상태·requestId만 표시한다. 응답 텍스트는 HTML로 실행하지 않는다.

## 자료 범위와 정리

- 기존 가상 봄이와 관찰 기록을 사용한다. 실제 보호소 자료와 프론트 저장소는 바꾸지 않는다.
- 임시 일반 Auth 계정 두 개를 만든다. 보호소 담당자 권한은 부여하지 않는다.
- 직접 만든 8×8 체크무늬 PNG를 임시 Storage 경로에 올리고, 봄이의 테스트 사진 행을 별도로 만든다. 실제 강아지 사진이 아니다. 사진 **조회**를 위한 준비이며 보호소 사진 **등록 API**의 검증을 대신하지 않는다.
- **임시 데이터 정리**를 누르면 정확한 UUID·실행 표식·파일 키로 이번 사진·계정·개인 기록만 정리한다. 기존 12개 앱 테이블의 건수가 복원됐을 때만 완료를 표시한다. AI 사용량 기록은 기존 서버 정책을 따른다.
- 브라우저를 닫아도 30분 뒤 정리를 시도한다. 정상 프로세스 종료에도 정리 훅이 있다. 강제 종료·네트워크 단절에 대비해 Git에서 제외된 `build/login-check-*/created-users.txt`, `browser-photo.txt`에 정확한 복구 대상이 남는다. 넓은 이메일 패턴이나 전체 테이블 삭제를 하지 않는다.
- 완료 후 화면은 조회용으로 잠시 남는다. 새 검증은 도구를 다시 실행한다. 정리 실패 시 `CLEANED`로 표시하지 않는다.

## 적용 범위

이 도구는 루프백 주소에만 열리고 Host·Origin·Fetch-Site·매 실행의 로컬 키를 확인한다. 서버 키·DB 비밀번호·임시 비밀번호를 브라우저에 보내지 않는다. 허용된 사용자 API만 선택한 HTTPS 개발 서버로 보내며 다른 서버·관리 API·실제 계정 토큰은 거절한다. 요청 크기와 응답 크기를 제한하고 외부 리다이렉트를 따라가지 않는다.

브라우저 CORS를 피하기 위한 로컬 연결 도구가 있으므로, **RN 웹의 실제 CORS 설정을 통과했다는 뜻은 아니다.** Supabase SDK 토큰 갱신, 회원가입·메일 확인·소셜 로그인, 실제 RN 조작·화면 이동, 모바일 보안 저장소, 맵 애니메이션 재생은 최종 프론트에서 확인한다. 프론트 화면 없이도 먼저 검증할 수 있는 서버 연결과 오류 처리가 이 작업의 범위다.
