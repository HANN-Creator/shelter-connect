# 32px 스프라이트 자동 검수·보완 (B-43)

생성 완료만으로 품질을 통과시키지 않는다. 새 작업은 `sprite-quality-v1` 정책을 기록하고 기준 이미지 승인 후 각 행동을 **생성 → 픽셀 검사·Luna 시각 검수 → 필요한 시트만 보완 생성 → 재검수**한다. 기존 사진·도트 그림체·32×32 원본 픽셀과 4방향 기준 이미지의 해시는 그대로 유지한다.

## 공통 꼬리 기준

원본 사진을 Luna에 한 번 전달해 `LOW/LEVEL/HIGH/CURLED/UNKNOWN` 중 꼬리 자세를 정하고 `qualityPolicy.contract`에 모델·근거와 함께 저장한다. 이 값은 네 방향 전체가 공유한다. 사진에서 불분명한 꼬리를 추측해 확정하지 않는다. 성격이나 기분을 추론하지 않는다.

LOW는 엉덩이 아래로 늘어진 꼬리이며, 정면에서 몸 뒤에 가려져도 된다. 좌우 흔들림은 화면 축이 아닌 강아지 몸의 좌우축을 기준으로 한다. 옆모습에서는 움직임이 작게 보일 수 있다. 높게 들어 올리거나 위아래로 펌프질하듯 움직여서는 안 된다.

## 검사와 보완

- 9프레임 각각의 투명도·32×32 크기·첫 프레임 기준 이미지 일치 검사.
- 모든 프레임 가장자리의 불투명 픽셀을 검사한다. 경계에 닿으면 보수적으로 `CANVAS_CLIPPING`으로 분류한다. Luna가 통과시켜도 이 검사는 무시하지 않는다.
- Luna에는 네 방향 기준 이미지와 현재 시트 9프레임을 정수 배율로 확대한 검수표를 보낸다. 방향 이탈, 꼬리 높이 모순, 외형 변화, 행동 누락, 큰 위치·크기 변화를 검사한다.
- 문제 있는 행동·방향에만 새 시드를 사용한 수정 요청을 보낸다. 냄새 맡기는 주둥이를 앞으로 뻗지 않고 앞발 사이로, 걷기는 발을 아래 경계 너머로 내리지 않도록, 뒷모습 앉기는 끝까지 얼굴을 숨기도록 지시한다.
- 생성 결과의 픽셀을 흐리게 만들거나, 문제 프레임을 삭제하거나, 임의의 수동 그림으로 바꾸지 않는다. 동일 결과 해시는 기존 검수 결과를 재사용한다.
- 시트당 자동 보완은 최대 2회다. 이는 일일 생성 제한과 별개로 같은 결함을 반복 생성하는 것을 막는 작업별 한도다. 정상 시트는 추가 PixelLab 호출 없이 재사용한다.
- 수정 전 PNG·제공업체 ID·요청 해시·검수 결과를 `attempt_history`에 보존한다. 수정 PNG는 별도 `repair-N` 경로에 저장한다.
- 2회 후에도 문제가 있으면 결과를 보존하고 `REVIEW / QUALITY_REPAIR_EXHAUSTED`로 남긴다. 최종 승인 요청은 `409 QUALITY_REVIEW_REQUIRED`다. AI 검수는 확률적이므로 최종 사람의 품질 확인도 유지한다.

## API

신규 생성 요청의 본문은 동일하다. 방문자 조회는 AI를 실행하지 않는다.

기존 `REVIEW` 상태의 미검수 팩에 적용:

`POST /v1/shelter-admin/dogs/{dogId}/styled-assets/{jobId}/repair`

```json
{
  "note": "저장된 시트를 검사하고 결함이 있는 행동만 자동 보완합니다.",
  "expectedSeedHashes": {"south":"...", "north":"...", "west":"...", "east":"..."}
}
```

같은 보호소의 담당자만 허용하며 사진·파생물·PixelLab 허가를 재확인한다. 동일 요청은 현재 작업을 반환하고 보완 한도를 초기화하지 않는다. 기존 승인 팩을 자동으로 변경하지 않는다. 과거 팩을 일괄 유료 재검수하지 않는다.

관리자 상태 응답은 `qualityPolicy`, 단계별 `qualityReport`, `repairCount`를 추가한다. 미리보기·공개 manifest의 `quality`에는 정책 버전·통과 여부·보완 횟수만 포함한다. 작업 `generationPlan.expectedProviderRequests`는 최초 생성 계획이며 보완 제출 수와 PixelLab Generations는 별도로 집계해야 한다.

## 중단과 재개

Luna 호출 전 시작 표식을, 완료 후 검수 결과와 입력 해시를 DB에 저장한다. 중간에 AI 호출이 끊어지면 임의로 통과시키거나 무한 호출하지 않는다. `FAILED / QUALITY_*` 상태에서 운영자의 기존 `recover {}` 요청으로 재개한다. 이때 기존 PixelLab 완료 응답과 저장 시트를 재사용한다.

PixelLab 접수 여부가 불명확한 `OUTCOME_UNKNOWN`은 기존과 같이 확인된 작업 ID가 필요하다. 품질 실패로 확인된 결과만 자동 재생성하며, 네트워크 오류를 재생성 허가로 간주하지 않는다. 외부 호출은 DB 트랜잭션 밖에서 수행하고 기존 lease·중복 방지·권한 검사를 유지한다.

## DB·설정

V14: `asset_jobs.quality_policy`, `styled_asset_steps.quality_report`, `repair_count` 추가. 단계 상태에 기존 저장물을 검수하는 `CHECKING` 추가. 기존 행의 정책은 NULL이며 명시적 repair 요청 전에는 기존 동작을 유지한다. 기존 RLS와 최소 권한은 그대로 적용된다.

기존 `AI_ENABLED`, `OPENAI_MODEL`(기본 gpt-5.6-luna), `OPENAI_API_KEY`, `ASSET_GENERATION_ENABLED` 설정을 사용한다. 별도의 키나 생성 모델 변경은 없다. 이미지 분석 토큰은 PixelLab Generations와 별도 비용이다.

## 검증

단위·DB 통합 검사: 경계 픽셀이 AI 통과를 덮어쓰는지, 알 수 없는 AI 명령 거절, 네 방향 LOW 꼬리 지시, 결함 시트만 재생성, 정상 시트 원본 재사용, 재생성 예산 소진 후 승인 차단, AI 중단 후 PixelLab 재제출 없이 재개, 반복 요청의 예산 보존, 권한 경계와 기존 팩 호환을 확인한다. 실제 개발 서버의 보완 결과는 실행 보고서와 PR 검증 기록에 따로 기록한다.
