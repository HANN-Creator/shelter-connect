# B-102 사나움과 경고 짖기 행동

- 사용자 요청: 경계·물러나기만으로 사나움을 구분하기 어려우므로 으르렁거리기와 경고 짖기, 말풍선을 추가한다.
- 선행: B101 (`334f2c2`), 기존 사진 기반 4방향 생성과 관찰 근거 기반 행동 선택.
- 브랜치: `backend/b-102-warning-behaviors`.
- 노션: 이 세션에 Notion 연결 도구가 없어 카드 ID·상태는 미동기화. 로컬 기준 및 PR에 범위와 검증을 기록한다.
- 현재 사용자 지시: 미니 PC로 백엔드·DB 이전 준비 중. 배포, 원격 DB 변경, 기존 50마리 배치 재개, 유료 이미지 생성은 수행하지 않는다.

## 완료 기준

1. Luna가 기록에 있는 공격성/으르렁과 경고 짖기를 서로 다른 태그로 선택하고 근거 ID·원문 인용을 반환한다.
2. 기본 IDLE/WALK/SIT 유지. 사나움만으로 짖기나 입질을 임의로 추가하지 않는다.
3. 새 행동의 4방향 생성·저장·경고/학습 기록·재생 명세가 같은 코드를 사용한다.
4. 기존 8종 행동 설정과 진행 중 작업의 품질 규칙·이미지·승인·재시도 횟수를 보존한다.
5. 코드/DB 회귀 검사와 패키징 검증. 실제 그림과 앱 화면 검증은 이전 후 별도 수행한다.

## 행동과 원문 근거

| 관찰 기록 | AI 태그 | 생성 행동 | 말풍선 |
| --- | --- | --- | --- |
| 사나움, 공격적임, 으르렁거림 | AGGRESSIVE | GROWL | 으르렁거리는 중 |
| 사람 접근에 짖음, 경고하며 짖음 | WARNING_BARKER | WARNING_BARK | 경고하며 짖는 중 |
| 소심함, 겁이 많음, 접근을 피함 | 기존 CAUTIOUS | 기존 BACK_OFF | 기존 물러나기 표현 |

품종·사진만으로 성격을 추정하지 않는다. 부정/가정/지시문, 단순 입질, 놀이·반가움의 짖음은 새 태그 근거로 삼지 않도록 Luna 지시를 확장했다. 인용 문자열·관찰 ID는 서버가 검증한다. 의미 분류는 모델 판단이므로 모의 응답 검사만으로 실제 Luna의 분류 정확도를 보장하지 않는다.

두 경고 태그는 따로 선택한다. 공격성만 있으면 GROWL만 추가하고, 짖기 근거가 함께 있을 때 WARNING_BARK를 추가한다. 경고 기록은 FRIENDLY보다 우선해 반김용 TAIL_WAG를 비활성화한다. 별도 SNIFFER 또는 공놀이 근거 없는 반김용 SNIFF도 비활성화한다. 이미 존재하는 산책·휴식 선호 등 다른 근거는 유지한다.

## 생성·재생 계약

- 새 경고 행동을 선택한 계획은 `traits-v3`이고, 기존 행동만 선택한 계획은 `traits-v2`와 같은 중복 방지 키를 유지한다. 기존 `schemaVersion=1`의 추가 행동 키 `GROWL`, `WARNING_BARK`.
- 각 4방향, 원본 입력 포함 9프레임, 제자리 반복 동작. 속도 및 `worldMotion.unitVector`는 0. 기존 눈·외형·기준점·색을 유지하며 실제 공격/물기/돌진은 생성 지시에 넣지 않는다.
- GROWL: 몸을 살짝 앞으로 기울이며 작은 긴장된 턱 동작. WARNING_BARK: 짧은 입 열기/닫기와 머리·가슴 움직임. 후면은 얼굴을 돌리지 않고 어깨 움직임으로 표현한다.
- 신규 동작 지시는 공유 `rules.json`의 `qualityMotion`/`qualityRearMotion`에서 읽는다. 기존 `quality-rules.json` v43 및 해시는 그대로 유지해 기존 서버 작업·학습의 규칙 불일치를 만들지 않는다.
- `generationPlan.expectedProviderRequests`: BASE 1 + 선택 행동 × 4, 13~41회. 청구 Generations와 다른 개념이다.
- 공개/담당자 manifest의 `actionMessages`는 실제 포함된 새 행동의 말풍선만 제공한다.
- `behavior.interactions.PERSON_WARNING`: 근접 사람 대상 제자리 GROWL → BARK(각각 존재할 때) → IDLE. 반응 대기가 끝난 뒤 1.2초/1초, 동작 최대 3초, 종료 후 15초 재사용 대기. 대상이 사라지거나 범위 밖이면 대기 중에도 종료.
- 프론트는 이 반응을 사람 반김/공놀이보다 먼저 평가한다. 경고 두 행동은 일반 배회 무작위 후보에서 제외하고 사람 접근 반응으로 재생한다. 공격적 추적·맵 이동은 하지 않는다.
- 경고 시트가 없는 과거 팩은 해당 반응을 비활성화하고 IDLE을 사용한다. 시트가 없다고 공격성 기록을 없애거나 PERSON_GREETING을 다시 켜지 않는다.
- 이 PR은 서버 계약과 공용 로컬 미리보기 문구를 제공한다. 별도 RN 앱에서 말풍선/상태 머신을 구현·확인한 것은 아니다.

## 저장 호환과 이전

Flyway V25는 `asset_steps`, `styled_asset_steps`, 품질 관찰/학습 scope에 두 코드를 허용하고 행동 계획 상한을 BASE 포함 11종, legacy ordinal을 10, styled ordinal을 40으로 확장한다. V17의 BASE 전용 학습 자료 등록과 해당 자료의 공개 금지 조건은 유지한다. 기존 행·스냅샷·이미지·권한·RLS는 바꾸지 않는다.

기존 8종 설정은 새 두 키를 비활성 값으로 읽는다. 새 두 키의 명시적 null/잘못된 값/이동 속도는 거절한다. 이미 활성화된 새 키를 구버전 편집기가 누락하면 `409 BEHAVIOR_ACTIONS_REQUIRED`로 원래 설정을 보존한다. 읽기와 배포만으로 기존 강아지를 재분류하거나 추가 생성하지 않는다.

새 미니 PC에 적용할 때 V25까지 마이그레이션한 뒤 이 코드로 서버를 시작한다. 기존 실행 중 작업은 저장된 행동 계획으로 재개한다. 새 행동을 기존 강아지에 붙이려면 이전 후 해당 기록을 다시 분석·확인한 새 계획으로 명시 요청해야 한다. 저장된 기존 팩에 새 시트가 저절로 생기는 것은 아니다.

행동 스냅샷(`behavior_plan`) 자체가 없는 구형 전체 팩의 동일 입력 재요청은 기존 작업을 반환하는 비용 보호 규칙을 유지한다. 이 경우 새 행동을 추가하는 재생성 경로는 별도로 정해야 하며, 이 변경으로 기존 팩을 자동 교체하지 않는다.
