## 실제 배포에서 확인한 문제

B-69 배포 뒤 비공개 강아지 하나로 v17을 확인했다. 첫 BASE 생성에서 EAST의 꼬리 문제가 검출돼 서버가 EAST만 자동 편집했다. SOUTH/NORTH/WEST는 PNG 해시까지 보존됐다. 총 PixelLab 제출은 2회이며 사람의 기본 도트 승인은 없었다.

편집 후 일반 외형 검수는 WEST/EAST의 꼬리 자세 불일치를 각각 확신도 0.94로 판단했다. WEST는 작은 수평 돌기, EAST는 위로 올라간 꼬리였다. 별도 꼬리 관찰은 EAST 꼬리가 있다고 답했지만 투명 픽셀을 가로지르는 좌표를 제출했다. v17은 그 좌표 오류로 일반 판단의 확신도까지 0.74로 낮춰 `UNCERTAIN_VERDICT`로 보완을 멈췄다. 실제 가장자리에 닿는 픽셀은 없었는데 첫 판정에 잘림이라는 설명이 섞인 점도 확인했다.

작업 `cfeed2f7-e904-4f72-a5ff-672c9b9b2e4a`는 `SEED_REVIEW`로 비공개 보존했다. 나머지 12개 움직임은 시작하지 않았다. 임시 STAFF 소속·로그인을 제거하고 기존 토큰 차단을 확인했다. 강아지·사진·도트·검수·비용 이력은 남겼다. DB V23과 기존 다른 작업은 변경하지 않았다.

## 변경되는 처리

- 처음 꼬리를 관찰할 때도 실제 투명 여백과 연결 성분 수를 제공한다. 좌표가 투명 픽셀을 가로지르거나, 완전한 연결 이미지인데 잘림·분리라고 판단하거나, 확신도가 낮으면 **동일 이미지로 한 번** 재관찰한다. 재관찰에는 실제 32×32 알파 행과 이전 응답의 검증 결과를 제공한다. 정상 관찰에는 추가 호출이 없다.
- `tailEvidence.observationHistory`에 최초·재관찰 응답과 픽셀 검증을 모두 보존한다. 재관찰 실패는 최초 결과와 고정 실패 코드를 남긴다. 불확실함이 해소되지 않으면 그대로 보류한다. 픽셀을 칠하거나 좌표를 자동으로 가까운 몸 픽셀에 붙여 통과시키지 않는다.
- 좌표 불확실성을 `TAIL_MISSING`으로 바꾸지 않는다. 별도 일반 검수의 확정 결함과 확신도는 유지하고 `repairEvidenceSource`로 출처를 표시한다. 위치만 불확실한 방향은 `deferredDirections`로 남겨 원본을 보존하고, 확인된 다른 방향 결함만 선택 편집할 수 있다. 일반 검수 자체가 불확실한 경우는 기존대로 보류한다.
- 편집 허용과 품질 승인은 다르다. `tailEvidence`가 불확실하거나 해시가 다르면 기본 도트 승인·행동 생성·최종 공개를 허용하지 않는다. 편집 후에는 새 이미지 전체를 다시 검수한다. 확정 결함이 하나도 없으면 좌표 오류만으로 PixelLab 재생성 비용을 쓰지 않는다.
- 최초 생성과 선택 편집 모두 완전한 측면 꼬리와 서로 맞는 꼬리 자세를 명시한다. 승인 그림체, 32px 도트/40px 동작, 통과·유보 방향 원본, 기본 보완3회/동작당3회는 유지한다.

공유 규칙은 `sprite-regressions-2026-10-09-v18`, SHA256 `ce3c0619ae83c9e289ccf6d55b03d1d2a0dd90e334cb24144560c5093d8bf410`이다. API 경로·운영 환경변수·DB 마이그레이션 변경은 없다. 기존 정책 버전 `photo-tail-evidence-v1`과 이미지·사진·규칙 해시 결합을 유지한다. 과거 작업을 새 기준 통과로 간주하거나 보완 예산을 초기화하지 않는다.

## 검증과 한계

[실패 원본·원판정·실제 재관찰](../backend/scripts/fixtures/tail-refinement-v18/README.md)을 회귀 자료로 보존한다. 실제 Luna 재관찰 1회는 EAST의 틀린 좌표를 실제 불투명 픽셀 위의 완전한 경로로 고쳤다. 그러나 확신도는 0.72여서 최종 통과가 아니었다. 최초 검증 도구가 ‘재관찰 뒤 불확실성이 없어야 한다’고 기대한 검사는 실패했고 기록을 보존했다. 검증 기준을 실제 목표인 **좌표 교정 확인 + 낮은 확신도의 승인 차단 + 확정된 별도 결함의 보완 가능**으로 구분하여 같은 저장 응답으로 검증했다. 모델 응답이나 운영 승인 기준 0.75를 바꾸지 않았다.

실제 호출 당시와 최종 코드의 관찰 지침·이미지·알파 검증 방식은 동일하다. 호출 이후 최초 생성/선택 편집의 예방 문구를 보강했으므로 공유 규칙 전체 해시는 다르다. 저장 응답의 당시 해시를 변경하지 않으며 최종 규칙의 새로운 운영 승인 근거로 재사용하지 않는다. 실제 호출 도구 `StyledTailRefinementLiveTest`는 `TAIL_REFINEMENT_LIVE_APPROVED`, `TAIL_REFINEMENT_LIVE_PHOTO`, `TAIL_REFINEMENT_LIVE_OUTPUT`, `OPENAI_API_KEY`를 받는다. 이미 접수한 요청은 입력 결합을 검증하고 재사용하거나 불일치 시 중단한다. 일반 테스트·CI는 유료 호출하지 않는다.

단위 검사는 실제 v17 원판정에서 0.94 결함이 보완 가능해지는지, 좌표 오류만으로는 편집하지 않는지, 한 번만 재관찰하는지, 응답 오류·투명 경로·거짓 잘림·해시 불일치·위조 선택 계획을 차단하는지 확인한다. PostgreSQL 검사는 확정 결함만 선택 편집하고 불확실한 꼬리는 모션 시작과 자동 승인을 계속 막는지 확인한다. Python 생성 규칙·길이와 기존 모션 회귀 검사도 실행한다. 최종 수치와 CI·병합 SHA는 PR 및 노션에 기록한다.

이번 수정은 검수·보완을 잘못 막던 원인을 해결한다. 이 개체의 좌우 꼬리 디자인 자체가 이미 수정 완료됐다는 뜻은 아니다. 새 배포 후 실제 선택 편집→BASE 통과→12모션→최종 승인→프론트 재생은 B-68에서 이어서 확인한다. 10마리 전체·모든 강아지 품질을 검증했다고 보고하지 않는다.
