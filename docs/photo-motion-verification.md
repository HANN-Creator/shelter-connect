# 사진부터 동작 에셋 조회까지 검증

B-26은 RN 화면이 없어도 실제 개발 서버에 사진과 관찰 기록을 넣고, 생성 결과를 앱용 API로 받을 수 있는지 확인하는 작업이다. 결과 PNG를 직접 만들어 넣지 않는다. 사진 등록부터 외형 분석·캐릭터 생성·동작 생성·저장까지 Render 서버가 수행한다.

## 확인하는 흐름

1. 지정된 Supabase 개발 프로젝트와 비공개 버킷, 실행 중인 생성 작업이 없는지 확인한다.
2. 임시 일반 계정에 가상 보호소의 직원 권한을 주고, 비공개 테스트 강아지와 가상 달리기 관찰 기록을 등록한다.
3. AI 행동 초안을 확인하고 승인한다. 선택된 동작은 `IDLE`, `WALK`, `SIT`, `RUN`이어야 한다.
4. 사용 허가를 확인한 사진을 업로드한다. 같은 요청을 다시 보내도 사진·생성 작업이 늘어나지 않아야 한다.
5. 서버의 외형 분석·얼굴 영역·기본 도트와 체형 제안을 내려받는다. 다리 위치, 몸통·머리·꼬리 마스크, 털색 표본을 확인한 뒤 체형 확정 API를 호출한다.
6. 생성된 네 동작을 내려받고 실제로 재생해 본다. 프레임 수·투명 배경·재생 시간·반복 규칙은 코드로 검사하고, 다리 움직임·색·실루엣은 별도로 살펴본다.
7. 검토한 결과만 가상 항목으로 잠시 공개해 앱 조회를 확인한다. 승인 전에는 404, 승인 후에는 같은 행동 버전과 같은 PNG가 반환되어야 한다.
8. 임시 로그인과 공개 접근을 정리한다. 기존 데이터는 바뀌지 않아야 하며 생성 비용 원장과 비공개 감사 기록은 남긴다.

실제 보호소를 등록하거나 크롤링을 시작하는 검사가 아니다. 사진 속 강아지의 실제 성격을 주장하지 않으며, 원본 사진을 GitHub에 올리지 않는다.

## 실행

Pillow·NumPy가 설치된 Python과 `psql`이 필요하다. 키는 기존 로컬 설정 파일에서 읽으며 터미널 인수·보고서·프리뷰에 넣지 않는다. 실행 전 Render의 Live 커밋을 확인하고 `--server-commit`으로 기록한다. 이 인수 자체가 배포 버전을 확인해 주지는 않는다.

```sh
python backend/scripts/check_photo_motion_live.py \
  --project-ref gwimdiwrqfcqulefshoz \
  --server-commit <확인한-Live-커밋> \
  --photo <사용-허가된-1024px-이하-PNG> \
  --env-file <로컬-DB-설정> \
  --storage-env-file <로컬-Storage-설정> \
  --output-dir <Git-밖의-새-폴더> \
  --allow-paid-calls --exercise-temporary-publication
```

한 실행에서 행동 분석·사진 분석과 PixelLab `BASE`·`IDLE`·`SIT` 생성이 발생한다. `WALK`·`RUN`은 서버의 모션 하네스로 만든다. 유료 생성 실패를 자동으로 반복하지 않는다. 새 실행은 새 비용이 발생하므로 기존 보고서를 먼저 확인한다.

## 두 번의 검토

프로그램은 `rig-review-request.json`, `animation-review-request.json`을 차례로 남기고 기다린다. 해당 파일을 복사해 각각 `rig-review.json`, `animation-review.json`으로 작성한다. 기다리는 동안 프로그램을 종료하지 않는다.

- 체형 검토: `rig-proposal.json`과 `base.png`를 보고 `profile`에 확인·수정한 체형을 넣는다. `decision`을 `APPROVE` 또는 `REJECT`로 바꾸고 `note`에 확인 내용을 적는다.
- 동작 검토: `preview/` 폴더를 로컬 HTTP 서버로 열어 네 동작을 확인한다. 같은 방법으로 결정과 검토 내용을 적는다.
- 두 파일의 작업 ID, 단계, 이미지 해시와 체형 버전은 요청 파일과 일치해야 한다. 다른 작업의 승인 파일이나 바뀐 PNG로 진행할 수 없다.
- 검토를 거절하거나 제한 시간 안에 검토하지 않으면 공개하지 않고 임시 데이터를 정리한다. 검사 실패를 품질 통과로 바꾸지 않는다.

검토 파일은 먼저 다른 이름으로 저장한 뒤 이름을 바꾸면 작성 도중 읽히는 일을 피할 수 있다. 토큰은 프로세스 메모리에만 있으므로 프로세스를 재시작해 이어가는 방식은 지원하지 않는다.

`preview/`에는 사진·기본 도트·동작 PNG·재생 정보만 들어간다. 검토용으로 로컬에서 열고, 원본 사진을 공개 배포하지 않는다. `manifest.json`의 URL은 같은 폴더의 파일명으로 바꾼 것으로, 실서버의 만료되는 서명 URL을 복사한 것이 아니다. API 응답과 다운로드 원본의 해시 비교 결과는 `report.json`에서 확인한다.

## 확인 범위

이 검사는 사진 한 장과 가상 행동 기록 한 세트의 실제 연결을 확인한다. 모든 품종·체형, 여덟 동작 전체, 여러 사용자 동시 생성 또는 RN 기기 재생 품질까지 보장하지 않는다. 기본 체형 제안은 외곽 크기에 맞춘 초안이며 관절 자동 인식이 아니다. 체형 검토 단계를 생략하면 새로운 강아지에서 잘못된 다리 위치가 그대로 사용될 수 있다.

체형 초안의 외곽선 표본이 다리 음영을, 발 표본이 어두운 경계를 가리키고 있었다. 귀·꼬리·몸통 마스크와 다리 좌표, 색 표본을 실제 도트에 맞춰 수정한 뒤 **기존 체형 확인 API**로 전달했다. 그림 픽셀을 직접 수정하거나 로컬에서 만든 PNG를 서버 결과로 올리지 않았다.

따라서 이번 결과는 **검토 단계를 포함한 실제 연결 통과**다. 아무 확인 없이 모든 사진이 같은 품질로 완성된다는 뜻은 아니다. 기본 도트의 밝은 가슴 무늬는 원본 사진에서 명확히 확인되지 않으며 걷기·달리기의 발 모양은 공통 하네스의 단순화된 표현이다. 실제 보호소 사용 전 외형 확인과 RN에서 동작을 전환할 때의 자연스러움은 별도로 확인해야 한다.

API·DB·배포 서버 코드는 바꾸지 않았다. 이번 PR은 검증 도구·로컬 프리뷰·기록을 추가하므로 서버 재배포는 필요하지 않다.
