# B97 생성 문구의 원문 범위 보존

브랜치: `backend/b-97-prompt-scope-preservation`. 선행 작업: B96 / PR #108.
노션은 이번 세션에서 연결 도구가 없어 미동기화 상태다.

## 실제 배포 검증에서 확인한 실패

B96 배포 후 검은 강아지 `445468202602743`의 기존 기준 도트를 재검수했다.
품질 규칙 v43으로 원본 해시와 기본 도트 보완 횟수 0을 유지한 채 SYSTEM
승인을 받았다. 앞·뒤 IDLE도 각각 원래 3회 보완 예산 안에서 검수를 통과했다.
두 IDLE의 최종 결과는 검수된 정지 휴식 대체 표현이다.

전체 검증은 왼쪽 IDLE 보완 문구 작성 단계에서
`LESSON_PROMPT_MEANING_LOST`로 실패했다. 12개 동작 중 2개만 통과했고,
전체 팩 승인과 앱 재생은 확인하지 못했다. 테스트용 STAFF 소속·로그인은
해제했고 기존 B87/B90 승인 팩은 변경되지 않았다.

실패한 v4 문구는 세 차례 의미 검사에서 각각 털·발의 완전성, 꼬리 높이
복원, 원문에 없는 `feature placement` 고정을 지적받았다. 모든 초안에
있던 추가 조건이 마지막 검사에서야 검출됐다. 기존 작성 지침의 광범위한
고정 부위 통합과, 누락 복원 중심의 수정 지시 및 구분 없는 피드백 형식이
이를 방지하기에 부족했다. 실패 입력·전체 응답은
`backend/scripts/fixtures/prompt-scope-v5/evidence.json`에 보존한다.

## 변경

`complete-prompt-compact-v5`는 기본 지시와 모든 학습 규칙을 최초 작성과
보완 작성에 동일하게 전달한다. 모습 보존·위치 고정·형태 고정의 범위를
구별하고, 원문의 명시된 부위 목록을 전체 특징 고정으로 확대하지 않는다.

독립 검수 응답에서 누락된 기본 조건, 근거 없는 추가 조건, 충돌 조건을
별도로 기록한다. 추가 판단은 기본 지시뿐 아니라 모든 학습 예방 규칙과
비교한다. 수정 단계는 원문을 기준으로 누락 복원·추가 제거·충돌 해소를
구별한다. 형식 수정이 끼어들어도 의미 수정 피드백을 유지한다.
추가/충돌 목록이 남으면 낙관적인 PASS 필드가 있더라도 제출하지 않는다.
이전 검수 기록의 추가 필드 부재는 호환하되 새 모델 응답에는 필수로 받는다.

첫 실제 v5 검증에서 AI가 `Restore shared tail height` 누락을 통과시킨
사례도 보존한다(`live-false-positive.json`). 기본 지시에서 `Restore ...`
절을 추출해 작성·검수의 필수 원문 구절로 전달하며, 빠졌다면 낙관적 AI
판정을 코드에서 거부한다. 개별 강아지나 방향에 고정된 치환이 아니다.

3회 의미 검수, 1000자 제공자 한도, 모든 활성 규칙 전달, PixelLab 구매 전
검증 및 기록 저장을 유지한다. 범위를 잃은 문구를 무조건 통과시키거나
규칙을 덜 보내는 변경은 없다.

기존 `prompt-resume`에 v4 실패를 추가한다. 실제 실패 지점·기준 도트·품질
규칙·입력 해시가 일치하고 해당 시도의 이미지 구매가 없을 때만 담당자가
v5로 한 번 재개할 수 있다. 승인된 앞·뒤 IDLE, 학습 규칙, 이미지 이력과
보완 횟수 1을 보존한다. 같은 v5 실패를 반복 재개하는 기능은 아니다.

API 형식, DB 마이그레이션, 환경변수와 품질 규칙 v43은 바뀌지 않는다.
품질 규칙 SHA는
`eddc439488293d4286a5bbd56638398154c6df2c13b26711940872afda7093c3`다.
배포만으로 기존 실패 작업을 재개하거나 승인하지 않는다.

## 검증 및 남은 범위

실제 Luna 검증은 최초 작성 990자·실패 문구 수정 989자로 모두 통과했다.
각 경로에서 작성 2회(길이 수정 포함)와 독립 검수 1회, 총 6회 응답을
보존했다. Java 단위 665개(건너뜀 31), PostgreSQL 통합
594개(건너뜀 2)에서 실패·오류 0, bootJar 빌드 성공을 확인했다.
재개 검사는 v4의 왼쪽 실패에서 두 기존 IDLE·5개 학습 규칙·시도 이력을
보존하며, 잘못된 해시·규칙·권한·중복 요청·구매 여부 미확인 사례를 차단했다.
GitHub CI와 병합 SHA는 PR 기록에 남긴다. 문구 검증 성공과 생성 이미지 품질·전체 팩 승인·앱 재생은 별도
결과다. 배포된 v5에서 기존 검은 강아지를 재개해 끝까지 확인해야 한다.
