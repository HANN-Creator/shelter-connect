# 32×32 맵용 도트 · B-38 / B-39

[작업 카드](https://app.notion.com/p/3ee5b2d1a55f80499c12cb1560cb9850)

새 에셋 작업은 64×64 기본 그림과 동작을 만든 뒤, 서버 모션 하네스의 `map_pixels` 단계에서 32×32 PNG도 생성한다. 기존 사진 등록 요청은 그대로다. 별도 이미지 생성 API·키·환경변수·DB 마이그레이션은 추가하지 않는다.

## 생성과 검토

- 원본 시트는 보존하고 `dog-assets/{dogId}/{jobId}/map-32/{base|action}.png`에 변환본을 비공개로 저장한다.
- 해당 강아지 BASE에서 최대 16색을 추출한다. 모든 행동에 같은 팔레트를 사용하며 원본에 없는 색, 다른 강아지의 갈색 등을 주입하지 않는다.
- 고정 2×2 영역에서 불투명 픽셀의 색을 면적 비율대로 평균 낸 뒤 원본 팔레트의 가까운 색으로 맞춘다. 투명 픽셀의 숨은 RGB는 제외한다. 경계 전체에 진한 외곽선을 덧칠하거나 작은 눈 하이라이트를 한 칸 전체로 확대하지 않는다. 디더링·보간·프레임별 확대나 재중앙 정렬은 하지 않는다. 투명도는 0/255다.
- 원본과 도트 버전은 프레임 수, 재생 시간, 반복/마지막 프레임 유지/역순 복귀 규칙이 같다. 기준점만 `(32,60)`에서 `(16,30)`으로 바뀐다.
- 두 버전 모두 기존 보호소 최종 검토를 거친다. 승인 전 공개 API는 404이며 허가 철회 시 함께 차단된다. 자연스러운 움직임·외형은 검토자가 확인한다.
- PixelLab/OpenAI 추가 호출 없이 로컬 연산으로 처리한다. 저장 용량과 서버 연산은 추가된다.

## API · 프론트 연결

`GET /v1/dogs/{dogId}/assets`와 보호소 미리보기의 상위 필드는 기존 64×64 그대로다. 새 응답의 `data.variants.MAP_32`를 맵에서 선택한다.

```javascript
const sprite = manifest.variants?.MAP_32 ?? manifest;
// sprite.frameSize, anchorPixels, animations[action].frames를 함께 사용한다.
// 원본 시트와 32px 좌표를 섞지 않는다.
```

| 항목 | 원본 | `variants.MAP_32` |
| --- | --- | --- |
| frameSize | 64×64 | 32×32 |
| anchorPixels | x=32, y=60 | x=16, y=30 |
| WALK / RUN | 48장, 3072×64 | 48장, 1536×32 |
| BACK_OFF | 24장, 1536×64 | 24장, 768×32 |
| 그 외 동작 | 16장, 1024×64 | 16장, 512×32 |
| 방향 | 오른쪽 3/4 | 오른쪽 3/4 |
| URL 만료 | 상위 expiresAt, 60초 | 동일 |

32px 객체에는 `baseUrl`, `animations`, `availableActions`, `fallbackAction`, `facing`, `generatorVersion=map-pixel-v2` (기존 작업은 `map-pixel-v1`), `sampling=nearest`가 포함된다. `animations`의 frameCount·durationMs·loop·holdLastFrame·returnToIdle은 원본과 같다. 맵 크기와 이동 속도는 프론트가 정한다. 도트 한 칸이 화면의 정수 개 물리 픽셀에 맞도록 확대하고 필터링을 nearest로 설정한다. 32px로 바꿨다는 이유로 강아지의 월드 크기나 이동 속도를 절반으로 줄이지 않는다.

MAP_32가 없는 기존 승인 작업이나 배포 시점에 일부만 변환된 작업은 `variants: {}`를 반환한다. 모든 선택 동작과 BASE의 변환 버전·팔레트 검증이 일치해야 MAP_32를 제공한다. 완성된 v1 작업은 그대로 읽을 수 있다. 배포 중 v1/v2가 섞인 작업이나 알 수 없는 버전은 64px로 돌아가며, 잘못된 v2 표시를 하지 않는다. 부분 시트만 섞어 제공하지 않는다. 기존 작업을 자동으로 재생성하거나 덮어쓰지 않으며, 파이프라인 식별자를 바꾸어 유료 생성이 반복되지 않도록 한다. 기존 작업의 일괄 변환은 이번 범위에 포함하지 않는다. 북쪽·남쪽 방향 생성도 추가하지 않는다.

## 실패와 재시도

정규화한 원본을 저장한 뒤 `asset_steps.result.renderedSource`에 체크포인트를 기록한다. 변환이나 저장이 잠시 실패하면 다음 tick이 이 원본에서 이어간다. 제공자의 결과 유효시간이 지난 경우에도 이미 저장된 원본은 재사용한다.

`MAP_PIXEL_INVALID_INPUT` / `MAP_PIXEL_INVALID_RESULT`는 작업을 FAILED로 두며 운영자 retry 시 원본부터 다시 변환한다. `MAP_PIXEL_UNAVAILABLE`은 지연 재시도한다. 도트 단계 실패로 유료 BASE/동작/외형 분석을 다시 요청하거나 확정한 골격을 초기화하지 않는다. 원본 생성 자체가 실패한 경우의 기존 유료 재시도 정책은 그대로다. 체크포인트와 팔레트 해시는 공개 manifest에 포함하지 않는다.

## 검증

Python 검사는 강아지별 팔레트·투명도·작은 눈 하이라이트의 과장 방지·국소 외곽선 색·입선 명암·다리 사이 투명 영역·정렬·시트 경계·결정적 결과·잘못된 요청을 확인한다. Java/PostgreSQL 검사는 생성→비공개 저장→검토→두 버전 API, 타임라인 일치, 철회, 기존 응답 호환, 저장된 원본 재사용과 유료 요청 횟수를 확인한다. 배포 이미지의 JAR에서 꺼낸 하네스로 3개 로컬 동작과 32px 변환을 실행하는 CI 검사도 포함한다. 실제 사진과 생성 PNG는 공개 Git 저장소에 추가하지 않는다.

## B-39 자동 보정의 범위

[작업 카드](https://app.notion.com/p/3ef5b2d1a55f8051b96cc1e57e0c8f87). `map-pixel-v2`는 사진에서 얼굴 위치를 새로 추론하거나 특정 강아지의 눈 좌표를 덮어쓰지 않는다. 64px 원본의 국소 명암 비율을 보존하는 결정적 변환이다. 원본에 없는 표정·발 모양을 새로 그리지는 않으며, 32px의 작은 세부 손실은 최종 검토 대상이다. 원본 64px와 기존 승인 에셋은 유지한다.

두부 3개 시트(BASE/WALK/RUN, 49프레임)와 갈색 강아지 9개 시트(BASE/8개 행동, 201프레임)를 실제 runner에 입력해 원본/v1/v2를 비교한다. 이 검증은 기존 64px 생성 에셋의 서버 보정 검증이며 새 사진 등록에서 유료 AI를 다시 호출한 검증은 아니다. 이미지 수동 수정 없이 runner의 출력 PNG를 사용한다.
