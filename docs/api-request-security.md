# API 요청 크기·횟수와 오류 로그

B-32부터 개발 서버와 로컬 서버에 같은 기본값을 적용한다. 성공 응답과 로그인 방식은 그대로이며, 제한을 넘긴 요청은 저장·AI·Storage 호출 전에 거절한다.

## 프론트에서 처리할 오류

| HTTP | code | 처리 |
| --- | --- | --- |
| 413 | REQUEST_TOO_LARGE | 본문·metadata·multipart 크기를 줄인다. 같은 내용을 자동 재시도하지 않는다. |
| 413 | PHOTO_TOO_LARGE | 사진을 줄인다. 원본이 작아도 PNG 변환 후 5MiB를 넘을 수 있다. |
| 429 | API_RATE_LIMITED | `Retry-After` 초만큼 기다린다. 저장 요청 재시도에는 기존 중복 방지 ID를 유지한다. |
| 415 | UNSUPPORTED_CONTENT_ENCODING | gzip 등 본문 압축을 끄고 전송한다. |

기존 `code`, `message`, `requestId` 형식과 `X-Request-ID`는 유지한다. 기존 AI 전용 429는 별도 예산 제한이다. Swagger에도 공통 413·429·415와 Retry-After를 표시한다.

## 입력 제한

- multipart를 제외한 요청 본문: **64KiB = 65,536바이트**. Content-Length가 없거나 작게 적혀 있어도 실제 읽은 바이트를 검사한다. 최대 65,537바이트만 메모리에 읽은 다음 JSON 변환에 전달한다.
- 사진 원본과 정규화한 PNG: 각각 **5MiB = 5,242,880바이트**. Supabase dog-photos 버킷의 5MiB 제한과 동일하다. 이미지 크기·종류 검사는 유지한다.
- multipart 전체: **6MiB**, 최대 4개 part. `file` 이외의 metadata 등은 part별 64KiB. 임시 파일은 디스크에 저장하고 컨테이너가 요청 종료 시 정리한다.
- 요청 헤더 전체 16KiB, multipart part 헤더 2KiB. 압축 요청은 지원하지 않는다.
- 로그인 검증·경로 권한 확인을 통과한 뒤 본문을 읽는다. 비로그인 보호 경로는 기존처럼 401이다. 파일 사용 허가와 보호소 소속 검사는 기존 서비스에서 이어서 수행한다.

## 요청 횟수

각 범위의 **최근 60초**를 센다. 적용 경로는 `/v1/**`다.

| 범위 | 기본 한도 | 환경변수 |
| --- | --- | --- |
| 서버 전체, 잘못된 토큰·거절 요청 포함 | 1,200회 | API_GLOBAL_MINUTE_LIMIT |
| 로그인하지 않은 공개 API 전체 | 300회 | API_ANONYMOUS_MINUTE_LIMIT |
| 검증된 로그인 사용자별 전체 | 180회 | API_USER_MINUTE_LIMIT |
| 로그인 사용자별 쓰기(POST/PATCH/PUT/DELETE 등) | 60회 | API_WRITE_MINUTE_LIMIT |

위 범위가 겹치면 모두 적용한다. 전체 한도 검사는 JWT 확인 전, 사용자별 검사는 JWT 및 경로 권한 확인 후 실행한다. 거절된 요청도 전체 한도에는 포함된다. 재시도 대기 시간은 해당 창에서 다시 자리가 나는 초다.

사용자 구분은 검증한 JWT subject만 사용한다. 토큰 갱신이나 X-Forwarded-For 변경으로 한도를 초기화할 수 없다. Render의 프록시 주소를 사용자 IP로 오인하지 않도록 IP별 제한은 두지 않는다. 비로그인 한도는 공개 API 이용자가 함께 사용한다.

카운터는 현재 Render **단일 인스턴스의 메모리**에 있다. 재시작하면 초기화되며, 여러 인스턴스를 운영하게 되면 Redis 등 공유 카운터나 게이트웨이가 필요하다. 사용자 카운터는 최대 4,096개이고, 활성 항목을 임의로 버리지 않는다. 만료된 항목을 정리할 때까지 새 항목을 거절한다. 이는 소규모 개발 서버 보호이며 네트워크 DDoS 방어를 대체하지 않는다.

헬스체크·Swagger 정적 문서는 이 API 한도에서 제외한다. 기존 DB 기반 유료 AI 일일·동시 호출 한도는 재시작해도 유지된다.

## 오류 기록

API 예상 밖 오류에는 서버가 생성한 requestId와 예외 클래스만 남긴다. 예외 본문·cause·stack trace·SQL·요청 본문·Authorization은 남기지 않는다. 컨트롤러 밖 예외도 같은 원칙을 적용한다. Hibernate SQL/bind/SQL 오류 상세와 Spring 요청 상세 로깅도 꺼둔다.

문제 제보에는 발생 시각, 요청 종류, HTTP 상태와 requestId를 사용한다. 운영 중 상세 SQL/본문 로깅을 켜면 이 보호가 사라질 수 있으므로 개인정보를 넣지 않은 로컬 재현으로 확인한다.

## 검증

경계 크기, 길이 없는 chunked JSON·multipart, 큰 metadata, PNG 변환 후 용량 초과, 정상 업로드, 토큰 갱신·위조 프록시 헤더, 동시 요청, 카운터 만료·최대 크기, 비로그인 차단과 오류 로그를 검사한다. 실제 생성 API나 실사진은 테스트에 사용하지 않는다.
