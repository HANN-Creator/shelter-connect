# 보호소·강아지 조회 API · B-03

프론트에서 보호소를 고르고 도트 강아지를 보여줄 때 쓰는 API야. 기존 노션 초안의 `/v1` 경로와 `data`, `nextCursor` 형식을 따라 만들었어. 이 문서는 **구현된 조회 응답 기준**이고, C-03의 공동 검토와 RN 화면 연결은 별도로 확인하면 돼.

## 먼저 호출해보기

로컬 PostgreSQL에 V1과 [샘플 데이터](../backend/sample-data/README.md)를 넣고 [서버](../backend/README.md)를 켜면 돼. 별도 로그인 없이 공개된 정보만 조회할 수 있어.

```sh
curl 'http://127.0.0.1:8080/v1/shelters?limit=20'
curl 'http://127.0.0.1:8080/v1/shelters/02100000-0000-4000-8000-000000000001'
curl 'http://127.0.0.1:8080/v1/shelters/02100000-0000-4000-8000-000000000001/dogs?limit=2'
curl 'http://127.0.0.1:8080/v1/dogs/02200000-0000-4000-8000-000000000001'
```

서버 배포 주소는 아직 없어. Supabase에 샘플이 저장되어 있어도 Spring Boot에서 원격 DB 접속 환경변수를 설정하고 서버를 실행해야 이 API를 호출할 수 있어. RN 웹용 CORS는 프론트 주소를 정한 뒤 추가해.

## 조회 경로

| 요청 | 결과 |
| --- | --- |
| `GET /v1/shelters` | 보호소 목록 |
| `GET /v1/shelters/{shelterId}` | 보호소 상세와 공개 강아지 수 |
| `GET /v1/shelters/{shelterId}/dogs` | 선택한 보호소의 강아지 목록 |
| `GET /v1/dogs/{dogId}` | 사진을 제외한 기본 프로필 |

목록은 `{ "data": [], "nextCursor": null }`, 상세는 `{ "data": { ... } }` 형식이야. ID는 UUID 문자열이고 미확인 값은 `null`로 남겨. 배열은 값이 없으면 `[]`야.

## 공개 조건

- 보호소는 승인 상태가 `APPROVED`이고 공개로 설정된 곳만 나와.
- 강아지는 그 보호소에 속하고, 공개 상태이며 보관 처리되지 않아야 해. `AVAILABLE`, `IN_PROGRESS`만 탐색에 포함해.
- `IN_PROGRESS`는 이미 입양 절차가 진행 중이라는 뜻이야. 화면에서 입양 가능 상태와 구분해줘.
- `ADOPTED`, `PAUSED`, 비공개·보관된 강아지는 목록·상세·강아지 수에서 모두 제외해. 기존 대화에서 입양 후 프로필을 보여주는 규칙은 후속 작업이야.
- 비공개 보호소·강아지의 ID를 직접 요청해도 없는 ID와 같은 404를 반환해.
- 공개 보호소에 보이는 강아지가 없으면 정상 응답인 빈 목록을 내려줘.
- 사진 URL·저장 경로, 원문 관찰 기록·작성자·승인 이력·사용자 정보는 반환하지 않아. 특징은 보호소가 작성한 `traitLabels`와 `introduction`을 사용해.

모든 응답에 `Cache-Control: no-store`를 넣었어. 보호소 공개 여부나 입양 상태가 바뀌면 다음 요청에서 다시 확인해.

## 필터와 페이지 이동

| 쿼리 | 경로 | 규칙 |
| --- | --- | --- |
| `region` | 보호소 목록 | 앞뒤 공백을 뺀 지역명 접두어. 최대 100자. 생략·공백은 전체 |
| `limit` | 두 목록 | 기본 20, 1~50 정수. 빈 값이나 범위를 벗어난 값은 400 |
| `cursor` | 두 목록 | 첫 요청에는 생략. 다음부터 직전 응답의 `nextCursor`를 그대로 전달 |

`region=서울`이면 `서울 은평구`처럼 서울로 시작하는 지역이 나와. `%`, `_` 같은 문자는 검색 기호로 해석하지 않아. 현재 지역은 행정 코드가 아니라 저장된 지역명이고, 거리순 검색은 아직 제공하지 않아. 좌표는 화면 표시용으로 전달해.

정렬은 UUID 오름차순으로 고정했어. 인기순·가까운 순서라는 뜻은 아니야. 서버는 마지막으로 전달한 ID 뒤에서 이어서 조회해. 그 강아지가 이후 비공개가 되어도 다음 페이지를 읽을 수 있어. 여러 요청 전체를 하나의 시점으로 고정하지 않으므로, 조회 도중 등록·공개 상태가 바뀌었다면 첫 페이지를 새로 불러와 최신 목록을 확인해줘.

커서는 클라이언트에서 해석하거나 만들어 쓰지 말고 그대로 전달해. 같은 보호소·같은 지역 필터에서만 사용할 수 있어. 필터나 보호소가 바뀌면 커서를 비워. `limit`은 다음 요청에서 바꿔도 돼. 마지막 페이지와 빈 목록의 `nextCursor`는 `null`이야.

## 응답 예시

### 보호소 목록

샘플의 좌표·이름·동물 정보는 전부 가상이야. 아래는 `region=서울`로 조회한 결과야.

```json
{
  "data": [{
    "id": "02100000-0000-4000-8000-000000000001",
    "name": "온기 보호소 (가상)",
    "region": "서울 은평구",
    "latitude": 37.61,
    "longitude": 126.93,
    "mapKey": "sunny",
    "dogCount": 3
  }],
  "nextCursor": null
}
```

보호소 상세의 `data`에는 위 필드에 `address`, `contactPhone`, `websiteUrl`이 추가돼. 현재 샘플에서는 세 값이 모두 `null`이야. `dogCount`는 실제 보호 중인 전체 마릿수가 아니라 **현재 탐색에 공개된 강아지 수**야. 온기는 3, 다온은 1로 나와.

### 보호소의 강아지 목록

다온 보호소의 응답이야. 해리는 비공개이므로 밤이만 보여.

```json
{
  "data": [{
    "id": "02200000-0000-4000-8000-000000000004",
    "shelterId": "02100000-0000-4000-8000-000000000002",
    "name": "밤이",
    "species": "DOG",
    "adoptionStatus": "AVAILABLE",
    "avatarKey": "bami",
    "traitLabels": ["조용한 쉼터", "나만의 거리"]
  }],
  "nextCursor": null
}
```

`avatarKey`는 이미지 URL이 아니라 앱의 도트 에셋을 고르는 키야. 현재 샘플은 `bomi`, `dubu`, `kongi`, `bami`를 사용해. 매핑되지 않은 키는 기본 도트로 표시해줘. 실제 에셋 준비 여부는 [샘플 안내](../backend/sample-data/README.md)를 참고해.

### 강아지 프로필

```json
{
  "data": {
    "id": "02200000-0000-4000-8000-000000000001",
    "shelterId": "02100000-0000-4000-8000-000000000001",
    "name": "봄이",
    "species": "DOG",
    "sex": "FEMALE",
    "breed": "믹스",
    "birthDate": "2023-01-01",
    "birthDatePrecision": "YEAR",
    "birthDateEstimated": true,
    "weightKg": 6.8,
    "neutered": true,
    "adoptionStatus": "AVAILABLE",
    "avatarKey": "bomi",
    "traitLabels": ["천천히 친해져요", "짧은 공놀이"],
    "introduction": "처음엔 조금 떨어져서 살펴봐. 옆에 앉아 기다려주면 내가 먼저 다가갈게."
  }
}
```

`birthDatePrecision`은 `UNKNOWN / YEAR / MONTH / DAY`야. 봄이의 `2023-01-01`은 저장 기준값이므로 **“2023년생 추정”**이라고 보여줘. 1월 1일이 실제 생일이라는 뜻은 아니야. `birthDate`는 시간대 변환 없이 정밀도에 맞춰 표시하면 돼. 밤이는 생일을 몰라 `birthDate`, `birthDateEstimated`가 `null`이고 정밀도는 `UNKNOWN`이야.

`sex`는 `MALE / FEMALE / UNKNOWN`, `neutered`는 `true / false / null`이야. 모르는 상태를 ‘아니오’로 표시하지 않도록 주의해줘.

## 오류 처리

이 조회 경로에서 처리하는 오류는 아래처럼 내려가. `requestId`는 응답의 `X-Request-ID` 헤더와 같아. 프론트에서 문제가 생기면 이 값을 함께 알려주면 돼.

```json
{
  "code": "RESOURCE_NOT_FOUND",
  "message": "요청한 정보를 찾을 수 없어요.",
  "requestId": "서버가 생성한 UUID"
}
```

| HTTP | code | 프론트 처리 |
| --- | --- | --- |
| 400 | `INVALID_REQUEST` | UUID·limit·region 입력 확인 |
| 400 | `INVALID_CURSOR` | 커서를 비우고 첫 페이지 다시 조회 |
| 404 | `RESOURCE_NOT_FOUND` | 목록을 갱신하고 접근 불가 안내 |
| 500 | `INTERNAL_ERROR` | 잠시 후 재시도. requestId 보관 |

예상하지 못한 DB 오류에서는 SQL·호스트·비밀번호·스택 내용을 응답하지 않아. 다른 미구현 경로나 지원하지 않는 HTTP 메서드는 Spring의 기본 오류 응답을 사용할 수 있어.

## 검증 범위와 다음 연결

HTTP 요청 검사는 UUID·크기·커서·지역 입력, JSON 형태와 오류 응답을 확인해. PostgreSQL 통합 검사는 샘플 기반 필터·페이지 이동, 비공개·보관·입양 상태와 보호소 상태 변경, 사진 제외·미확인 값을 검증해. CI에서는 빌드한 JAR도 띄워 같은 네 경로를 실제 HTTP로 호출해.

DB 구조와 기존 V1은 바꾸지 않았어. B-04의 [인증·보호소 권한](auth-and-permissions.md)을 추가한 뒤에도 이 공개 조회는 로그인 없이 사용할 수 있어. 잘못된 Bearer 토큰을 첨부한 요청은 401이야. C-03의 프론트 응답 검토와 사진·대화·동작 설정·등록 API는 각각의 후속 카드에서 진행해.
