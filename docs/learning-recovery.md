# B-61 실패 학습에서 보완 재개까지

노션: [B-61](https://app.notion.com/p/3f25b2d1a55f80b3a5d0f5809a190509). B-50/B-60 후속이다. 실제 이미지의 최종 통과·게시 확인은 B-60에 남는다.

## 확인된 누락

B-60의 쉬기 3개는 실패 후보 4개가 `WAITING_EVIDENCE`에 머물렀다. 같은 규칙·행동·방향·꼬리 범위의 정상 비교 사례가 없어 활성 규칙과 실제 적용 규칙이 모두 0개였다. 편집 원본이 통과하고 팔레트 복원본이 실패한 경우에도 정상 원본 판정을 학습 자료로 보존하지 않았다. 검증된 규칙이 나중에 생겨도 중단된 작업을 다시 연결하는 처리도 없었다.

## 처리 순서와 한도

1. 편집 원본과 복원본 각각의 판정·해시를 기록한다. 최종 통과는 여전히 두 판정 모두 통과해야 한다. 같은 바이트에 상반된 판정이 나오면 정상 비교 쌍으로 학습하지 않는다.
2. 새 작업의 IDLE이 기존 자동 보완 2회를 소진하면 `styled_learning_recoveries`에 동작별 복구를 1개 등록한다. 기존 작업은 담당자가 아래 API로 해시를 확인해 연결한다.
3. 동일 범위의 허가된 정상 사례가 없다면 해당 방향의 승인 도트를 9프레임 반복한 **학습 전용 정지 참조**를 만든다. Luna의 실제 검수를 통과한 경우만 정상 예시가 된다. 참조는 애니메이션 결과·manifest·승인 이미지에 들어가지 않는다. 실패 이미지와 바이트가 같거나 판정이 충돌하면 자동 학습을 중단한다.
4. 기존 학습기가 실패/정상 예시로 예방 문구를 제안하고 정답을 숨긴 비교 검증을 실행한다. 재현 실패 또는 정상 사례 오탐이면 활성화하지 않는다.
5. 실패 이슈와 일치하는 새 ACTIVE 규칙이 있을 때만 IDLE을 1회 추가 편집한다. 바로 전 생성에서 이미 사용한 후보 해시는 제외한다. 필수 규칙 ID·해시·예방 문구가 실제 요청에 포함되는지 제출 전에 검사하고 같은 규칙을 결과 검수에도 전달한다.
6. 실제 결과가 실패하면 `EXHAUSTED`로 끝난다. 횟수·원본·검수·요청·규칙 이력을 보존하며 자동 승인이나 반복적인 한도 초기화는 하지 않는다.

참조 검수는 복구당 최대 1회다. 검증된 규칙이 없으면 PixelLab 추가 호출은 0회다. 새 규칙이 준비되면 최대 1회이며, 과거 수동 보완 횟수가 3~4회인 작업도 현재 횟수에서 정확히 1만 증가한다. 모델 호출 도중 결과가 불명확해지면 같은 호출을 자동 재전송하지 않는다. 규칙이 늘었다는 사실만으로 새 이미지 품질을 보장하지 않는다.

## API와 상태

`POST /v1/shelter-admin/dogs/{dogId}/styled-assets/{jobId}/learning-repair`

소속 STAFF/MANAGER가 `requestId`, 20자 이상의 `note`, 4방향 `expectedSeedHashes`, 선택한 IDLE의 `expectedSheetHashes`(최대 4개)를 보낸다. 현재 규칙·승인 도트·완료된 REVIEW 작업·실패 시트·기존 횟수 2~4를 확인한다. 같은 requestId/본문은 멱등이고 다른 본문 재사용은 409다. 이미 복구가 등록된 동작을 다시 등록하거나 한도를 초기화할 수 없다.

작업 조회의 `steps[].learningRecovery`는 `state`, `reason`, `requiredLessons`, `referenceReport`를 제공한다. 자동 연결이 없는 기존 작업은 null이다.

| 상태 | 의미 |
| --- | --- |
| WAITING_EVIDENCE | 정상 비교 자료 확보 전 |
| CHECKING_REFERENCE | 학습 전용 참조 검수 중 |
| WAITING_RULE | 정상 자료는 있으나 검증된 새 규칙 대기 |
| QUEUED | 검증된 규칙을 지정한 추가 보완 접수 |
| COMPLETED | 추가 보완 검수 통과; 팩 전체 승인은 별도 |
| EXHAUSTED | 추가 보완도 실패; 자동 반복 없음 |
| NEEDS_REVIEW | 참조 실패·동일 이미지의 상반된 판정 등 |
| FAILED / STALE / DISABLED | 호출 실패·해시/규칙 변경·사진 사용 허가 철회 |

규칙 후보가 없으면 `NO_MATCHING_RULE_CANDIDATE`, 검증 실패·중단이면 `RULE_VALIDATION_FAILED_OR_DISABLED`, 제출 문구에 필수 규칙이 없으면 `LEARNED_RULE_NOT_APPLIED`를 기록한다. 무기한 유료 재시도 대신 대기 사유를 확인할 수 있다.

## DB·배포

V20은 복구 상태·스냅샷·필수 규칙·참조 판정·잠금을 저장하는 테이블을 추가한다. 서버 runtime 역할만 접근하고 anon/authenticated는 접근할 수 없다. 기존 팩·승인 여부·이미지를 마이그레이션에서 변경하지 않는다. 새 환경변수는 없으며 기존 에셋 worker/AI 활성화 설정을 따른다. V20 적용 후 서버를 배포해야 실행된다.

규칙 제안·검증기는 `sprite-lessons-v2`를 기록한다. 특정 이슈의 추가 규칙이 관련 없는 전체 규칙을 반복하지 않았다는 이유로 거절되지 않도록 범위를 명확히 했다. IDLE 학습에도 같은 방향의 기준 도트와 프레임 쌍, 실제 픽셀 측정값을 사용한다. 정답·과거 합격 여부는 비교 검증 입력에 포함하지 않는다.

규칙 파일은 기존 `sprite-regressions-2026-10-07-v12`와 SHA `6bb10fa0ea5462dc9054bc3e40dc6257efd2311c97ab47e65feabc7949eb8935`를 유지한다. 이번 변경은 기존 결함의 학습 연결 수정이며 판정 기준을 완화하지 않는다.

## 검증

`StyledAssetPostgresTest`는 실제 PostgreSQL에서 정상 사례 확보→후보 검증→다음 요청 반영, 원본 통과/복원 실패 분리, 규칙 검증 실패·중단, 출처 철회, 기준 도트 판정/규칙 변경, 중복 요청, 동시 선점, 중단된 검수의 재전송 차단, 추가 보완 실패와 이력 보존을 검사한다. 모의 모델의 통과는 실제 이미지 품질 통과로 해석하지 않는다.

실제 Luna 연결 검사는 `RUN_LEARNING_RECOVERY_LIVE=true`로 `liveLunaRecoversB60EvidenceAndPinsAValidatedRule`만 명시적으로 실행한다. `LEARNING_RECOVERY_FIXTURES`에는 사용자가 승인한 B-60 `job.json`, `directions/`, `sheets/`, `raw-edits/`를 둔다. 기존 `OPENAI_API_KEY`/`OPENAI_MODEL`을 환경으로 전달하고 `LEARNING_RECOVERY_REPORT`에 결과를 저장한다. 데이터베이스는 폐기 가능한 localhost `shelter_test`만 허용하며 PixelLab 및 Storage는 모의 구현이다. 실제 Luna 검수·규칙 제안·비교 검증·요청 반영을 확인하지만 새로운 PixelLab 이미지가 좋아졌다는 증거는 아니다.

## 2026-10-07 실제 Luna 결과

승인된 B-60 정면 IDLE의 실제 원본·4방향 도트·저장 판정을 폐기 가능한 로컬 DB에 재현했다. 첫 연결 검사에서는 참조가 통과했지만 기존 검증기가 부분 규칙에 전체 품질 기준을 요구해 거절했고, 짧은 예방 문구가 잘린 문제도 보존했다. 문장 완결·범위·같은 방향 비교 입력을 수정한 뒤 같은 실제 이미지로 다시 검사했다. 검증 실패를 강제 통과시키거나 판정 기준을 낮추지 않았다.

- 정지 참조: Luna 실제 검수 통과, 원래 실패 애니메이션 보존.
- `IDENTITY_DRIFT` 및 `IDLE_MOTION`: 실제 Luna 제안·정답을 숨긴 정상/실패 비교 검증을 통과해 ACTIVE가 됨.
- 필수 규칙 2개의 ID/후보 해시/예방 문구가 다음 편집 요청에 들어감을 확인.
- 원본 이미지·정상 비교·예방 문구 등 실제 모델 입력을 사용했지만 PixelLab 제출과 Storage는 모의 구현이었다. PixelLab 유료 생성은 0회이며 실제 새 애니메이션 품질·개발 서버 자동 진행·공개 승인은 아직 이 결과에 포함되지 않는다.

실제 후보 해시: IDENTITY_DRIFT `e7740a849abd55fd4ad1359da1505a275de1bdc1758272b648bf0302882f7cc1`, IDLE_MOTION `a081c895b0cafcc1f6834c2082661b9e4d2e64627bacfc89c8f6de3bf8a6ef93`. 이 로컬 검증 후보를 개발 DB의 ACTIVE 규칙으로 임의 복사하지 않는다. 배포 후에는 서버가 자신의 증거·허가·해시를 검증해 생성해야 한다.

로컬 검증: Java 단위 검사 377개 통과(선택 실행 1개 제외), PostgreSQL 통합 검사 374개 통과(실제 모델 선택 실행 2개 제외), Python 파이프라인 83개·모션 26개 통과, bootJar 빌드 통과. V20으로 늘어난 SQL bootstrap의 마이그레이션 수 기대값을 갱신하고 해당 검사도 재실행했다. 실제 Luna 선택 검사는 별도 1개 통과했다. CI와 개발 DB 적용 여부는 PR·노션의 최종 기록을 따른다.
