# B-47 · 서버의 전체 프레임 꼬리 편집 보완

B-46에서 검증한 전체 9프레임 편집을 서버 워커에 연결한다. 사진으로 낮은 꼬리(`LOW`)가 확인된 `TAIL_WAG`가 첫 생성과 한 차례 재생성 뒤에도 불합격이면, 두 번째이자 마지막 보완은 `edit-animation-v2`로 기존 시트 전체를 편집한다. 같은 좁은 기준 프레임에서 재생성만 반복하던 동작을 바꾼다.

## 실행·비용 경계

- 클립당 보완 최대 2회는 유지한다. 마지막 보완에서만 전체 편집 1회를 요청한다. B-46 실측 편집 1회의 사용량은 20 Generations였으며 일반 PixMiniMax 생성과 구분한다.
- `UNKNOWN`·`LEVEL`·`HIGH`·`CURLED`는 LOW 편집 지시를 사용하지 않는다. 사진에 없는 꼬리 자세나 성격을 만들지 않는다.
- 새 작업 정책에 `lowTailRepair=REGENERATE_THEN_EDIT_ONCE`와 규칙 v4 해시를 고정한다. 이전 작업의 권한·소진 횟수·실패 상태를 변경하지 않으며 규칙이 달라진 실행은 명시적인 재검수 대상이다.
- 편집 입력은 해당 작업의 직전 시도 이력에 저장된 시트만 사용한다. 키 범위와 SHA-256을 검증하고 예약·접수 ID·불명확한 접수의 재전송 방지는 기존 경로를 따른다.

## 원본을 숨기지 않는 검사

PixelLab 응답 원본 9프레임을 `raw-edits`에 저장한다. 출력용 시트는 승인 기준 프레임과 팔레트를 복원하되 위치·해상도·알파 실루엣은 재표본화하지 않는다. **편집 원본과 복원 시트를 모두** 검수하고 하나라도 실패하면 승인할 수 없다. 원본 0번이 잘렸는데 승인 기준 이미지로 덮여 문제가 사라지는 경우도 차단한다.

공통 검사에 몸에서 떨어진 픽셀(`DETACHED_PIXELS`)을 추가했다. 가장자리 접촉, 정면 LOW 꼬리의 상부 돌출, Luna의 외형·방향·행동 판정과 함께 검사한다. 원본 해시·검수 결과·이전 시도·제공자 사용량은 보존한다. 저장소 읽기는 AI 검수 시작 기록보다 먼저 수행하여 다운로드 실패를 AI 호출 중단으로 오인하지 않도록 했다.

자동 편집은 B-46의 사람이 검토한 꼬리 마스크 합성과 다르다. 팔레트와 첫 기준 프레임은 보존하지만 나머지 프레임의 몸 픽셀이 완전히 동일함을 보장하지 않는다. 실제 출력의 외형·움직임 검토와 최종 승인 단계가 필요하다. 검사를 통과하기 위해 흐림 처리하거나 프레임을 버리지 않는다.

## 검증과 적용

회귀 검사는 LOW의 두 번째 보완만 편집으로 전환되는지, 원본 실패가 복원 결과의 통과로 가려지지 않는지, UNKNOWN은 편집 호출을 하지 않는지, 재조회가 추가 생성으로 이어지지 않는지를 확인한다. 모의 제공자를 사용한 통합 검사와 실제 새 강아지 생성 검증은 구분해 기록한다.

API 경로와 DB 스키마 변경은 없다. 추가 비밀키·환경변수도 없다. 배포 뒤 새 비공개 강아지로 사진 등록 → 근거 기반 행동 선택 → 4방향 생성 → 저장·검수·재조회 흐름을 확인하고, 승인받은 임시 STAFF 소속과 로그인 계정은 검증 후 해제한다. 사진의 특징이 `온순`뿐인 경우 기본 `IDLE/WALK/SIT`만 선택되는 것이 정상이며 꼬리 흔들기를 억지로 추가하지 않는다.

병합·배포·실제 생성 결과는 PR 기록과 로컬 검증 보고서에 남긴다. 노션 외부 기록은 앞선 승인 검토 거절에 따라 별도 동기화 승인 대기 상태다.
