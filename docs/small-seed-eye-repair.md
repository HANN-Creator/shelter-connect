# B-65 작은 기준 도트 눈 보완

노션: https://app.notion.com/p/3f35b2d1a55f80259740f5e442e89e65

32×32의 검은 강아지는 작은 눈동자가 털에 묻힐 수 있다. 초기 생성과 재생성의 공통 규칙에 작은 채워진 동공, 한 픽셀의 절제된 반사광, 주변 털과의 국소 명암을 명시한다. 흰 눈 테두리·빈 눈구멍·과장된 흰자는 계속 불합격이다. 원본 사진과 승인된 그림체는 바꾸지 않는다.

## 자동 보완 경로

새 작업은 `seedEyeRepair=native-seed-eye-inpaint-v1`을 저장한다. 실제 외형·2px 여백은 통과했지만 앞/옆 눈만 실패하면 Luna가 해당 방향의 눈 위치를 찾는다. 위치는 32px 원본 좌표이고, 눈마다 최대 6×6의 불투명한 머리 내부 영역만 허용한다. 정면은 두 영역, 측면은 한 영역이다. 통과한 방향과 후면은 편집하지 않는다. 불확실하거나 범위를 벗어난 위치는 편집 요청으로 보내지 않는다.

서버는 네 방향을 크기 변경 없이 128×32에 나열하고 PixelLab `inpaint-v3`로 한 번 요청한다. 편집 범위 밖의 보이는 픽셀은 원본과 같아야 하고, 빈 배경에 새 윤곽이 생겨도 거절한다. API가 투명 배경을 단색으로 반환하는 경우에만 원본 투명도를 복원한다. 바뀐 눈 외의 원본 픽셀을 덮어써서 제공자의 다른 결함을 숨기지 않는다. 전체 원본 응답도 보존한다.

편집본은 다시 사진·승인 그림체와 비교하여 네 방향 눈/외형 및 2px 여백을 검사한다. 편집 자체가 승인 사유가 되지 않는다. 기존 최대 두 번의 보완 예산을 사용하며, 요청 해시·접수 ID·원본 해시·눈 위치·변경 픽셀 수를 기록한다. 접수 결과가 불명확하면 재전송하지 않는다.

이전 시도의 보관된 보고서와 원본을 사용하므로 재시작 후 현재 검수 보고서가 교체되어도 편집 종류가 바뀌지 않는다. 명시적 재검수와 기존 승인 에셋은 추가 생성을 하지 않는다. 모든 적용 가능한 학습 규칙은 기존 압축·검증 경로로 최초 생성과 편집 요청에도 포함한다.

## 실제 검증과 한계

- 승인 범위의 오슈 사진·스프라이트를 사용했다. 사진 해시는 `052d6277d92c194dacbb7bf29f0f75c8bf6928b0690361c0584532fb3f43bb49`이다.
- 전체 이미지 편집은 머리 모양/팔레트까지 바뀌어 채택하지 않았다. 프롬프트만 바꾼 신규 생성은 양옆 눈 가독성이 미통과했다. 실패한 실험도 보존한다.
- 사람이 좌표를 지정한 부분 편집 실험과 **Luna가 직접 좌표를 찾은 자동 편집**을 구분한다. 최종 후보는 후자다. PixelLab 한 번의 편집 후 네 방향의 실제 눈·외형 검수와 2px 여백 검사를 통과했다. 눈 영역 안에서 64픽셀이 바뀌었고, 영역 밖의 원본 픽셀과 후면 파일은 보존되었다.
- **원본에 대한 Luna 판정은 일관되지 않았다.** 이전 검수에서는 양옆 눈 실패, 이번 검수에서는 통과했다. 실제 원본 통과 보고서를 지우거나 실패로 바꾸지 않았다. 이번 편집 진입은 사용자의 눈 보완 요청으로 별도 표시했다. 따라서 이번 실검증은 실제 자동 위치 탐색·PixelLab 편집·후속 검수의 증거이며, 해당 호출에서 AI가 먼저 원본 결함을 발견했다는 증거는 아니다. 서버의 실패 감지 후 진입·재시작·중복 방지는 모의 제공자를 쓰는 PostgreSQL 검사로 구분해서 검증한다.
- 검수의 판정 일관성과 다른 강아지에 대한 실제 성공률은 추가 검증이 필요하다. 한 강아지의 통과를 전체 강아지의 품질 보장으로 보지 않는다.

회귀 원본·실험 결과·보고서·원본 제공자 응답·해시는 `backend/scripts/fixtures/small-seed-eyes-v14/`에 있다. 사진 원본이나 비밀 키는 저장소에 포함하지 않는다.

## 연결 영향

공통 규칙은 `sprite-regressions-2026-10-08-v14`이다. 요청/응답 API, 새 환경변수, DB 마이그레이션 추가는 없다. 기존 JSON 정책과 시도 이력을 사용한다. 활성화에는 서버 배포가 필요하며, 이번 작업에서 개발 서버 배포·운영 이미지 교체·공개는 수행하지 않았다. 이전 B-64의 V23 적용 여부와 WALK/SIT 좌우 잘림 네 건은 별도 미완료 범위다.

실제 API 재현은 `StyledSeedEyeRepairLiveTest`에 승인된 입력 폴더와 `SEED_EYE_REPAIR_LIVE=true`를 명시한 경우만 실행된다. 일반 검사와 CI는 비용을 발생시키지 않는다. 실제 요청 폴더를 재사용할 때 요청/규칙/원본 해시가 다르면 중단하고, 접수된 요청은 같은 ID로만 조회한다.
