## 실제 실패

B-90의 강아지 `832fc090-f04a-479a-96b2-753ef872e47d`, 작업 `e1e0b869-8914-4f9e-8865-4e38b6a04f5d`는 v41 배포 후 동일 원본 BASE 검수와 SYSTEM 승인을 통과했다. 첫 IDLE은 학습 규칙 4개가 모두 검증된 952자 문구로 접수됐다. 실제 9프레임은 과도한 움직임으로 두 관찰에서 결함이 확정되어 자동 보완이 예약됐다.

보완의 기본 문구는 907자다. 기존 방식은 이 문구를 고정하고 연결 문구 10자를 뺀 나머지 83자에만 모든 규칙을 담으려 했다. `approved` 조건 누락을 발견한 뒤 다시 작성하다가 `LESSON_PROMPT_INVALID`로 중단됐다. 보완 이미지 접수 전 실패라 추가 PixelLab 비용은 발생하지 않았다. BASE 10 + 첫 IDLE 1 = 11 Generations, 접수 2건이다. `repair_count=1`은 준비된 보완 순번이며 보완 이미지 구매 완료를 뜻하지 않는다.

원본 입력과 저장 판정은 `backend/scripts/fixtures/full-prompt-budget-v2/evidence.json`에 보존한다.

## 변경

`complete-prompt-compact-v2`는 기본 지시·수정 지시·해당 범위의 활성 학습 규칙 전체를 **하나의 설명으로 작성**한다. 기존 설명 뒤에 다시 덧붙이지 않는다. 일반 모션 1,000자, BASE/편집 2,000자 한도 전체를 사용한다. 첫 생성과 일반 보완, 학습 후 보완이 같은 작성기를 사용한다. 적용 규칙 개수 제한은 없다.

별도 AI 호출은 모든 규칙뿐 아니라 원래 기본 지시의 방향·수치·크기·모든 프레임 범위·최종 자세·금지·예외·외형과 그림체를 대조한다. 누락한 기본 조건도 재작성 피드백으로 반환한다. 눈·털·명시된 방향·캔버스 크기의 원문 표지는 코드로도 검사해 AI의 잘못된 통과를 막는다. 새 조건 추가, 의미 누락, 길이 초과는 여전히 이미지 접수 전에 차단한다. 원래 규칙 전부는 후속 이미지 검수에도 그대로 전달한다.

작성은 형식 재시도 최대 3회, 의미 검증·재작성 최대 3차례다. 실패 초안의 실제 길이·본문과 검증 이력을 저장한다. 버전·기본 문구·전체 규칙·한도로 구성한 입력 해시가 바뀌므로 v1 실패/통과 결과를 v2 결과로 오인하지 않는다. 이미지 전송 해시도 검증한 전체 문구와 일치해야 한다.

## 기존 작업의 제한적 재개

`POST /v1/shelter-admin/dogs/{dogId}/styled-assets/{jobId}/prompt-resume`

```json
{
  "requestId": "<새 UUID>",
  "note": "<20~2000자 재개 이유>",
  "label": "idle-south",
  "expectedSeedHashes": {"south":"<sha256>","north":"<sha256>","west":"<sha256>","east":"<sha256>"},
  "expectedRulesSha256": "<현재 공통 규칙 해시>",
  "expectedPromptInputSha256": "<마지막 v1/v2 FAILED 문구 입력 해시>"
}
```

승인된 같은 보호소 담당자만 요청할 수 있다. 기존 원본 이용 허가, 현재 규칙·기본 도트·SYSTEM 승인 근거가 일치해야 한다. `FAILED` 작업의 유일한 실패 동작이 `LESSON_PROMPT_INVALID` 또는 `LESSON_PROMPT_MEANING_LOST`이고 마지막 실패 문구가 v1 또는 v2이며 고정 규칙도 동일한 경우만 허용한다. 현재 시도의 접수 시각·provider ID·결과가 있으면 거부한다. 현재 행에 남은 요청 해시는 완료된 직전 원본 이력의 해시와 같을 때만 허용한다.

재개는 해당 동작을 PENDING으로 바꿀 뿐이다. 기준 도트, 승인, 원본·9프레임 이력, 품질 판정, 학습 규칙, 보완 횟수와 과거 유료 접수는 보존한다. 기존 실패 문구도 남긴다. 같은 requestId의 같은 요청은 멱등 응답하며, 다른 요청 내용이나 같은 동작/작성기 버전의 두 번째 재개는 거부한다. 이후 워커가 새 문구를 독립 검증한 뒤 기존 보완 순서와 예산으로 이어간다. 이 API가 이미지를 승인하거나 검수를 건너뛰지 않는다.

## 적용 경계

- DB V24 유지. 마이그레이션·새 환경변수 없음.
- 이미지 품질 규칙 v41 / SHA `657da19999b7bb49cd099cf759b5d2de6597e3f3d0086185cde9ccd05068a4b0` 유지. 이번 실패는 문구 예산 처리 문제이며 이미지 품질 기준을 바꾸지 않는다.
- 기존 승인 팩과 프론트 소스는 변경하지 않는다.
- 실제 Luna 문구 검사와 로컬/CI 검증은 PR·노션에 기록한다. 문구 통과가 이미지 품질 통과를 뜻하지 않는다.
- 배포 후 같은 B90 작업을 재개해 보완 이미지·12동작·최종 SYSTEM 승인·앱 재생을 이어서 검증한다. 배포 전에는 완료로 보고하지 않는다.

## 실제 Luna 문구 검증 (2026-10-11)

운영과 같은 `gpt-5.6-luna` 작성기·검증기·오케스트레이터로 보존된 첫 생성과 보완 입력을 실행했다. 첫 생성은 918자/4규칙, 보완은 942자/4규칙으로 기본 조건과 모든 규칙의 보존 판정을 통과했다. 보완 초안은 모든 프레임·마지막 프레임의 방향 범위를 충분히 명시하지 못해 독립 검증에서 거절됐고, 자동 재작성 후 통과했다. 최종 구현의 실제 호출은 첫 생성 2회, 보완 4회이며 결과는 `live-text-result.json`에 보존한다.

개발 중의 길이 초과 응답과 눈 조건을 빠뜨린 낙관적 판정도 발견했다. 실패 자료는 로컬 검증 산출물에 남겼고, 눈·털·방향·캔버스 원문 표지 누락 회귀 검사를 추가했다. 현재 승인된 원본이나 이미지 품질 검사를 느슨하게 바꾸지 않는다. 이 확인에서는 PixelLab 이미지를 새로 구매하지 않았다.
