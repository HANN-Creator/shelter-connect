# B-85 확정 결함 보완과 불확실 검수 분리

배포 v36의 `idle-north`에서 두 독립 관찰은 같은 1~7번 프레임의 꼬리·등 무늬 깜빡임을 확인했다. `action`, `identity`, `palette`, `tail`은 모두 FAIL이지만 `idleStillness`만 PASS/FAIL이었다. 전체 판정이 UNCERTAIN이어서 예전에 사용한 미확정 후보 1회 제한에 걸렸고, 원래 보완 예산 3회 중 1회만 쓴 상태로 멈췄다.

## 변경 동작

`StyledConfirmedMotionRepair`가 검수 결과와 별도로 편집 가능한 확정 대상을 계산한다. 유효한 두 관찰이 같은 속성·같은 프레임에 FAIL을 기록하고, 기준 도트에서 이어지는 첫 자세를 둘 다 확인해야 한다. 원본/복원본이 함께 있는 경우 모든 보고서에서 같은 편집 대상이 확인되어야 한다. 다른 속성의 불확실성은 편집 대상으로 추가하지 않는다. 이전에 검증한 꼬리·색 깜빡임 보완 조건은 그대로 유지한다.

같은 원인으로 `walk-south`의 loop FAIL/PASS 후보도 별개의 tail UNCERTAIN/PASS 때문에 막혀 있었다. 미확정 후보는 실제 FAIL 근거가 있는 속성만 편집하고, 근거가 없는 불확실 속성은 프롬프트에 보존 대상으로 명시한다. 모든 속성이 UNKNOWN인 경우에는 편집하지 않으며 후보 1회 제한을 그대로 유지한다. 원본/복원본 중 어느 한쪽에서 해당 속성의 편집 근거가 없으면 선택하지 않는다.

신규 생성 워커, 기존 `motion-candidate-repair` API, PixelLab 편집 문구가 같은 계획을 사용한다. 미확정 후보를 이미 한 번 사용했어도 확인된 결함은 **기존 전체 보완 횟수 안에서만** 수정한다. 확정 계획은 원본 보고서와 함께 `attempt_history.confirmedRepairPlan`에 저장한다. 기존 API 이름·요청/응답 구조·DB 스키마·배포 환경변수는 바뀌지 않는다.

이 계획은 PASS도 학습 정답도 아니다. 기존 UNCERTAIN 기록을 바꾸거나 부정 학습에 넣지 않는다. 편집 결과는 전체 9프레임을 다시 검사하며 모든 필요한 검수가 통과해야 SYSTEM 승인이 가능하다. 순수 불확실성의 후보 한도, 소속·사진 허가, 해시·중복 요청, 예산, 정적 대체안 재편집 금지는 유지한다.

공통 규칙 v37은 첫 생성과 보완 양쪽에 `IDLE`의 꼬리·털 무늬 고정을 명시한다. 실제 9프레임·원본 관찰은 `backend/scripts/fixtures/confirmed-motion-v37`에 보존한다. 회귀 실행에서 규칙 SHA를 현재 것으로 치환하는 것은 저장된 관찰의 코드 재현이며 새로운 AI 검수가 아니다.

## 검증과 남은 범위

- 실제 원본 PNG/각 프레임/두 관찰 해시 보존, 확정 대상 계산, 원본/복원본 충돌·유효하지 않은 응답·오래된 규칙·첫 자세 불확실 차단을 검사한다.
- PostgreSQL 검사에서는 미확정 후보 후 확정 결함 보완, 기존 3회 한도, 새로운 검수 PASS 전 승인 차단, 부정 학습 차단, 선택 재개 때 통과 동작/기준 도트 보존을 확인한다. 이 검사의 제공자 응답은 모의 응답이다.
- 실제 PixelLab 보완은 `StyledConfirmedMotionRepairTest.liveSavedTargetGetsOneEditAndFreshFullReview`를 명시적으로 실행한다. 한 요청의 접수 기록과 결과를 보존하며 접수 불명 상태나 미완료 검수를 재시도해 다른 판정을 얻지 않는다. 기존 관찰로 편집을 요청하고 새로운 결과만 실제 Luna로 검수한다. 원격 DB·공개 상태를 바꾸지 않는다.
- 배포 서버 전체 12모션의 최종 자동 승인과 네이티브 앱 재생은 B-68의 별도 실제 검증으로 남는다. 코드 검사 또는 로컬 한 동작 PASS를 전체 완료로 보고하지 않는다.

## 2026-10-10 실제 검증 결과

저장된 v36 관찰과 원본을 사용하여 생산 코드의 편집 요청·PixelLab 클라이언트·Luna 검수로 로컬에서 검증했다. 두 실제 편집은 모두 꼬리 움직임이 남아 CONFIRMED_DEFECT였다. 원래 1/3회 상태를 기준으로 남은 2회까지만 편집한 뒤 `StyledIdleHold.eligible`이 기존 정적 쉬기 대안을 선택했고, 승인 기준 도트와 동일한 9프레임의 새 검수는 PASS였다. 걷기나 앉기를 정지 이미지로 대체하지 않는다.

실제 원본/결과/관찰/해시는 회귀 자료의 `live-validation`에 보존했다. 이 실행은 원격 DB 작업의 재개가 아니므로 서버의 보완 횟수·승인·공개 상태는 그대로다. 실제 한 동작의 보완/대안 검증과 전체 팩 자동 승인·앱 재생을 구분한다.
