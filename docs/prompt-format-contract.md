## 실제 배포 결과와 실패

B92 배포 후 같은 B90 작업의 정면 IDLE은 전체 문구 984자/4규칙, 9프레임 편집 1012자/4규칙으로 자동 보완·검수를 통과했다. 이어서 후면 IDLE의 첫 생성 875자/2규칙과 1차 자동 편집 1160자/2규칙까지 진행했다. 후면 2차 편집은 이미지 접수 전에 `LESSON_PROMPT_INVALID`로 멈췄다.

원인은 글자 수가 아니었다. 세 초안은 1251, 1226, 1289자로 2000자 이내였으나, 서버가 넣은 findings의 `ACTION_MISSING`·`IDLE_MOTION`을 포함해 밑줄 금지 정규식에 걸렸다. 작성기는 모든 조건을 보존하라는 지시와 식별자를 쓰지 말라는 지시를 함께 받았고, 재시도는 원인을 구분하지 않는 “too long or malformed”였다. 원본 입력·전체 2규칙·초안·해시는 `backend/scripts/fixtures/prompt-format-v3/evidence.json`에 보존한다.

## 변경

- v3 작성기와 독립 검증기는 진단 코드/규칙 ID/해시를 메타데이터로 구분한다. 코드만으로 시각 조건을 대체할 수 없으며 실제 수정 부위·프레임 범위·금지·예외를 명확하게 유지해야 한다.
- 밑줄은 일반 텍스트로 허용한다. 문구는 실행하지 않는다. 단일 문자열, 15자 이상, 공급자 한도, 한 줄, 끝 문장부호, 허용된 ASCII 및 URL 차단 검사는 유지한다. JSON/마크업을 그대로 붙이거나 임의로 잘라 통과시키지 않는다.
- 형식 실패는 길이·응답 구조·앞뒤 공백·미지원 문자 코드·URL·미완성 끝을 구분한다. 다음 작성에 정확한 사유와 원문을 전달하고 최종 실패에도 세 초안/사유를 보존한다. 한도 미초과를 초과로 설명하지 않는다.
- 원본 기본 지시와 적용 가능한 모든 학습 규칙은 그대로 별도 의미 검증한다. 필수 눈·털·방향·캔버스 표지도 유지한다. 최초 생성/보완 공통이며 규칙 개수 제한·이미지 품질 완화가 아니다.
- 버전이 입력 해시에 들어가므로 기존 v1/v2 실패/통과 기록을 새 문구로 오인하지 않는다.

## 기존 작업 재개

`POST /v1/shelter-admin/dogs/{dogId}/styled-assets/{jobId}/prompt-resume`의 요청 형태는 유지하고 알려진 v1/v2 실패만 허용한다. 현재 v3 또는 알 수 없는 버전은 거절한다. 같은 보호소 권한, 이용 허가, SYSTEM BASE 승인, 현재 시드/규칙/마지막 실패 입력 해시, 동일한 학습 규칙, 유일한 실패 단계, 접수/결과 없음 조건은 그대로다.

정면 PASS와 기준 도트, 모든 원본/이전 검수, 과거 v2 재개 기록, `repair_count=2` 및 유료 접수 이력을 보존한다. 해당 실패 단계만 PENDING으로 바꿔 남은 기존 순서를 이어간다. 버전/동작별 재개 중복과 다른 내용의 동일 요청은 계속 차단한다. DB 직접 상태 변경·예산 초기화·승인 우회 없음.

DB V24·품질 규칙 v41(657da19999b7bb49cd099cf759b5d2de6597e3f3d0086185cde9ccd05068a4b0)·환경변수·프론트·기존 승인 팩은 변경하지 않는다.
