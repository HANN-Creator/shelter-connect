# B-51 기준 도트 눈 표현 검사

> 2026-10-08 후속: [B-64 품질·WALK/SIT 학습 복구](motion-learning-quality-repair.md)에 v13/V23과 새 작업 정책을 정리했다. 아래는 해당 카드 당시의 기록이다.

최근 세 강아지의 32px 기준 도트에서 눈이 검은 털에 묻히거나 속이 빈 테두리처럼 보였다. 기존 생성 지시의 “작고 자연스러운 눈”만으로 눈 표현이 유지되지 않았고, 행동 검수는 이미 승인된 기준 도트를 정답으로 사용했다.

## 새 작업의 처리

1. 사진과 기존 승인 스타일을 그대로 사용한다. 공통 `seedEyes` 규칙은 털과 구분되는 작은 채워진 동공, 절제된 반사점, 방향별 위치·크기 일관성을 지정한다. 빈 고리·큰 흰자·화난 실눈은 거절한다.
2. PixelLab이 4방향 기준 도트를 만들면 서버의 `StyledSeedQualityAgent`가 사진·승인 스타일·네 방향 원본을 함께 Luna에 전달한다. 기준 도트는 아직 승인되지 않은 검사 대상임을 명시한다.
3. 정면·좌우의 읽기 쉬운 눈과 스타일, 뒷면의 얼굴 비노출, 사진 외형을 검사한다. 불확실한 응답도 통과시키지 않는다. 방향별 중복/누락과 잘못된 응답은 검사 오류로 중단한다. 가장자리 접촉은 원본 픽셀로 별도 확인한다.
4. 시각 불합격은 기준 도트만 최대2회 다시 생성한다. 각 시도는 기존 `repair_count`/`attempt_history`에 저장하고 사진·그림체·9프레임 규약은 유지한다. 실패한 기준 도트 파일은 덮어쓰지 않는다. 명확한 검사 오류·접수 불명은 자동 재전송하지 않는다.
5. B-63 새 일반 작업은 [검수 근거 확인 후 자동 승인](automatic-quality-approval.md)으로 행동 생성에 진행한다. 이전 작업은 담당자 승인을 유지한다. 2회 보완 후 불합격이면 `SEED_REVIEW`에 머물고 `SEED_QUALITY_REVIEW_REQUIRED`를 반환한다. 승인 API와 행동 작업 선점 양쪽에서 품질 조건을 검사한다.

검사 결과는 `steps[0].qualityReport`로 제공하며 네 방향 파일 해시·규칙 해시와 결합된다. 다른 이미지의 통과 기록으로 승인할 수 없다. 새 작업의 `qualityPolicy.seedQualityVersion`은 `seed-eyes-v1`이다. 기존 승인된 작업은 소급 변경하지 않는다. API 요청 형태·DB 구조는 바뀌지 않는다.

공통 품질 규칙은 `sprite-regressions-2026-10-06-v8`이다. 다른 규칙 해시로 진행 중이던 작업은 기존 정책대로 `QUALITY_RULES_CHANGED`에서 멈춘다. 재검토·새 생성은 별도 명시 절차이며 기존 보완 예산을 초기화하지 않는다.

## 검증 자료와 경계

- `seed-eye-regressions.json`: 최근 실제 실패 도트의 해시와 사람이 확인한 결함 종류. 원본 사진·도트 바이트는 승인된 비공개 로컬 검증 폴더에만 보관한다. 해시 목록 자체를 시각 검출기로 표현하지 않는다.
- 단위 검사(관련 26개 통과; 실제 API 전송 검사는 기본 생략): 정면/좌우의 실패·불확실 응답 차단, 뒷면 얼굴 차단, 외형 실패, 중복 방향, 규칙·이미지 해시 결합, 최대 길이 입력과 보완 요청의 전달.
- PostgreSQL 검사(관련 38개 통과; 기존 실제 API 전송 검사는 기본 생략): 불합격 기준 도트 자동 보완, 과거 결과·영수증 보존, 최대2회 제한, 담당자 승인 우회 차단, 행동 유료 호출 차단, 검사 오류의 무한 재시도 방지, 기존 생성·저장·학습 흐름의 회귀 검사.
- 기존 대화·최소 권한 DB 통합 검사 25개도 통과. 새 검수 모듈을 추가하면서 해당 테스트의 AI 모의 구성도 함께 갱신했다.
- Python 공통 생성·회귀 검사 31개 통과. Java 빌드와 JAR 생성 통과.
- 실제 생성: 승인된 오슈 사진으로 같은 백엔드 payload builder와 PixelLab을 사용해 4방향 기준 도트를 다시 생성했다. 사람 검수에서는 정면과 양옆 눈의 명암 구분이 개선되었다. 원본 32px 픽셀에 사후 눈 그리기나 블러를 적용하지 않았다.
- B-51 배포 후 실제 Luna 검사를 수행했다. 개발 API에서 v7 규칙 해시와 `seed-eyes-v1` 적용을 확인했다. 실제 생성·검수·최대2회 보완은 동작했지만 세 결과 모두 눈 가독성 검사에 실패해 `SEED_QUALITY_REVIEW_REQUIRED`에서 멈췄다. 행동 생성은 시작하지 않았다. 생성 품질 통과로 보고하지 않는다.

CLI는 같은 생성 예방 규칙을 사용하지만 명시적인 사람의 기준 도트 검토가 필요하다. 자동 Luna 검사와 제한된 보완은 서버 워커 경로다.

## B-51A 실제 응답 해석과 기존 도트 재검수

실제 Luna 응답은 뒷모습에 `readability=NOT_VISIBLE`, `style=PASS`를 반환했다. 눈이 없다는 정상 판정과 그림체 통과 판정인데, B-51은 두 값 모두 `NOT_VISIBLE`이어야 한다고 검사해 불필요한 `EYE_DIRECTION`을 추가했다. v8에서는 뒷면의 눈 노출 여부를 `readability`로 확인하고 그림체의 `FAIL`/`UNCERTAIN`도 계속 거부한다. 정면·양옆의 눈 불합격이나 외형 불확실 판정은 그대로 유지한다.

실제 응답과 입력 해시를 `seed-eye-verdict-regressions.json`에 보존했다. 이 재현 검사는 응답 해석을 검사하며 실제 이미지 품질 통과를 뜻하지 않는다.

기존 `POST /v1/shelter-admin/dogs/{dogId}/styled-assets/{jobId}/quality-recheck`는 규칙이 바뀐 `SEED_REVIEW` 작업도 처리한다. 요청에는 기존처럼 `note`, `expectedSeedHashes`, `expectedRulesSha256`을 보낸다.

- 저장된 네 방향의 원본 해시를 검증한 뒤 Luna만 다시 호출한다. PixelLab에 생성·조회 요청을 보내거나 이미지를 바꾸지 않는다.
- 기존 검사 결과를 이력에 보존하고 보완 횟수·유료 요청 이력은 유지한다. 재검수에 실패해도 남은 보완 예산을 자동 소비하지 않는다.
- 이전 수동 정책 작업은 통과해도 `SEED_REVIEW`에서 담당자의 새 승인을 기다린다. B-63 자동 승인 정책 작업은 재검수 근거까지 통과하면 자동으로 이어간다. 불합격이면 승인과 행동 생성이 계속 차단된다.
- 같은 요청의 재전송은 재검수나 생성 비용을 반복 발생시키지 않는다. 권한·이미지·이전 규칙 해시가 다르면 거절한다. 이미 승인되거나 거절된 작업은 변경하지 않는다.
- 완료된 미승인 동작 팩을 재검수할 때도, 눈 검사 정책이 있는 팩은 기준 도트부터 다시 검사하고 새 담당자 승인 뒤 동작 검사를 진행한다.

로컬 검증: 응답 해석 단위 검사, 저장된 도트 재검수의 성공·실패·원본 변조 차단, 보완 횟수·공급자 요청 보존, 기존 동작 재검수 회귀를 확인했다. v8의 개발 서버 배포와 실제 Luna 재검수는 아직 남아 있다. DB 마이그레이션·새 환경변수는 없다.

## 기본 도트 자동 학습 확장

B-52는 이 검수의 실패/정상 결과를 [기본 도트 학습 경로](seed-quality-learning.md)에 연결한다. 정상 학습 예시는 AI 통과뿐 아니라 같은 도트에 대한 담당자 승인이 필요하다. v9부터 활성 규칙을 기본 도트 생성과 눈 검수에 함께 전달하며 DB V16이 필요하다.
