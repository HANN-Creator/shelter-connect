# B-82 쉬기 움직임 관찰 충돌의 정지 대안

실서버 v34의 같은 강아지 IDLE west는 기존 3회 편집 후 `idleStillness`만 FAIL/PASS로 갈렸다. 꼬리 존재·외형·눈·다리·방향·반복과 기준 자세는 두 관찰 모두 PASS였고, 픽셀 잘림·실루엣·분리·하체 이동 검사도 비어 있었다. 이 경우 기존 정지 대체 경로의 확정 실패 조건에 들어가지 못했다. 원본 9프레임, 이전 두 관찰과 결과·해시는 `backend/scripts/fixtures/idle-stillness-v36`에 보존한다.

원래 IDLE 편집 예산을 소진했을 때에 한해, 유일한 `idleStillness` PASS/FAIL 충돌이면 기존 승인 도트의 정확한 40px 여백 이미지로 별도의 `STATIC_IDLE` 9프레임을 만든다. 이전 원본을 자르거나 숨기지 않으며 이전 UNCERTAIN을 PASS/확정 결함으로 바꾸지 않는다. 임의 승인과 부정 학습도 하지 않는다. 기존 정지 대안은 파생 방식·원본 시트 해시·승인 도트 해시·방향을 기록하고 전체 품질 검수를 새로 받는다. 이 새 결과가 실패하면 REVIEW로 남고 추가 편집·반복 대체하지 않는다. 정지 대안에는 눈 깜빡임이나 호흡 애니메이션이 없다.

확인하는 범위는 이전 raw/restored 관찰까지 포함한다. 모든 다른 속성이 PASS, 두 관찰이 유효하고 유일한 불일치가 PASS/FAIL이어야 한다. 픽셀 결함·다른 불확실성·관찰 누락·WALK/SIT·예산이 남거나 초과한 상태·이미 파생된 결과는 이 경로를 사용할 수 없다. 소속 담당자의 기존 재개 API는 원본/정책 해시와 권한 확인을 그대로 유지한다. 새 작업과 재개 작업 모두 공통 규칙 v36 및 같은 워커를 사용한다. 최초 생성·일반 편집은 기존의 고정된 꼬리 IDLE 지침을 그대로 사용한다.

실제 검증: 승인된 west 도트로 만든 동일 9프레임을 생산 코드의 Luna 검수에 한 번 전달해 PASS였다. 이전 원본의 UNCERTAIN은 그대로다. 이는 해당 정지 대안의 품질 결과이며 서버 전체 팩 승인 또는 앱 재생 완료를 뜻하지 않는다. DB 테스트는 정상/실패 새 검수, 원본 및 두 관찰 보존, 한 번만 파생, 추가 PixelLab 호출 없음과 승인/보류 전환을 검사한다. 모의 공급자의 동일 응답 바이트가 기존 판정을 재사용하는 동작도 유지한다.

API·DB V23·운영 환경변수 변경 없음. 정지 대안 전략 버전 `approved-seed-idle-hold-v1`과 기존 보완 예산 유지. 품질 규칙 v36.
