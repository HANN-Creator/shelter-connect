# B-60 · 동작별 검수 입력과 기존 쉬기 보완 경로

브랜치 `backend/b-60-idle-continuation-fallback`. B-59 실제 배포 검증의 후속이다. 노션 쓰기는 앞선 자동 승인 검토 거절로 미동기화이며 로컬 문서와 PR에 기록한다.

## 실제 확인한 문제

동일한 비공개 개발 강아지 `442418202600971`의 저장된 12개 시트를 v11로 재검수했다. 7개 통과, 5개 실패였다. 정면·뒷면 쉬기는 원본/복원본 모두 통과했으나 좌우 쉬기의 내부 다리·명암 움직임이 남았다. 새 비교 화면에서는 앉기 정면·뒷면·왼쪽도 실패했다. 이는 실제 모델 판정이며 모두 오판이라고 확정하지 않는다.

PixelLab 추가 요청은 0회였다. 승인 도트, 108프레임, 편집 원본, 보완 횟수와 이전 실패 이력을 모두 보존했다. 프론트도 정확한 서버 파일에 `서버 7개 통과 · 5개 동작 재검수 대기`를 표시한다. 임시 STAFF 소속과 Auth 로그인은 해제했고 비공개 강아지의 익명 에셋 조회는 404다.

## 변경하는 동작

- 쉬기(IDLE)는 해당 방향 도트와 프레임 0/현재 프레임 쌍을 비교한다. 나머지 동작은 네 방향 도트와 시간순 9프레임을 보여준다. 앉기·눕기의 정상 자세 변화와 한 방향에서 가려진 신체 부위를 판단할 문맥을 보존한다. 원본 픽셀·마지막 프레임과 기존 검사 기준은 유지하며 AI 실패를 자동 통과로 바꾸지 않는다.
- 명시적 추가 보완의 IDLE은 반대편 동작을 복제하지 않고 해당 방향의 승인 도트에서 편집한다. WALK/SIT의 기존 엄격한 좌우 대칭 검사는 유지한다.
- 추가 보완은 작업 전체가 아니라 선택한 동작별로 제한한다. 일반 대상은 실패 판정·현재 규칙·승인 도트·시트 해시가 일치하고 기존 보완 횟수가 2이며 이전 추가 보완 이력이 없어야 한다. 2→3을 기록한다.
- 예외적으로, 과거 추가 보완에서 반대편 복원 방식을 사용한 IDLE이 3회째이고 현재 실패 원인이 `IDLE_MOTION`뿐인 경우 승인 도트 편집을 한 번 허용한다. 3→4를 기록하고 5회째는 허용하지 않는다. 이미 승인 도트 편집을 사용한 3회째 IDLE에는 적용하지 않는다.
- 이전 요청을 `repairContinuationHistory`에 보존한다. 현재·과거 requestId의 같은 본문 재전송은 현재 작업만 반환하며 재생성하지 않는다. 같은 ID에 다른 본문은 409다. 선택하지 않은 동작·기본 도트·인간 승인 기록은 유지한다.

## API·DB

기존 `POST /v1/shelter-admin/dogs/{dogId}/styled-assets/{jobId}/repair-continuation`의 요청 형식은 동일하다. 응답의 `qualityPolicy`에 이전 추가 보완 기록이 추가되며 `qualityReport.reviewLayout`은 행동에 따라 달라진다. STAFF/MANAGER 권한과 사용 허가·검수·공개 경계는 유지한다.

V19는 기존 `repair_count` CHECK에 IDLE의 4회 기록만 허용한다. 기존 값·행·RLS·권한·자동 보완 상한 2는 변경하지 않는다. 서비스는 4회 기록을 위의 해시와 과거 전략 조건으로 제한한다. 새 테이블·환경변수·모델 변경은 없다. 개발 DB 적용과 실제 서버 배포는 PR 기록에 별도로 남긴다.

공통 규칙 v12 / SHA `6bb10fa0ea5462dc9054bc3e40dc6257efd2311c97ab47e65feabc7949eb8935`. 실제 v11 보고서와 원본/복원 PNG를 `backend/scripts/fixtures/paired-review-live.json`에 보존한다. 과거 v10/v11 실패 자료를 덮어쓰지 않는다.

## 검증과 완료 기준

회귀 검사는 실제 12개 시트의 해시·108프레임·실패 판정 보존, 동작별 검수 입력, 프레임 8 전달, 과거/현재 요청 재전송 무과금, 다른 실패 동작의 독립 보완, 3→4 보완 한도, 원본 실패 시 승인 차단, 선택하지 않은 결과와 이력 보존, DB의 IDLE 5회/다른 행동 4회 거부를 다룬다. 모의 생성/검수 응답을 쓰는 서버 통합 검사는 실제 이미지 품질 통과를 의미하지 않는다.

배포 후 같은 저장 이미지를 v12로 한 번 재검수한다. 남은 실패가 적격 IDLE이면 해당 시트만 승인 도트에서 보완하고 원본·복원본을 실제 Luna로 검사한다. 전체 12개 통과, 비공개 팩 검토, 정확한 서버 파일의 프론트/시뮬레이터 연결이 완료 조건이다. 실패가 남으면 기록과 REVIEW 상태를 유지한다. Render UI는 앞선 자동 승인 검토 거절로 사용자 배포가 필요하다.
