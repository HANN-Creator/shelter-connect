# B-86 쉬기·앉기 보완 경로와 걷기 근거 검수

v37 배포의 같은 비공개 강아지는 12개 모션 중 9개만 통과했다. 이 작업은 남은 세 보고서의 서로 다른 원인을 분리한다. 원래 PNG·9프레임·두 AI 관찰은 `backend/scripts/fixtures/motion-repair-v38`에 해시와 함께 보존한다.

## 동작

- **IDLE**: 두 관찰이 같은 프레임의 실제 움직임을 확인하고 기준 자세·외형이 PASS일 때, action 또는 loop의 이견 때문에 정적 대체가 막히지 않는다. 꼬리 판정만 갈리더라도 각 관찰이 이미 움직인다고 지목한 1~8번 프레임에 한정되고 기준 0번 자세는 정상이면, 실패한 움직임과 분리된 정적 후보를 만들 수 있다. 원래 꼬리 판정은 그대로 보류이며 새 정적 그림도 독립 검수를 받아야 한다. 원래 유료 보완 한도 소진 후에만 승인된 같은 방향 도트 9장을 별도 `STATIC_IDLE`로 만들고 새 검수를 받는다. 이전 실패 시트와 보고서는 유지한다. 같은 규칙의 `motion-candidate-repair`에서도 이 무료 전환을 선택할 수 있다. 정적 대체를 다시 편집하거나 WALK/SIT를 정지 이미지로 대체하지 않는다.
- **SIT**: 두 관찰이 0번 프레임의 잘못된 첫 자세를 확인하고 다른 해부학은 정상이라면, 이미 앉아 있는 시트를 다시 편집하지 않는다. 같은 강아지의 승인된 서 있는 이미지를 PixMiniMax의 `first_frame`으로 보내고, 이전 시트의 마지막 앉은 자세를 `last_frame` 제약으로 함께 보내 전환을 다시 생성한다. 끝 이미지도 생성 참조 후보일 뿐 승인된 결과로 간주하지 않는다. 새 결과의 프레임을 사후 교체하지 않고 모두 검사한다. 이 요청도 원래 보완 횟수에 포함하며 `attempt_history.confirmedRepairPlan`에 `CONFIRMED_ENTRY_RESTART`를 기록한다. 새 결과에 다른 결함이 있으면 기존 남은 예산만 사용한다.
- **정면 WALK**: 두 기존 관찰에서 tail/loop만 UNCERTAIN와 PASS이고 다른 속성·픽셀 검사는 모두 정상일 때만 추가 근거 관찰을 한 번 수행한다. 원본 9장과 정적 참조 외에 모든 인접 쌍(0→1 … 8→0)을 전체 캔버스·최근접 확대로 보여준다. 프레임별 꼬리 연결/가림 9개와 전환별 연속성 9개를 모두 확인해야 한다. FAIL이 하나라도 있는 보고서, 둘 다 UNCERTAIN인 속성, 다른 해부학 의심에는 적용하지 않는다. 누락·중복·잘못된 인덱스·실제 결함·판단 불가·타임아웃은 보류를 유지한다. 같은 이미지를 다시 돌려 다수결로 통과시키지 않는다. 별도로, WALK의 8→0 연결에 실제 FAIL 관찰이 있으면 기존 미확정 후보 정책으로 원본 9프레임 전체를 편집한다. 이 후보도 독립 전체 검수를 통과해야 하며, 기존 후보 사용 기록과 원래 유료 보완 한도는 유지한다. 승인 자세의 시작·끝 입력만으로 WALK를 다시 생성하는 실험은 머리 위 돌출물을 만들어 채택하지 않았다.

걷기의 `walkEvidence`에는 모델·규칙·입력 이미지·프레임 해시·18개 근거를 저장한다. 해결되면 원래 보고서를 `beforeWalkEvidence`에 보존한다. 최종 승인에서도 이 연결을 확인한다. 이 선택적 추가 관찰의 실패는 이미 얻은 두 유효 관찰을 버리거나 전체 검수 재시도를 발생시키지 않는다.

## 범위와 경계

공통 규칙 `sprite-regressions-2026-10-11-v38`은 최초 생성과 보완 모두에 서서 시작해 앉는 전환을 요구한다. 기존 그림체, 완전한 꼬리, 고정된 머리·무늬와 전체 9프레임 검사는 유지한다. 원본/복원본이 있다면 두 결과 모두 필요한 검수를 통과해야 한다.

API 요청·DB 스키마·환경변수 추가는 없다. 기존 같은 규칙 선택 재개 API의 무료 IDLE 전환 허용 범위만 늘어난다. v37 작업을 v38로 재개하려면 기존 `motion-repair-resume`의 입력 해시·권한 검사를 사용한다. 기존 유료 예산·통과 이미지·사진 허가·소속·비공개 설정을 바꾸지 않는다. 새 규칙의 전체 검수는 새 결함이나 불확실성을 발견할 수도 있다.

## 검증 방식

- 저장된 실제 관찰의 규칙 SHA를 현재 값으로 바꾸는 회귀 실행은 **분기 조건 재현**이다. 새로운 AI 품질 판정으로 보고하지 않는다.
- 단위 검사: 실제 원본 해시, 독립 관찰·첫 자세 조건, 모든 인접 쌍의 픽셀 보존, 추가 근거 18개 완전성, 타임아웃 후 무재시도, 해시 연결, 결함 차단.
- PostgreSQL 검사: 같은 규칙에서 소진된 IDLE의 새 정적 결과만 검수; 결과 실패 시 승인 차단; SIT의 `first_frame`과 실제 제공자 경로; 원래 예산·실패 기록·통과 동작·소속 권한 보존. 제공자 응답은 모의 응답이며 시각 품질 검증과 구분한다.
- 실제 제공자 실행: `StyledMotionRepairEvidenceLiveTest`를 승인된 같은 이미지에 대해 명시 실행한다. 요청 전 intent와 접수·결과를 보존하여 재실행해도 유료 요청이나 검수를 반복하지 않는다. 새 정적 IDLE, 기존 WALK의 추가 근거, 눈에 보이는 전환 점프를 넣은 음성 샘플, 승인 자세에서의 SIT 생성과 필요시 남은 1회 편집을 검증한다. 원격 DB·공개 상태는 변경하지 않는다.

배포 서버의 전체 12개 모션 자동 승인·저장·네이티브 앱 재생은 B-68의 실제 검증으로 별도 남는다. 로컬 한 동작의 실제 PASS나 모의 DB의 APPROVED를 운영 전체 완료로 보고하지 않는다.
