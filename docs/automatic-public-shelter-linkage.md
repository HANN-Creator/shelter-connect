# B-106 신규 공공 강아지의 보호소 자동 연결

공공 동물 등록은 `POST /v1/shelter-admin/dogs` 한 번으로 실제 보호소 연결까지 수행한다. `publicAnimalId`에 공공 API의 15자리 동물번호를 전달한다. 기존 배치의 `introduction`에 있는 `public animal <15자리>.` 표기도 호환한다. 두 번호가 다르거나 여러 출처 표기가 있으면 등록을 거절한다. 일반 보호소 직접 등록에는 이 필드가 필요하지 않다.

1. 입력과 기존 관리 보호소의 활성 소속을 확인한다.
2. DB 쓰기 트랜잭션 밖에서 고정 공공 API를 조회한다. 이름으로 보호소를 추측하지 않는다.
3. 짧은 트랜잭션에서 소속을 다시 잠금 확인하고 강아지와 실제 보호소 연결을 함께 저장한다. `dogs.shelter_id`는 실제 보호소이고 기존 생성 권한은 `management_shelter_id`로 보존한다.
4. 이후 사진·행동 계획·도트 생성 요청은 기존 경로를 따른다. 새 보호소는 PENDING/비공개다. 등록 자체가 PixelLab을 호출하거나 사진 사용 허가를 추가하지 않는다.

예시(기존 관리 범위에 대한 STAFF 권한 필요):

```json
{
  "shelterId": "02100000-0000-4000-8000-000000000001",
  "publicAnimalId": "442418202601187",
  "name": "공공 API 강아지",
  "avatarKey": "public-dog",
  "isPublic": false
}
```

공공 동물번호는 기존 원본 기록의 unique 제약으로 중복 등록되지 않는다. 성공 응답은 실제 `shelterId`와 최종 `updatedAt`을 반환한다. 원본 상세는 기존 `GET .../public-source`로 확인한다. 별도의 연결 POST는 신규 등록에 필요하지 않다.

## 실패와 생성 대기

- `PUBLIC_SOURCE_NOT_CONFIGURED`(503): 서버의 `DATA_GO_KR_SERVICE_KEY` 미설정.
- `PUBLIC_SOURCE_UNAVAILABLE`(502): 공공 API 오류·미확인 동물·잘못된 원본.
- `PUBLIC_SOURCE_DUPLICATE`(409): 이미 저장된 동물번호.
- `PUBLIC_SOURCE_PRIVATE_REQUIRED`(409): 공공 등록을 공개로 요청함.
- 조회 실패의 코드만 서버 로그에 남기고 인증키 포함 URL·응답은 기록하지 않는다. 강아지·연결 저장 중 실패하면 전체를 롤백한다. 호출자는 실패 원인을 해결한 뒤 등록을 다시 요청한다. 실패한 등록에서 사진 업로드나 유료 생성을 이어가면 안 된다.
- 수동 생성·사진 자동 생성·일반/32px 워커는 동일한 보호소 연결 검사를 사용한다. 공공 동물의 실제 소속이 누락되거나 원본과 불일치하면 생성 요청에 `PUBLIC_SOURCE_LINK_REQUIRED`(409)를 반환한다.
- 과거에 이미 대기열에 있던 미연결 작업은 같은 ID/단계/이미지를 보존하고 `QUEUED / PUBLIC_SOURCE_LINK_REQUIRED`로 대기하며 5분 간격으로 연결을 확인한다. V28은 이 사유로 대기하고 활성 lease가 없는 작업만 연결 보정을 허용한다. 연결 완료 시 즉시 재개 가능하도록 깨운다. RUNNING·OUTCOME_UNKNOWN·그 밖의 QUEUED·활성 lease 작업은 기존대로 소속 변경을 차단한다.

## 검증·운영

PostgreSQL에서 등록→실제 보호소→두 생성 파이프라인 접수, 이전 배치 호환, 동시 중복, 조회/저장 실패의 전체 롤백, 권한 재검사, 대기 작업의 동일 ID 재개를 검사한다. 로컬 전체 검사(일반 707개 중 32개 제외, PostgreSQL 695개 중 2개 제외)와 사진 자동 생성까지 포함한 등록 집중 검사 16개에서 실패·오류가 없었다. 실제 정부 API는 기존 환경변수 키를 사용하며 테스트의 가짜 원본을 운영에 넣지 않는다.

2026-10-20 착수 시 서버는 `PUBLIC_SOURCE_NOT_CONFIGURED`를 반환했다. 미니 PC `runtime.env`에 기존 공공 API 인증키를 추가하도록 요청했으며 키 값은 채팅·PR에 기록하지 않는다. 실제 설정·배포·등록 검증 결과는 PR에서 갱신한다. 노션 도구가 제공되지 않아 외부 카드는 미동기화다.
