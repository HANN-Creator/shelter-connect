# B-64 스프라이트 품질과 걷기·앉기 학습 복구

노션: [B-64](https://app.notion.com/p/3f35b2d1a55f800b9befe8f8a1f21e59). 브랜치 `backend/b-64-motion-learning-repair`.

## 문제와 변경

B-63 실제 오슈 작업은 기본 도트 자동 승인은 완료했지만 동작은 5/12만 통과했다. 좌우 도트에는 여백이 1px뿐이었고 걷기·앉기의 꼬리가 실제로 잘렸다. 알파가 고정된 쉬기를 몸 크기 변화로 판정한 경우도 있었다. 학습 후 추가 편집은 IDLE만 지원했고, 후보 규칙의 정상 예시 오탐은 REJECTED에서 멈췄다.

- **처음부터 여백 확보:** 새 생성 정책에 `seedMotionMargin: 2`를 저장한다. 승인 전 원본을 별도 보존하고, 전체 실루엣이 안전 영역에 들어갈 수 있는 경우에만 픽셀 이동으로 위치를 정렬한다. 확대·축소·흐림·몸 일부 제거 없이 모든 보이는 픽셀을 보존하며 이동량과 원본 해시를 기록한다. 실제 4방향 알파의 상하좌우 여백을 측정하고 부족하면 `SEED_MOTION_MARGIN`으로 기준 도트 단계에서 보완한다. 통과 전에는 동작을 생성하지 않는다. 새 검사 때문에 기존 승인 도트를 임의 축소·재생성하지 않는다. 학습 전용 참조 등록에는 이 생성 정책을 적용하지 않는다. 서버와 CLI는 같은 예방·보완 규칙을 사용한다.
- **쉬기 근거 확인:** 알파가 동일하고 RGB 변화가 1~64/255이며 구조적 실패가 없는 IDLE_MOTION에만 독립 검수를 최대 1회 추가한다. 모든 원본 프레임을 다시 보며 첫 판정과 정답은 숨긴다. 명확한 `SHADING_ONLY`에만 해당 IDLE_MOTION을 정정하고 두 판정을 보존한다. `UNCERTAIN`, 움직이는 내부 특징, 눈·정체성·잘림 등 다른 실패를 강제 통과시키지 않는다. 수치만으로 통과하지 않는다.
- **WALK/SIT 학습 후 재개:** `validated-motion-learning-v2`의 새 작업은 IDLE/WALK/SIT가 일반 보완을 소진한 뒤 동작별 복구를 등록한다. 같은 행동·방향·꼬리·현재 규칙의 새로운 ACTIVE 규칙만 추가 보완을 허용한다. IDLE은 승인 자세 참조를 쓰고, WALK/SIT는 승인된 해당 방향 도트에서 PixMiniMax로 새 9프레임을 만든다. 실제 검증에서 Pro 전체 편집 4개 모두 잘림이 재발해 추가 학습 보완 경로를 전환했다. 실패 원본 9프레임은 모두 이력·학습 근거에 보존한다. 정상적인 걸음·앉는 자세를 정지 그림으로 대체하지 않는다.
- **과거 정상 동작 재활용:** 현재 범위의 정상 사례가 없으면 사용 허가와 승인 도트 해시가 유효한 과거 같은 범위의 정상 원본을 최대 1회 현재 규칙으로 다시 검수한다. 통과한 바이트만 현재 버전의 정상 사례가 된다. 과거 합격 라벨을 그대로 복사하지 않는다. 참조가 없거나 실패하면 `NO_APPROVED_MOTION_REFERENCE`를 남기며 유료 이미지 호출은 하지 않는다.
- **거절된 후보 수정:** `lessonRevision: validated-rule-rewrite-v1`의 새 작업은 정상 사례 오탐·결함 누락·규칙 충돌 피드백을 받아 후보를 최대 2회 다시 작성한다. 매번 정답을 숨긴 별도 재검증을 통과해야 ACTIVE가 된다. 실패 후보·해시·검증 결과·사례 해시는 이벤트에 보존한다. 재검증에는 재작성 피드백이나 정답을 노출하지 않는다.

모든 적용 가능한 ACTIVE 규칙을 최초 생성과 보완 및 검수에 전달하는 B-62 정책은 유지한다. **2회는 후보 재작성의 비용 한도이며 선택할 규칙 수 제한이 아니다.** 이미지 추가 보완은 동작당 1회이고, 과거 횟수·유료 요청·완료 결과를 초기화하지 않는다. 허가 철회·규칙 중단·해시 변경·결과 불명확 상태에서는 임의 재전송하지 않는다. 여전히 실패한 결과는 공개하지 않는다.

## API·DB·배포

기존 `/learning-repair` 요청의 `expectedSheetHashes`는 IDLE/WALK/SIT 합계 최대 12개로 확장한다. IDLE의 기존 보완 횟수 2~4, WALK/SIT 2~3만 접수하며 이후 정확히 1 증가한다. 기존 v1 자동 정책은 IDLE만 처리하고, 기존 작업은 명시적 재검수·복구 요청으로 연결한다. 이미 복구한 동작은 중복 접수할 수 없다.

V23은 WALK/SIT의 최종 학습 보완 횟수 4를 허용하고, 후보 `revision_count`(0~2), `revision_feedback` 및 BASE 여백 이슈를 추가한다. 기존 승인·스프라이트·권한·학습 사례는 변경하지 않는다. 운영자 규칙 조회는 `revisionCount`, `revisionFeedback`과 전체 이벤트를 제공한다. 새 환경변수는 없다.

공통 규칙은 `sprite-regressions-2026-10-08-v13`이다. 기존 ACTIVE 규칙을 새 해시로 임의 복사하지 않는다. 과거 동작 정상 사례는 위의 실제 재검수를 통해서만 새 범위로 들어간다. 서버 배포와 V23 적용 전에는 개발 서버에서 새 경로가 실행됐다고 볼 수 없다.

## 검증 범위

- 회귀 원본: `backend/scripts/fixtures/oshu-motion-learning-v13/`에 오슈 기본 도트 4개와 동작 시트 12개를 원본 해시 그대로 보존한다. 모든 시트는 32×32의 9프레임이다.
- 단위 검사: 실제 원본 여백, 좌우 WALK/SIT의 잘림 차단, IDLE 독립 판정·불확실성·다른 결함 유지, 최대 외형 설명과 보완 문구 길이 검사.
- PostgreSQL: WALK/SIT의 정상 원본·과거 재검수→학습→승인 자세에서 9프레임 재생성, 후보 재작성 성공/소진, 승인 전 여백 차단, 중복·허가 철회·해시·한도·중단 이력과 기존 자동 승인 경계 검사.
- 실제 Luna: 승인된 오슈 원본을 v13으로 재검수. **8/12 통과**(IDLE 네 방향, WALK/SIT 정면·후면). 좌우 WALK/SIT 4개는 실제 잘림으로 미통과. 새 이미지를 만들지 않은 이 검증을 꼬리 복원 완료로 해석하지 않는다.
- 실제 PixelLab 편집 검증은 별도 선택 검사 `StyledMotionLearningLiveTest`로 기록한다. 개발 DB의 기존 작업/공개 결과를 변경하지 않고, 실제 과거 정상 사례의 현재 검수, 실제 후보 제안·재검증, 승인된 오슈 9프레임 편집 및 원본·복원본 검수를 실행한다. 저장·큐·권한 경계는 별도의 실제 PostgreSQL 검사 대상이다.

실제 모델 검사는 `OSHU_MOTION_LIVE`/`OSHU_EDIT_LIVE=true`일 때만 실행하며 build/CI에서는 실행하지 않는다. 기존 `OPENAI_API_KEY`, `PIXELLAB_API_KEY`는 환경으로만 전달한다. 결과 경로는 `OSHU_MOTION_REPORT`, `OSHU_EDIT_REPORT`이고, 실패·완료·유료 접수 ID가 남은 폴더를 재실행해 중복 구매하지 않는다. 테스트 통과와 이미지 품질 통과를 구분한다.

## 실제 외부 생성 결과와 남은 품질 문제

2026-10-08 승인된 오슈 원본과 허가된 과거 정상 WALK/SIT 사례를 사용했다. 과거 정상 영상 4개는 현재 Luna 검수를 통과했고, 각 범위의 후보 4개도 정상/실패 비교와 잘린 프레임 확인을 통과했다. 다음 실제 요청에 그 예방 문구를 포함했다.

| 실제 호출 | 결과 |
| --- | --- |
| 기존 12개 시트 재검수 | 8 통과, 좌우 WALK/SIT 4개 잘림 |
| 검증된 규칙을 넣은 Pro 편집 4회 | 4개 모두 잘림 재발; 원본/팔레트 복원본 차단 |
| 승인 도트와 같은 규칙을 넣은 PixMiniMax 재생성 4회 | 4개 모두 잘림; 공개/DB 결과 교체 없음 |
| 같은 실제 사진으로 새 기준 도트 생성·보완 3회 | 첫 두 번 여백/눈/방향 실패, 마지막은 여백 통과·눈 가독성 실패; 동작 생성/승인 안 함 |

총 PixelLab HTTP 제출은 11회다. 청구상 Generations 수와 동일하다는 뜻은 아니다. 새 도트 시험은 위치 정렬을 추가하기 전 결과이며, 이후 픽셀 손실 없는 정렬과 검사 결합은 별도 단위/DB 검사로 확인했다. 눈 실패를 위치 정렬로 통과시킨 것으로 해석하지 않는다.

실패한 8개 편집/재생성 원본과 실제 판정은 회귀 폴더의 `actual-followup.json`, `edits/`, `regenerated/`에 보존한다. 이 기록은 **품질 완성 증거가 아니라 반복 실패를 재현하는 증거**다. 실제 개발 DB, 기존 공개 결과, 기존 승인 도트를 변경하지 않았다.

따라서 이번 코드는 학습·후보 수정·안전 여백·자동 추가 보완의 누락을 고친다. **오슈 전체 애니메이션 품질 완료는 아직 아니다.** 기존 큰 도트의 좌우 동작 잘림과 새 기준 도트의 눈 가독성은 추가 생성 전략 검증이 필요하며, 이미지 통과나 공개 승인으로 표시하지 않는다. V23 및 코드 배포 확인도 별도 단계다.

## 최종 로컬 검사

- Java 단위 검사: 393개 중 389 통과, 실제 외부 호출 선택 검사 4개 건너뜀. 실패 0. `bootJar` 통과.
- 실제 로컬 PostgreSQL 전체 통합 검사: 414개 중 412 통과, 환경별 조건 검사 2개 건너뜀. 실패 0. V1~V23 및 기존 Supabase 초기 스키마 이어받기 확인.
- Python 전체 scripts 86개, motion-tests 26개 통과. 실제 실패한 추가 생성 8개도 해시·9프레임·잘림 위치를 그대로 재현한다.
- 실제 PixMiniMax 추가 보완 검사는 단독 실행으로 정상 종료했지만, 이미지 판정 4개는 모두 실패다. 편집/새 도트의 외부 호출 증거는 모두 보존했으나 당시 동시 Gradle 보고서 기록이 충돌한 실행은 테스트 성공 건수로 세지 않았다.

위 결과는 개발 서버 배포와 이미지 전체 통과를 뜻하지 않는다. PR·CI와 배포 상태는 작업 카드에 별도로 기록한다.
