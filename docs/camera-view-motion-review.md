# B-81 카메라 시점별 동작 검수

B-80 배포 실검증에서 정면 IDLE은 자동 편집 1회 후 통과했지만, 동일 강아지의 뒤쪽 IDLE 검수가 뒤통수와 말린 꼬리를 눈·얼굴로 오인했다. 실제 9프레임, 네 방향 기준 도트, 두 관찰 원문과 파일 해시를 `backend/scripts/fixtures/rear-motion-v35/`에 보존했다. 이 사실만으로 전체 동작을 정상이라고 승인하지 않는다.

40px 동작 검수는 네 방향의 승인 도트를 별도 정적 `VIEW KEY`로 전달하고, SOUTH=카메라 쪽 정면, NORTH=카메라에서 멀어지는 후면, WEST/EAST=좌/우 측면을 명시한다. 기존 기준/첫 프레임 비교와 실제 프레임 0–8은 그대로 유지한다. 기준 그림을 애니메이션 순서에 섞거나 원본 픽셀을 수정하지 않는다. 첫 관찰과 필요한 독립 관찰은 동일한 시점 정보를 받는다.

후면에서는 원래 가려진 눈·주둥이를 요구하지 않으며 엉덩이의 말린 꼬리를 얼굴로 읽지 않도록 안내한다. 반대로 실제 정면 얼굴이 후면 동작에 나타나면 방향·외형 오류로 계속 차단한다. 시점 명칭은 요구 조건이며 실제 그림이 올바르다는 증거가 아니다. 미관 경고·명확한 결함·불확실성 정책, 검수 횟수, 보완 예산, 자동 승인 조건은 바꾸지 않는다. 눈/얼굴 관련 판정을 일괄 PASS로 치환하는 코드도 없다.

공유 규칙의 `rearView`는 CLI와 서버의 최초 생성·기존 편집 경로에 사용한다. Java 복구 편집에도 같은 후면 조건을 연결한다. 32px 기존 검수에도 동일한 시점 정의를 전달한다. 규칙 v35, DB V23, API와 환경변수 변경 없음. 기존 v34 작업은 현재 서버에서 계속 처리하며 새 규칙 배포 전 결과를 덮어쓰지 않는다.

검증은 실제 실패 자료의 해시, 모든 원본 픽셀의 검수 이미지 보존, 두 관찰의 동일 입력, 잘못된 방향/불확실성의 차단 및 생성·편집 프롬프트 길이를 확인한다. 실제 Luna 대조 검사는 후면, 정면, 정면 그림을 후면으로 요구한 음성 사례를 각각 한 번의 검수 흐름으로 실행하고 결과를 보존한다. 모의 검사 통과와 실제 품질 결과를 구분한다. 실서버 전체 팩의 최종 SYSTEM 승인과 앱 재생은 별도 실검증 결과로 기록한다.

## 실제 대조 결과

같은 후면 원본을 두 관찰 모두 눈·얼굴이 없는 정상 후면으로 읽었다. 다만 내부 무늬 변화 및 IDLE 해석 차이로 전체 결과는 UNCERTAIN이며 자동 승인되지 않았다. 기존 보수적 대안 편집 계획의 대상이 될 수 있음도 확인했으나, 실제 새 보완 이미지는 아직 생성하지 않았다. 정면 대조는 PASS, 동일 정면 그림을 NORTH로 요구한 음성 사례는 DIRECTION_DRIFT를 포함한 CONFIRMED_DEFECT였다. 원문은 fixture의 `actual-reviews/`에 보존했다. 단순 방향 라벨로 판정을 통과시키지 않음을 실제 호출로 확인했다.
