# 기본 도트·최종 팩 자동 품질 승인 (B-63)

> 2026-10-08 후속: [B-64 품질·WALK/SIT 학습 복구](motion-learning-quality-repair.md)에 v13/V23과 새 작업 정책을 정리했다. 아래는 해당 카드 당시의 기록이다.

새 32px 일반 작업은 사람의 `seed-review`와 최종 `review` 호출을 기다리지 않는다. 허가된 사진과 특징으로 요청한 뒤, 기본 도트 검수가 통과하면 행동 생성으로 진행하고 모든 선택 행동·4방향이 통과하면 `APPROVED`로 저장한다. 수천 마리마다 품질 승인 버튼을 누르는 병목을 없앤다.

## 상태와 판단 근거

`qualityPolicy.automaticApproval=quality-auto-approval-v1`은 **새 일반 작업에만** 저장한다. 기존 요청의 재전송은 같은 작업을 반환하며, 과거 대기·거절·승인 작업을 일괄 전환하지 않는다. 학습 자료 등록(`referenceOnly`)은 이 정책을 받지 않는다.

| 단계 | 통과 | 실패·불확실·근거 불충분 |
| --- | --- | --- |
| 기본 도트 4방향 | `seedReview.actor=SYSTEM` 기록 → `QUEUED` → 행동 생성 | 기존 최대 2회 보완 후 `SEED_REVIEW`; 행동 생성 중단 |
| 모든 선택 행동·4방향 | `qualityApproval.actor=SYSTEM` 기록 → `APPROVED` | 기존 보완 후 `REVIEW`; 공개 차단 |
| 공급자·저장·검수 호출 오류 | 기존 복구 절차 | `FAILED` 또는 `OUTCOME_UNKNOWN`; 성공으로 취급하지 않음 |

자동 승인은 별도의 모델 추측이 아니라 저장된 검수 결과에 대한 결정적 검사다. 기본 도트는 실제 원본 사진 해시, 네 방향 이미지 해시, 최신 규칙, 얼굴 가독성·스타일·정체성, 검수 모델·시간, 적용 학습 규칙 전체를 확인한다. 최종 팩은 정확한 actionPlan의 모든 시트가 존재해야 하며, 각 시트의 해시·행동·방향·기준 도트 해시·최신 규칙과 검수 결과가 일치해야 한다. 원본 편집본과 복원본이 있으면 둘 다 통과해야 한다. 누락·오래된 결과·중단된 규칙·잘림 등은 통과로 바꾸지 않는다.

실패 코드 `AUTO_APPROVAL_EVIDENCE_REQUIRED`는 검수 근거가 빠졌거나 현재 이미지와 맞지 않아 자동 승인할 수 없다는 뜻이다. 일반 품질 실패는 기존 `SEED_QUALITY_REVIEW_REQUIRED` / `QUALITY_REPAIR_EXHAUSTED`를 유지한다. 담당자는 예외를 조회·재검수·거절할 수 있으며 정상 작업에서는 승인 요청을 보낼 필요가 없다. 기존 수동 API는 과거 작업과 예외 처리 호환용으로 유지한다.

## DB·조회

V22는 `asset_jobs.quality_approval` JSON을 추가한다. 자동 최종 승인에는 버전·SYSTEM 주체·결정·단계·시간·작업 ID·규칙 해시·actionPlan·기본 승인 및 단계별 결과/검수 해시와 모델·시간을 기록한다. `reviewed_by`에는 가짜 사용자 ID를 넣지 않으며 자동 승인에서는 NULL, `reviewed_at`에는 처리 시간을 기록한다. 기존 수동 승인 제약에 범위가 명확한 기계 승인 근거 경로를 추가한다. 근거 없는 `APPROVED`, 다른 파이프라인의 자동 승인, 학습 전용 팩 공개는 허용하지 않는다.

담당자 작업 조회 응답에 `qualityApproval`이 추가되며 승인 전/기존 수동 작업은 null이다. 공개 에셋 응답 형식과 생성 없는 조회·재사용은 유지한다. 자동 승인 자체가 사진 허가, 강아지/보호소의 `is_public`, 보호소 승인 상태를 바꾸지는 않는다. 따라서 비공개 강아지의 결과는 자동 품질 승인이 끝나도 방문자에게 보이지 않는다.

기본 도트의 자동 승인은 정상 학습 예시의 해시 일치 조건에도 사용된다. 이는 **AI 검수와 픽셀 검사를 통과한 예시**이며 사람이 검토했다고 기록하지 않는다. 이후 후보 규칙의 별도 검증과 원본 사진 권한 확인은 유지한다.

## 검증과 남은 범위

PostgreSQL 통합 검사는 승인 API를 한 번도 호출하지 않는 생성→기본 자동 승인→최종 자동 승인→공개 조회→재조회 흐름, 실패/불확실 결과 차단, 재검수 통과 후 자동 완료, 원본 권한 철회, 비공개 조건, 변조·누락·오래된 근거, DB 제약과 중복 실행을 검증한다. PixelLab·Storage·검수 모델은 이 검사에서 모의 서비스다. 실제 새 강아지의 시각적 품질 통과로 보고하지 않는다.

이 작업은 **기본/최종 품질 승인 자동화**다. 공공 API의 전체 동물 수집·일괄 생성 예약, 입력 특징/행동 초안 확인, 모든 종류의 장애 무인 복구까지 구현했다는 뜻은 아니다. 일반 이미지 보완 최대 2회, 그 이후 학습 기반 자동 보완이 현재 IDLE에 한정되는 점, 실패한 규칙 후보의 자동 재작성 및 중단된 프롬프트 간결화 재개가 별도 과제인 점은 바뀌지 않는다. 최신 서버 배포 및 실제 PixelLab 전체 경로는 배포 후 검증해야 한다.
