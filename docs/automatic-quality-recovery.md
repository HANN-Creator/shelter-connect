# B-67 · 사진 기반 자동 보완 운영 이식

로컬 10마리 시험에서 기본 도트 1마리와 걷기 2방향을 자동 보완해 10마리 모두 선택된 검수를 통과한 흐름을 기존 Spring worker/DB/Storage에 연결한다. 승인된 `cozy32-photo-style-v1` 그림체를 유지한다. B-66의 거절된 평면 그림체는 포함하지 않는다.

작업 카드: https://app.notion.com/p/3f45b2d1a55f8074ae07c528794d2fec

## 새 작업의 처리

1. 실제 사진과 승인 스타일로 32×32 네 방향을 만든다. Luna가 눈뿐 아니라 털색·큰 무늬·귀·방향·꼬리·그림체를 함께 검수한다. 실제 사진·얼굴·스타일과 각 방향 도트를 별도 이미지로 비교해 작은 눈·흰 무늬가 합쳐 보이지 않게 한다. 방향별 필수 항목을 구조화해 확인하고 원본 픽셀로 가장자리도 검사한다.
2. 실패하면 같은 네 방향을 `edit-images-v2 / edit_with_text`로 수정한다. Luna의 사진 기반 보완 설명은 데이터이며 실행 명령이 아니다. 사진을 스타일 전이 참조로 사용하지 않는다. 수정 뒤 다시 검수한다.
3. 기본 도트가 통과하면 픽셀을 그대로 (4,4)에 옮겨 40×40 투명 캔버스에 넣는다. 크기 변경·필터·잘라내기는 없다.
4. 선택된 행동을 PixMiniMax로 만들고 9프레임 모두를 검수한다. 걷기는 단순 색상 변화만으로 통과하지 않는다. 정면에서 가려진 꼬리를 머리 위에 만드는 결함은 사진의 꼬리 자세가 HIGH/UNKNOWN이어도 검사한다. AI가 통과해도 정면 머리 중앙 상단에 기준 도트의 2px 허용 영역을 벗어난 새 픽셀이 3개 이상 생기면 보류한다. 이 기준은 실제 10마리의 선택된 정상 걷기에 별도로 재현했다.
5. 실패한 방향·행동만 `edit-animation-v2`로 원본 9프레임 전체를 보내 보완하고 다시 검수한다. 첫 프레임의 투명도 모양이 정확히 같을 때만 그 프레임의 색을 기준 도트로 되돌릴 수 있다. 나머지 8프레임은 재색칠하지 않는다. 원본 편집본과 최종본이 모두 통과해야 한다.
6. 모든 행동·방향과 기준 도트의 해시가 연결된 경우에만 기존 자동 승인 흐름으로 공개 가능한 묶음을 선택한다. 실패·불확실·누락·변경된 증거는 보류한다. 비공개 강아지는 승인된 묶음이 생겨도 공개 조회에 노출되지 않는다.

정책 `photo-grounded-recovery-v1`은 새 작업에만 저장한다. 기본 도트와 동작 각각 초기 생성 뒤 최대 3회 보완하며, 한도는 품질 규칙에서 작업 생성 시 고정된다. 무한 호출이나 기록 초기화는 하지 않는다. 이전 정책의 작업은 원래 32px 구조와 예산을 유지하고, 승인된 이미지도 바꾸지 않는다. 원격 요청 응답이 유실되면 `OUTCOME_UNKNOWN`으로 보류하고 다시 결제하지 않는다. 완료한 요청의 재전송은 같은 작업을 반환한다.

## 저장·API

기존 `quality_policy`, `attempt_history`, `quality_report`, Storage 구조를 사용해 DB 마이그레이션은 필요 없다. 원본·편집·실패 이력을 모두 보존한다. 프레임 해시는 저장한 시트에서 다시 추출한 PNG를 기준으로 고정해, 공급자의 PNG 압축 방식이 달라도 재검수의 해시가 바뀌지 않게 한다. `native-32` 저장 경로 이름은 원본 도트 해상도와 기존 호환성을 위해 유지한다.

새 묶음의 manifest는 동작 `frameSize=40×40`, `anchorPixels=(20,34)` 및 40px 간격의 프레임 사각형을 제공한다. 기본 이미지는 `baseFrameSize=32×32`, `baseAnchorPixels=(16,30)`이다. `contentPaddingPixels=4`, `nativeContentSize=32`로 추가 여백을 명시한다. 프론트는 하드코딩한 32px 간격 대신 manifest의 프레임 영역을 사용해야 한다. 이전 묶음은 그대로 32px이다.

## 재발 방지와 검증

첫 생성과 보완은 같은 `quality-rules.json`의 `recovery` 규칙을 사용한다. 검출된 결함은 기존 학습 기록과 독립 검증 흐름에도 기록한다. 한도에 도달했다고 실패 이미지를 강제 통과시키지 않는다.

`pilot10-recovery-v15/evidence.json`은 실제 로컬 시험의 실패·통과 판정과 생성 이미지 해시를 기록한다. 이는 새 서버의 실제 생성 결과를 대신하지 않는다. 회귀 검사는 원본 보존, 32→40 무손실 배치, 마지막 프레임 잘림, 사진 무늬 보완, 불확실 요청 중복 방지, 전체 묶음 해시와 자동 승인 경계를 검증한다.

배포 결과와 실제 서버 검증은 이 작업의 PR·노션 카드에 별도로 기록한다.

## 이번 실제 검증의 범위

운영 Java 검수기를 실제 Luna에 연결해 실패 후보 두 묶음, 로컬에서 통과한 후보, 정면 돌출부가 있는 걷기, 수정된 걷기를 재현했다. 최초 검수기가 놓친 돌출부와 눈/무늬 오판도 `reviewer-v1-evidence.json`, `reviewer-v2-evidence.json`에 보존했다. 시각 판단만으로 미세 결함을 모두 보장할 수 없어서 정면 픽셀 검사를 추가했다.

기존 로컬 PASS 후보는 사진과 직접 비교했을 때 넓은 흰 몸통 무늬가 부족했다. 과거 PASS 기록을 지우거나 운영 검수에 강제하지 않고 보완 대상으로 다룬다. 같은 운영 `StyledRecovery`·`StyledPixelLabClient`·`StyledSeedQualityAgent`로 실제 PixelLab 편집 1회와 Luna 재검수를 실행해 네 방향이 통과했다. `server-validation.json`과 `server-repair/`에 이 결과와 이미지 해시를 보존한다. 이는 로컬에서 실제 공급자를 호출한 검사이며, 운영 DB 저장·배포 후 종단 검증을 대신하지 않는다. 결과는 공개하지 않았다.

실제 공급자 검사는 환경변수로 명시적으로 허용해야 실행되는 테스트이며 기본 빌드·CI에서는 건너뛴다. 유료 결과가 불확실한 경우 기존 영수증을 확인하기 전까지 다시 호출하지 않는다. 전체 흐름의 DB·공개 경계 검사는 별도 임시 PostgreSQL과 모의 공급자로 검증한다.
