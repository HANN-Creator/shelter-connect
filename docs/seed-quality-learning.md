# B-52 기본 도트 자동 학습 연결

기존 자동 학습은 동작 스프라이트만 기록·적용하고 기본 도트(BASE)를 제외했다. 기본 도트의 눈 검수는 고정 규칙과 최대2회 재생성만 수행했다. 이제 기본 도트의 실패/통과 사례도 기존 학습 큐와 저장소에 연결한다.

## 처리 흐름

1. 최초 생성·보완·명시적 원본 재검수에서 네 방향 원본, 사진 참조/해시, 품질 보고서를 `styled_quality_examples`에 보존한다. 파일은 그대로 비공개이며 같은 작업·원본·규칙의 기록은 중복 저장하지 않는다.
2. 실패 사례에서 `EYE_READABILITY`, `EYE_STYLE`, `EYE_DIRECTION`, `SEED_IDENTITY`, `CANVAS_CLIPPING` 후보를 만든다. 기본 도트는 `action=BASE`, `direction=all`, `tail=UNKNOWN` 범위로 분리한다.
3. AI가 통과시킨 것만으로 정상 학습 사례가 되지 않는다. 같은 네 방향 해시를 담당자가 기존 `seed-review`로 승인한 뒤에만 정상 예시로 사용할 수 있다. 없으면 `WAITING_EVIDENCE`에서 대기하며 Luna를 호출하지 않는다.
4. 기존 Luna 클라이언트가 범위에 맞는 예방 문구와 검수 기준을 제안한다. 실제 사진·공통 그림체·네 방향 원본을 사용하고 기준 도트를 정답으로 표시하지 않는다.
5. 별도 재검증에서 정답·기존 보고서·원본 사례 ID를 숨긴다. 정상 예시를 보존하면서 실패 예시를 구분해야 `ACTIVE`로 바뀐다. 잘림 방향은 원본 검사 결과도 놓칠 수 없다. 후보는 기존 눈/방향/외형/가장자리 검사를 완화하지 못한다.
6. 활성 규칙은 다음 기본 도트의 첫 생성과 보완 생성에 최대2개까지 예산 안에서 추가한다. 같은 규칙 스냅샷의 검수 기준도 `StyledSeedQualityAgent`에 전달한다. 사진·도트·공통 규칙·학습 규칙 해시를 기록한다.

후보는 모델의 가중치를 학습시키는 것이 아니라 **DB에 저장된 검증된 규칙을 다음 요청에 덧붙이는 방식**이다. 정상·실패 예시의 구분 성공은 새 강아지의 품질 향상을 보장하지 않으며 `freshGenerationVerified=false`를 유지한다.

## 보존하는 경계

- 기존 담당자 승인·공개 절차, 원본 이미지, 그림체, 최대2회 자동 보완, PixelLab 접수 불명 보호는 유지한다.
- 승인된 기존 에셋은 변경하지 않는다. 과거 사례를 임의로 정상 처리하거나 기존 보완 예산을 초기화하지 않는다.
- 동작 규칙은 원래 행동·방향·꼬리 범위에만 적용된다. 기본 도트 규칙이 동작 요청에 섞이지 않는다.
- 사진/도트 바이트가 달라지거나 사용 허가가 철회되면 후보 생성·재검증을 중단한다. 운영자의 기존 학습 규칙 중단 API를 그대로 사용한다.
- PixelLab 접수 직전 규칙이 비활성화되면 접수하지 않는다. 이미 유료 접수된 작업의 스냅샷은 유지한다.
- 규칙 변경 뒤 원본 재검수는 지난 학습 스냅샷을 이력에 남기고 이전 규칙의 학습 문구를 비운다. 재검수는 PixelLab을 다시 호출하지 않는다.

## DB·API·배포

- V16 `seed_quality_learning`: 기존 사례/학습 테이블의 범위 제약을 BASE까지 확장한다. 기존 데이터·RLS·권한·append-only 사례/이력 정책은 그대로다. 새 테이블이나 새 서버 키가 없다.
- REST 요청 형태는 바뀌지 않는다. 운영자 학습 조회에서 BASE/all 항목도 나타나며 기본 도트 품질 보고서에 `photoSha256`, `lessonsSha256`, `learnedLessons`가 추가된다.
- 공통 규칙 버전은 `sprite-regressions-2026-10-06-v9`. 새 서버 배포 전에 V16을 적용해야 한다. 이전 버전으로 진행 중인 미승인 작업은 기존 절차에 따라 명시적으로 재검수해야 한다.
- 새 로컬/CLI 생성도 같은 Python 생성기를 사용하므로 검증된 BASE 규칙 입력을 동일하게 검사한다. CLI가 서버 학습 DB를 임의로 조회하거나 미승인 규칙을 활성화하지 않는다.

## 검증과 아직 남은 부분

- 로컬 PostgreSQL: 실패와 정상 기본 도트 기록, 담당자 승인 전 대기, 제안→정답 비공개 재검증→활성화→다른 강아지 첫 생성·검수 전달, 정상 사례를 거절하는 후보 차단, 원본 사진 변경·허가 철회 차단, 전송 직전 중단, 원본 재검수 중복 방지를 검사한다. 기존 동작 학습 검사도 유지한다.
- 단위 검사: 정답/보고서/사례 ID 비노출, 네 방향 응답 완전성, 다른 범위/오래된 규칙 거절, 학습 기준 전달과 원본 잘림 차단, Java→Python 생성 문구 연결을 검사한다.
- 실제 이미지/실제 Luna의 판별 성능과 새 강아지 유료 생성은 이번 코드 테스트와 별개다. 현재 로컬에는 OpenAI 키가 없으므로 실제 호출 통과로 보고하지 않는다.
- 이전 오슈의 v7 불합격/v8 통과는 서로 다른 규칙에서 나온 결과다. 동일 조건에서의 판정 불안정으로 단정하지 않는다. 사용자 승인 로컬 도트를 서버 정상 예시로 자동 등록한 것은 아니다.
- 노션 기록은 앞선 별도 승인 대기로 미동기화다. 실제 CI·병합·개발 DB 적용·배포 결과는 PR 기록에 구분해서 남긴다.
