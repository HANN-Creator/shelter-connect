# B-57 · 실패 동작의 기록을 보존하는 추가 보완

브랜치: `backend/b-57-complete-motion-repair`. 선행 B-54/B-55/B-56. 사용자가 전체 동작 완성과 프론트 확인까지 요청했다. 노션 쓰기는 앞선 자동 승인 검토 거절로 미동기화이며 재시도하지 않았다.

아래는 B-57 당시 동작이다. 추가 요청의 현재 조건과 IDLE 전략은 [B-60](idle-continuation-fallback.md)을 따른다. 과거 요청은 계속 중복 방지에 사용하며 기존 보완 횟수를 초기화하지 않는다.

## 문제와 변경

실제 강아지 `442418202600971`의 기존 미승인 팩은 12개 중 8개 통과, 4개 실패였다. 뒷면 IDLE은 실패한 움직임을 편집하자 들썩이는 몸·꼬리가 남았다. 왼쪽 IDLE/WALK/SIT는 꼬리 끝이 프레임 경계에 닿았고 원래 보완 2회를 소진했다.

- 새 작업의 마지막 IDLE 편집은 실패한 움직임 대신 승인된 도트 9장으로 시작한다. 원본 도트의 몸·꼬리 윤곽을 고정하고 작은 내부 명암 변화만 요청한다. 기존 작업에 고정된 편집 정책은 소급 변경하지 않는다.
- 명시적 추가 보완은 선택한 실패 동작에 한 번만 허용한다. 횟수는 2→3이며 이전 생성·검수·해시·학습 문구를 이력에 보존한다. 원래 자동 재시도 상한 2와 승인 도트는 유지한다.
- 좌우 IDLE/WALK/SIT는 같은 작업·행동의 반대 방향이 현재 규칙으로 통과한 경우에만 후보로 삼는다. 승인 도트의 반전 알파가 완전히 일치하고, 보이는 픽셀의 95% 이상에서 채널 차이가 3 이하이며 어느 채널도 64를 넘지 않아야 한다. 비대칭 무늬·윤곽이면 중단한다.
- 허용된 좌우 복원은 원본 9프레임을 반전하고 원래 방향의 팔레트·첫 프레임을 복원한다. 원본 반전본과 복원본을 모두 저장·검수하며, 임의로 잘라내거나 크기를 줄이지 않는다. PixelLab 추가 호출 없이도 Luna 검수와 학습 사례 저장은 수행한다.
- 나머지 IDLE은 승인 도트 기반 PixelLab 편집 1회를 수행한다. 실패가 남으면 REVIEW/QUALITY_REPAIR_EXHAUSTED이며 공개 승인은 차단된다.

## API

`POST /v1/shelter-admin/dogs/{dogId}/styled-assets/{jobId}/repair-continuation`

```json
{
  "requestId": "생성한 UUID",
  "note": "실패 원인과 선택한 동작의 추가 보완 이유, 20자 이상",
  "expectedSeedHashes": {"south": "…", "north": "…", "west": "…", "east": "…"},
  "expectedSheetHashes": {"idle-north": "…", "idle-west": "…", "walk-west": "…", "sit-west": "…"}
}
```

같은 보호소 STAFF/MANAGER, 완료된 REVIEW 작업, 현재 규칙, 승인 도트, 입력 해시에 묶인 실패 판정, repairCount=2를 확인한다. 요청은 작업당 한 번이며 같은 requestId·본문 재전송은 추가 호출 없이 현재 작업을 반환한다. 변경된 시트·본문, 통과한 대상, 승인/진행 중 작업, 다른 추가 요청은 409다. 인증·권한·사진 사용 허가 검사는 기존과 같다.

새 테이블이나 권한은 없다. V18은 `repair_count` CHECK의 최댓값만 3으로 바꾼다. 값·기존 행·기존 이력은 수정하지 않는다. 운영자 복구나 예산 초기화로 우회하지 않는다.

## 재현과 검증

공유 규칙은 v9 / SHA `6fae1b5ad7b062411172441cc8ac9eb6ec11c6cef905f6c1a0dd4c35014100ec`로 유지한다. 기존 `idle-motion-alpha.json` 회귀 자료에 이번 실패/후보 4개와 원본 해시를 추가했다. 대응 PNG는 `backend/scripts/fixtures/motion-continuation`에 보관한다.

실제 PixelLab의 승인 도트 기반 뒷면 IDLE 편집과 반전 후보 3개는 9프레임 구조 검사를 통과했다. 이는 로컬 비교이며 서버 Luna 검수·DB 저장·최종 승인과 구분한다. 시각적으로는 뒷면 들썩임이 제거됐고 좌측 앉기 마지막 자세의 꼬리도 여백 안에 남았다.

회귀 검사는 좌우 모든 픽셀 보존, 비대칭 거부, 원본·복원본 모두 재검수, 다른 보호소/오래된 해시 거부, 중복 요청 무과금, 3회 이후 차단, 승인 도트·실패 이력 보존, 변경된 소스 바이트 차단을 다룬다. 실행 결과와 실제 배포 후 결과는 PR 및 별도 실행 보고서에 남긴다.

로컬 실행: Python 44개 통과, Java 단위 372개 통과/1개 기존 제외, 실제 로컬 PostgreSQL 에셋·마이그레이션 98개 통과/1개 기존 제외, 배포 JAR 빌드 통과. 처음 검사에서 새 경로의 인증 허용 목록 누락을 발견해 수정했고 위 결과는 수정 후 재실행 결과다.

## 배포 후 완료 조건
