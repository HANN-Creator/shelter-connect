# B-100: 10마리 실제 배치 입력 오류 복구

- 선행: B-99 / d01d7f4, 2026-10-17 사용자 요청의 새 강아지 10마리 비공개 개발 생성.
- 브랜치: `backend/b-100-batch-input-recovery`.
- 노션: 도구 미제공으로 카드 미동기화. 검증·PR·배포 결과를 이 문서에 별도 기록한다.

## 실제 원인과 바뀌는 동작

사진 업로드는 최대 2048px인데 자동 외형 분석 결과를 입력으로 변환할 때 1024px 제한으로 원본을 다시 읽었다. 큰 사진은 Luna 분석을 마친 뒤 PixelLab 제출 전에 `INVALID_SPRITE_IMAGE`로 실패했다. 분석 검증에만 기존 1024px 사진 참조를 사용하고, 원본 저장·원본 SHA256·비율 얼굴 좌표는 보존한다. 생성 스프라이트의 픽셀이나 해상도는 변경하지 않는다.

같은 배치의 `idle-north`에서 규칙 11개를 모두 받은 초안 세 개가 1037·1053·1016자로 1000자 한도를 넘겼다. 공백 정리만으로 해결되지 않았다. 저장된 완료 초안만 대상으로 짧은 동등 표현을 적용하고, 여전히 한도를 넘으면 실패를 유지한다. 절·규칙·숫자·부정·승인/선택/정상 조건을 삭제하거나 문자열을 잘라내지 않는다. 실제 세 번째 초안은 998자이며, 원문·이력·전후 길이·해시를 남긴다.

처음 생성과 보완 작성은 같은 처리 후 전체 원문과 모든 규칙의 독립 관찰을 거친다. 현재 WARN_ONLY 작업은 의미 관찰의 경고를 그대로 저장하며 추가 유료 이미지 보완을 하지 않는다. 기존 엄격 정책의 의미 검사도 유지한다.

## 재개 계약

문구 작성 버전은 v6으로 구분한다. 기존 `prompt-resume`의 허용 대상에 v5 및 v5/WARN_ONLY의 명확한 제출 전 실패를 추가한다. 소속 STAFF, 최신 입력 해시, 규칙/시드 해시, 기존 승인, provider 영수증·예약 부재, 단계별 버전당 1회, 동일 요청 재실행 검사를 유지한다. 승인 이미지·다른 완료 단계·기존 보완 횟수·과거 실패 기록을 바꾸지 않는다.

API 요청/응답, 환경변수, DB 마이그레이션 변경 없음. DB V24 및 이미지 품질 규칙 v43 유지. 입력 길이·사진 참조 처리 문제이므로 그림체나 시각 결함 기준을 다시 바꾸지 않는다.
