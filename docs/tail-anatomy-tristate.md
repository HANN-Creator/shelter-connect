# B-73 꼬리 검수: 관찰과 결함 분리

노션: https://app.notion.com/p/3f45b2d1a55f80b1a59ceaf47465f365
브랜치: `backend/b-73-tail-review-tristate`

## 문제와 처리

동일한 정상 측면 꼬리가 v20 운영 검사에서는 WEST 확신도 0.72, 실제 로컬 패키지에서는 AI가 지정한 투명 픽셀 (29,10) 때문에 보류됐다. 반면 꼬리가 없는 실제 실패 사례도 존재한다. 숫자 기준을 낮추거나 불량을 강제 승인하는 방식으로 해결하지 않는다.

새 작업과 명시적 재검수는 `tail-anatomy-tristate-v2`를 고정한다. 생성/선택 보완 후 동일한 `inspectSeeds` 경로를 사용한다.

- 코드가 원본 알파의 가장자리 접촉·연결 성분과 뒤쪽 윤곽의 분기를 측정한다. 원본의 복사본만 세선화하며 PNG는 바꾸지 않는다. 분기 하나만으로 꼬리 존재를 확정하지 않는다.
- AI가 완전한 꼬리라고 해도 뒤쪽 윤곽 근거가 없으면 `UNCERTAIN`이다. AI가 누락이라고 해도 분기가 있으면 불일치로 보류한다. 실제 사진에서 전체 짧은 꼬리가 확인되는 예외만 분기 부재를 허용한다.
- 분기는 최소 4점, 아래 4행 발 영역 제외, 끝점은 뒤쪽 절반에 위치해야 한다. 뿌리도 뒤쪽에 있거나, 중앙 1/3의 척추까지 2px 이상 올라간 가지여야 한다. 좌우 반전 대칭을 회귀 검사한다. 이 보조 검사는 의미론적 꼬리 분할이 아니다. 몸·뒷다리 알파에 붙어 내려간 정상 꼬리는 지원하지 못할 수 있으며 이 경우 보류한다.
- 일반 사진 검수가 실제 사진에서 보이는 꼬리 근거를 기록한다. 꼬리 전용 검수에는 사진을 제외하고 대상 도트와 고정된 정상/누락 시각 기준을 전달한다. 사진의 품종 인상이 도트 관찰을 대신하지 않게 분리했다.
- 꼬리 전용 응답은 부착·별도 윤곽·끝부분의 관찰 범주를 사용한다. AI에게 정확한 픽셀 좌표나 확신도 점수를 요구하지 않는다. Luna 모델은 유지하고 이 검수만 reasoning `medium`을 사용한다.
- 관찰 불확실 또는 일반 검수와 꼬리 존재 판단이 충돌한 방향들은 같은 원본으로 한 번만 독립 재관찰한다. 이전 판정/좌표는 전달하지 않는다. 여전히 충돌하면 `UNCERTAIN`으로 남긴다.
- `PASS`만 다음 승인으로 진행한다. `CONFIRMED_DEFECT`의 방향은 기존 선택 보완/예산을 사용한다. `UNCERTAIN` 자체는 유료 수정 사유가 되지 않는다.
- 원본과 보고서는 작업에 남기되, 미해결 꼬리 관찰이 포함된 예시는 부정 학습 데이터와 규칙 후보 큐에 넣지 않는다. 섞인 보고서도 관찰이 해결될 때까지 학습에서 제외한다.

새 보류 이유는 `SEED_OBSERVATION_UNCERTAIN`이다. DB 마이그레이션, 키, 권한, 생성 스타일, 원격 작업의 누적 시도 횟수는 변경하지 않는다. 기존 v1 증거 검증 경로는 유지하며, 새 정책의 승인 검증은 한 곳에서 분기한다. 기존 승인 에셋을 자동 교체하지 않는다.

## 시각 기준과 검증 경계

`tail-review-rubric.png`는 생성 스타일 입력이 아닌 검수용 예시다. 출처와 이미지 해시는 같은 폴더의 JSON 및 공통 품질 규칙에 고정한다. 학습 규칙은 품질 검사를 우회할 수 없다.

초기 비교의 샘플 순서와 라벨을 유료 검수 전에 저장했다. 사진과 실제 측면 꼬리를 직접 본 에이전트의 라벨이며, 독립적인 사람 평가나 대규모 정확도 수치는 아니다. 파일럿의 40px 씨앗은 빈 4px 테두리만 검증 후 제거해 원래 32px 픽셀을 사용했다. 원본 도트는 확대·축소하지 않았다.

좌표를 제거한 첫 방법과 reasoning만 늘린 방법 모두 정상/누락 오판이 남아 실패로 기록했다. 정상/누락 시각 기준을 적용한 비교에서는:

| 구분 | 기존 좌표 방식 | 시각 기준 방식 |
| --- | --- | --- |
| 공통 정상 4개 통과 | 1/4 | 3/4 |
| 공통 명확한 불량 3개 차단 | 3/3 | 3/3 |
| 추가 정상 1개 통과 | 미실행 | 1/1 |
| 추가 분리 픽셀 1개 차단 | 미실행 | 1/1, 관찰 보류 |

경계 사례 1개는 이진 정확도 계산에서 처음부터 제외했다. 정상 검은 강아지 1개를 여전히 잘못 거절했으며 결과를 변경하거나 성공 라벨로 바꾸지 않았다. 이후 실제 서버 경로에 일반 검수와의 충돌 보류를 연결했지만 F 누락 사례를 두 검수가 함께 통과시키는 추가 실패가 발생했다. 그 실제 응답도 `case-f/production-consensus.json`으로 보존했다. 최종 후보는 이 응답을 실제 픽셀 분기 측정과 대조하면 두 방향 모두 `UNCERTAIN`으로 보류하며 유료 보완이나 부정 학습으로 넘기지 않는다. D 정상 꼬리의 실제 누락 오판도 분기 근거와 충돌하여 결함이 아닌 보류로 바뀐다. 이는 저장된 실제 응답의 **오프라인 재평가**이며 새 AI 검수 결과라고 표현하지 않는다. 이 비교만으로 모든 강아지의 자동 통과나 오류 0건을 보장하지 않는다. 비교 도구의 전체 일치 검사는 해당 1개 때문에 실패 상태이며, 이는 회귀 단위 검사의 성공과 구분한다.

독립 꼬리 비교 도구는 사진 관찰도 따로 호출한다. 운영 경로는 이미 수행한 일반 사진 검수 결과를 재사용하므로 그 추가 호출이 없다. 실제 비용은 호출 수 외 이미지 토큰·추론 토큰에 따라 달라지므로 이 표를 비용 절감율로 해석하지 않는다.

## 실제 패키지 검증

동일 사진·동일 네 방향 씨앗·기존 보완 1회/유료 제출 2회 이력을 별도 로컬 PostgreSQL V23에 복제하고 실제 서버 JAR, 실제 Luna, 실제 PixelLab, 비공개 Storage를 사용한다. 원격 작업 상태·판정·예산을 SQL로 수정하지 않는다. 승인된 개발 가상 보호소 자료만 사용하며 테스트 애플리케이션은 loopback으로만 연다.

이번 경로는 이미 생성된 기준 도트의 재검수부터 시작하므로 최초 기준 도트의 유료 생성 검증으로 표현하지 않는다. 기준 도트는 바이트 변경이나 추가 PixelLab 호출 없이 실제 재검수에 통과하고 SYSTEM 승인이 저장됐다. 이 실행은 뒤쪽 분기 보조 검사를 추가하기 전 JAR(규칙 SHA `85df6bc0e10250f32ea66a6c07064250a64b9632deafcc956db27368ea58071f`)이다. 마지막 후보의 실행 증거와 구분한다. 실제 IDLE 정면/후면/왼쪽은 각각 3회 보완 후에도 검수를 통과하지 못했다. AI는 발의 큰 교대 움직임·꼬리 자세 변화 등을 주장했으나 최종 세 시트의 알파 변화는 기준 프레임 대비 최대 1/2/4픽셀이고 바운딩 박스는 고정이다. 직접 본 프레임과도 과장된 움직임 설명이 맞지 않아, 실제 결함으로 단정하거나 정상으로 강제 승인하지 않는다. RGB 변화와 기준 도트/첫 프레임 불일치는 별도로 남아 있다. 자동 보완 호출과 실패 저장은 작동했지만 완성 이미지 품질이나 최종 공개가 성공한 것은 아니다. 추가 유료 제출 13회 뒤 소유한 로컬 워커를 중단했다. 중단 시 진행 중인 외부 제출은 없으며, 오른쪽 IDLE은 첫 검수 실패 후 다음 보완 대기, WALK/SIT 8개는 미생성이다. 원본·기록·보완 예산은 그대로 보존했고 최종 승인/공개는 없다. 이 실행을 전체 12모션 성공으로 표현하지 않는다. 최종 결과가 확인되기 전에는 배포 완료나 전체 완료로 표시하지 않는다.

## 회귀 자료와 해석

실제 정상 5개, 명확한 불량 4개, 경계 사례 1개의 입력 해시와 유료 관찰 원문을 `scripts/fixtures/tail-anatomy-v21/`에 보존했다. 여기에 꼬리가 몸에 붙어 내려간 별도 정상 샘플을 한계 검사로 추가했다. 아래로 내려간 꼬리를 `TAIL_MISSING`으로 확정하지 않는지 검사한다. 과거 보고서의 규칙 해시는 바꾸지 않으며 현재 승인 근거로 재사용할 수 없다.

초기 비교에서 발견한 오판은 삭제하지 않았다. 최종 후보의 실제 API 검수는 정상 A 전체 PASS, 정상 D 꼬리 PASS(별도 외형 불일치로 전체 보류), 누락 F 꼬리 UNCERTAIN(별도 털색 결함 있음)였다. 꼬리 관찰 호출은 A/D 각 1회, F 2회이며 이미 수행한 일반 사진 검수를 재사용한다. 기록은 `candidate-final/`에 보존했다. 테스트 도구가 처음에 모든 불확실 방향의 보완을 금지해 별도 확정 털색 결함까지 막으려는 잘못된 assertion으로 실패했다. 실제 응답을 바꾸거나 재호출하지 않고 그 assertion을 “불확실성만으로는 보완하지 않는다”로 바로잡아 통과했다. CI와 최종 패키지 확인은 별도로 기록한다. B-73은 꼬리 검수의 잘못된 승인·보완·학습을 줄이는 변경이며, B-68의 12개 실제 동작 품질 완료를 뜻하지 않는다.

## 최종 후보 패키지 확인

최종 JAR SHA `5f07942ab69e0007342a1e8adfc9601d2e314770ea417bfa719a454c2dff61f4`, 규칙 SHA `b004cb15e3f194ec16c034e2e6eb26ad3a7a4f9fdd39214dae5c224aa08b0b21`. 배포 JAR에서 추출한 실제 클래스/리소스/라이브러리로 동일 정상 A의 사진과 네 방향 도트를 Luna에 전송했다. 일반 검수와 꼬리 검수 모두 PASS, `boundPass=true`를 확인했다. 이는 **패키지 내부 검수 함수의 실호출**이며 이 마지막 실행 자체가 HTTP·DB 승인이나 전체 모션 생성을 검증한 것은 아니다. 앞선 로컬 PostgreSQL 실제 SYSTEM 승인 기록과 구분한다.

로컬 `bootJar test integrationTest`, Python 하네스 및 PR CI 결과는 PR 본문에서 확인한다. 실제 IDLE 검수 충돌과 전체 12모션 검증이 남아 있으므로 운영 배포를 요청하거나 전체 자동화 완료로 표시하지 않는다.
